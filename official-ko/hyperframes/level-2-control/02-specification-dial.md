# 명세 다이얼

> 명세 밀도는 결과물이 상상한 것에서 얼마나 벗어나는지를 조절합니다 — 작동하는지 여부가 아니라.

[뼈대](/prompting/anatomy)는 각 결정이 어디에 있는지 알려 주고, 이 페이지는 각 결정을 얼마나 세게 돌릴지 알려 줍니다. 얼마나 명시하는지가 얼마나 위임하는지를 정합니다 — 결과물이 상상한 것에서 얼마나 벗어날 수 있는지를 조절하며, 작동하는지 여부를 조절하지는 않습니다. "스냅피", "시네마틱" 같은 분위기 수준 프롬프트는 디자이너의 해석을 받습니다: 일관되지만, 에이전트가 색, 연출, 세부를 고릅니다. 밀도 높은 스펙 — 헥스값, 타임스탬프, 이징, 고정된 기법 — 은 *당신의* 프레임을 얻습니다.

세 가지 설정:

1. **분위기 단어** — "따뜻하고 미니멀한 로고 스팅". 쓰기 가장 빠르며, 룩은 에이전트가 소유합니다.
2. **스타일 토큰** — 정확한 헥스값, 이름 붙은 질감("halftone-dot", "paper-cut matte", "8-bit pixel"), 타입 방향("condensed caps", "thin geometric sans, wide tracking"). 저렴한 정밀도이며 단점이 없습니다.
3. **전체 비주얼 스펙** — 모든 요소에 형태 + 색 + 위치 + 타이밍이 있음 ([비주얼 스펙](/prompting/visual-specs) 참조). 특정 룩을 재현할 때 사용하십시오.

밀도는 결코 해치지 않습니다 — 더 강한 모델은 자기 취향을 덜 쓸 뿐입니다. 작은 모델이 잘 기본값으로 쓰지 못하는 기법 선택에서 가장 중요합니다. 매번 고정할 가치가 있는 두 가지:

* **3D**: 실제 깊이, 조명, 카메라 움직임이 있으면 → **"Three.js via the adapter"**라고 말하십시오. CSS 원근 변환은 조명이 중요한 장면에서 평평하게 읽히고, Three.js는 지원되는 seek-safe 런타임입니다.
* **순서**: 텍스트에서 동시성을 해소하십시오. "카운터가 페이드 아웃되고 4초에 READY가 찍힌다"는 겹침을 만들고; "4.2초까지 완전히 페이드 아웃; 4.2초에 READY가 찍힌다"는 겹치지 않습니다.

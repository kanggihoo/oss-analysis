Answer

에이전트가 SKILL.md의 7단계를 따라 그림을 직접 짜고, 스크립트 3개가 로고 수집, 자산 inline, PNG 캡처만 맡습니다. 결과의 원본은 HTML 파일 하나이고, PNG와 React 컴포넌트와 artifact는 이 HTML에서 만듭니다.

  1. 그림을 그리는 엔진은 레포에 없습니다. 에이전트가 template.html을 복사해서 geometry.md의 규칙대로 노드와 화살표 좌표를 직접 씁니다.1
  2. 스크립트는 fetch_icons.py(로고 받기), build.py(로고와 폰트를 HTML에 넣기), render_png.py(PNG 찍기) 순서로 이어집니다.2
  3. 화살표가 글자를 지나가는지는 코드가 검사하지 않습니다. 에이전트가 PNG를 열어 눈으로 확인하고, 문제가 있으면 좌표를 고쳐 다시 만듭니다.3
  4. 로고는 색을 바꾸지 않습니다. 흰색 로고는 로고를 건드리는 대신 어두운 tile 위에 올립니다.2

1

에이전트는 어떤 순서로 일하나?

Diagram structure
  • 내용 정하기 content
  • 로고 받기 icons
  • 좌표 쓰기 layout
  • HTML 만들기 build
  • PNG로 확인 look
  • 형식별 전달 deliver
  • 갤러리 공유 share
  • build → look · out.html
  • content → icons
  • deliver → share · 동의 시
  • icons → layout · icons 폴더
  • layout → build · 초안
  • look → deliver · 통과
  • look → layout · 겹침 있음

사용자가 "Next.js와 Hono API를 Vercel에 올리고 Neon, Clerk를 쓴다"처럼 말하면, 에이전트는 아래 순서로 진행합니다.2 확인 단계에서 겹침이 보이면 좌표 단계로 돌아갑니다.

  1. 내용 정하기 ↗

    기술마다 node 하나, 같은 runtime이나 vendor는 group 박스로 묶고, edge는 주 흐름(accent 실선), 내부 연결(neutral 실선), dev·deploy(점선) 세 종류로 나눕니다.

  2. 로고 받기 ↗

    fetch_icons.py <dir> tanstack hono ...를 실행하면 svgl, devicon, gilbarbara/logos 순으로 시도해 로고 파일과 manifest.json을 씁니다.

  3. 좌표 쓰기 ↗

    template.html을 복사해 노드는 left = centerX - 66, 그룹은 가장 바깥 노드 상자에서 24px 밖에 놓습니다.

  4. HTML 만들기 ↗

    build.py draft.html <icons> out.html --fonts <fonts>가 %%ICON_<name>%% 자리에 로고를 data URI로 채웁니다.

  5. PNG로 확인 ↗

    render_png.py로 PNG를 찍고 화살표가 글자를 지나지 않는지, 아이콘이 다 보이는지 에이전트가 직접 봅니다.

  6. 형식별 전달 ↗

    요청한 형식으로 줍니다. HTML이 기본이고 PNG는 라이트와 다크 두 장입니다.

  7. 갤러리 공유 ↗

    사용자가 명시적으로 동의한 경우에만 share.py submit을 실행합니다. 대화당 한 번만 제안합니다.

2

어떤 파일이 무엇을 받아서 무엇을 내놓나?

build.py는 두 군데에서 입력을 받습니다. 하나는 fetch_icons.py가 만든 icons 폴더이고, 다른 하나는 에이전트가 template.html을 고쳐 쓴 초안입니다.4 이 둘이 만나는 곳이 %%ICON_<name>%% 토큰입니다. 초안에 %%ICON_hono%%라고 적혀 있으면, build.py가 icons 폴더에서 이름이 hono인 파일을 찾아 base64 data URI로 바꿔 넣습니다.

Diagram structure
  • fetch_icons.py fetch
  • icons 폴더 iconsdir
  • 초안 HTML draft
  • build.py build
  • render_png.py render
  • PNG 두 장 png
  • fetch → iconsdir · 로고
  • iconsdir → build · 아이콘
  • draft → build · 토큰
  • build → render · out.html
  • render → png · 라이트, 다크

한 문장에서 파일까지 가는 실제 명령은 SKILL.md에 있는 예시 그대로 이렇습니다.2

3

누가 어떤 일을 하나?

위 흐름에서 스크립트가 하는 일은 파일을 받고, 바꾸고, 찍는 일뿐입니다. 어디에 무엇을 놓을지 정하는 일과 결과가 괜찮은지 판단하는 일은 에이전트에게 있습니다.2

일맡은 쪽근거
기술을 node, group, edge로 나누기에이전트SKILL.md 1단계 지시문
로고 받기fetch_icons.py출처를 순서대로 시도하고 manifest.json에 기록
노드와 화살표 좌표 정하기코드 없음에이전트geometry.md 규칙만 있음
로고와 폰트를 HTML에 넣기build.py남은 %%...%% 토큰이 있으면 실패
PNG 찍기render_png.py기본은 라이트와 다크 두 장
겹침과 잘림 확인코드 검사 없음에이전트render_png.py는 캡처만 함
React 컴포넌트로 바꾸기에이전트변환 스크립트 없이 tsx.md를 읽고 직접 작성
갤러리에 올리기share.py사용자 동의는 SKILL.md의 지시이고 share.py에는 확인 절차가 없음

코드가 막아 주지 않는 것

build.py는 토큰이 남았는지만 검사합니다. 화살표가 글자를 지나가는지, 노드가 그룹 밖으로 튀어나왔는지는 아무 스크립트도 검사하지 않습니다. 그래서 5단계에서 PNG를 직접 열어 보고, 문제가 있으면 3단계 좌표를 고쳐 다시 만드는 것이 이 워크플로의 품질 확인 방법입니다.

4

로고는 어떤 규칙으로 고르나?

fetch_icons.py는 이름이 정확히 일치하는 로고만 받고, 일치하지 않으면 다음 출처로 넘어갑니다. 비슷한 이름의 다른 브랜드 로고가 들어가는 것을 막기 위해서입니다.5

  • svgl에서 먼저 찾습니다. 라이트와 다크가 따로 있으면 라이트를 <name>으로, 다크를 <name>_dark로 저장합니다.
  • svgl에 없으면 devicon, 그다음 gilbarbara/logos를 시도합니다.
  • 모두 없으면 FAIL을 출력하고 종료 코드 1로 끝납니다. 이때 에이전트는 공식 로고 파일 주소를 name=URL 형식으로 넘깁니다.
  • 로고 전체가 흰색이면 manifest.json에 white_fill을 표시합니다. 에이전트는 SVG를 열어 정말 흰색인지 확인한 뒤, 맞으면 tile dark 클래스로 어두운 tile 위에 올립니다.2
  • 사용자, 브라우저 같은 brand 없는 노드는 lucide/<icon> 아이콘을 씁니다. 글자나 이모지를 tile에 넣지 않습니다.

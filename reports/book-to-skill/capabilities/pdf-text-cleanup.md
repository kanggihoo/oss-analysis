# PDF 텍스트 정리 (`clean_pdftotext`)

> pdftotext·pypdf·pdfminer가 뽑은 PDF 텍스트(쪽 사이가 폼 피드 `\f`)를 받아, 여러 쪽에 반복되는 머리말·꼬리말과 쪽 가장자리의 쪽번호를 지우고 줄 끝 하이픈으로 갈라진 단어를 이어 붙인 텍스트 한 덩어리를 돌려준다.

## 1부. 동작 설명

### 1.1 한눈에 보는 흐름
1. PDF 엔진 하나(pdftotext → pypdf → pdfminer 순으로 시도, 순서는 선행 스펙)가 텍스트를 뽑는다. 이 텍스트는 쪽 사이가 `\f`다.
2. 엔진 함수가 그 텍스트를 `clean_pdftotext`에 넘기고 결과를 그대로 반환한다.
3. 쪽이 3개 이상이면 쪽 가장자리 줄의 반복 횟수로 머리말·꼬리말 문자열을 정하고, 각 쪽의 첫·마지막 비공백 줄이 그 문자열이거나 쪽번호면 줄을 지운다. 3개 미만이면 지우지 않고 `\f`만 `\n`으로 바꾼다.
4. 쪽을 `\n`으로 이어 붙인 뒤, 줄 끝 하이픈 + 줄바꿈 + 글자 꼴을 하이픈 없이 붙인다.
5. 호출한 쪽(엔진 체인)이 정리된 텍스트가 공백뿐인지 본다. 공백뿐이면 다음 엔진으로 간다.
6. 보이지 않는 문자 정화(행 4)는 이 뒤, 체인이 끝난 다음에 따로 일어난다.

### 1.2 범위·통합 지점
- 제공: 위 두 가지 정리(머리말·꼬리말·쪽번호 제거, 하이픈 잇기)와, 이 정리가 어느 추출 경로에 적용되고 어느 경로에는 적용되지 않는지의 경계.
- 제외:
  - 엔진 선택·폴백·스캔본 중단(행 2). 이 스펙은 `clean_pdftotext`가 불리는 조건과 입력 모양만 정의한다.
  - Docling과 pdf-inspector 결과, 쪽 단위 사이드카 기록(`extract_pypdf_page_records`), 비PDF 형식: 정리를 거치지 않는다(R-02).
  - 표 셀이 붙었을 수 있는 소수 표기(예 `0.2070.110`)의 표시: 이 함수에는 없다. 쪽 사이드카 쪽 기능(행 6)이 `possible_joined_decimal_cells`로 표시한다(R-09).
  - 보이지 않는 문자 삭제·부수 문자 접기(행 4).
- 외부 의존·선행 계약: 입력은 문자열 하나. 호출자가 정하는 것은 어느 엔진이 이 문자열을 만들었는가뿐이다(1.3). 선행 스펙 `pdf-extraction`은 엔진이 언제 호출되는지를 정하며, 여기서는 아래 입력 경계만 쓴다.
- 소유 상태·부작용: 없음. 입력을 바꾸지 않고 새 문자열을 돌려주는 순수 함수다(파일·전역 상태 없음). 같은 입력이면 같은 출력이다.

### 1.3 인터페이스와 데이터 의미

| 연산·데이터 | 입력·출력 / 타입 | 의미·제약 |
|---|---|---|
| `clean_pdftotext` | in: string, out: string | 쪽 경계는 입력 안의 `\f`. 출력에는 `\f`가 없다. 예외를 직접 던지지 않는다(호출한 엔진 함수의 `try/except`가 있다). |
| pdftotext 경로의 입력 | `pdftotext -layout -enc UTF-8 <path> -` 의 stdout | 종료 코드 0이고 `strip()`한 결과가 비어 있지 않을 때만 정리한다. 아니면 정리 없이 `None`. |
| pypdf 경로의 입력 | 쪽별 `extract_text()` 문자열을 `\f`로 이은 것 | 쪽 추출이 예외면 그 쪽은 빈 문자열로 이어진다(빈 쪽도 쪽 수에 든다). pypdf를 못 쓰면 `None`. |
| pdfminer 경로의 입력 | `extract_text(path)` 결과 | 비어 있지 않을 때만 정리. 빈 값(빈 문자열/`None`)이면 정리 없이 그대로 반환한다. |
| 쪽 수 | `text.split("\f")`의 조각 수 | 빈 조각도 센다. 3 이상인지가 머리말·쪽번호 제거를 켠다. |
| 쪽번호 줄 | 앞뒤 공백을 뗀 줄 전체가 `\d{1,4}` 또는 로마 숫자 1~99(대소문자 무시) | 정규식은 C-01. |
| 하이픈 이음 | `(\w)-\n(\w)` → 앞뒤 글자만 남김 | 정규식은 C-01. |

### 1.4 행동 규칙과 남은 질문

| ID | 조건·입력 | 반드시 관찰될 결과·사후 상태 | 검증 수준 |
|---|---|---|---|
| R-01 | pdftotext가 성공한 텍스트, pypdf가 만든 텍스트(항상), pdfminer의 비어 있지 않은 텍스트 | 각각 `clean_pdftotext`를 거친 결과가 그 엔진의 반환값이다. | 코드 확인 |
| R-02 | Docling 결과, pdf-inspector Markdown, 쪽 사이드카용 쪽 텍스트, 스캔본 사전 점검용 pdftotext 출력, 비PDF 형식 | `clean_pdftotext`를 거치지 않는다. 호출처는 R-01의 세 곳뿐이다(`book_to_skill/`·`tools/` 전체 검색). `technical` 모드에서 Docling이 성공하면 이 정리는 전혀 적용되지 않고, Docling이 실패·빈 결과일 때 가는 pdftotext/pypdf/pdfminer 체인은 적용된다. | 코드 확인 |
| R-03 | 쪽 수(`split("\f")` 조각 수)가 3 미만 | 머리말·꼬리말·쪽번호를 지우지 않는다. `\f`를 `\n`으로 바꾸고 하이픈 이음(R-08)만 한다. 이때 입력의 끝 줄바꿈은 그대로 남는다. | 코드 확인 |
| R-04 | 쪽 수 3 이상 | 쪽마다 앞뒤 공백을 뗀 비공백 줄의 첫 줄에 1표, 비공백 줄이 2개 이상이면 마지막 줄에도 1표를 준다(첫·마지막이 같은 문자열이어도 2표, 줄이 하나뿐인 쪽은 1표). 빈 쪽은 표가 없지만 쪽 수에는 든다. 표가 쪽 수의 절반을 **초과**하는 문자열이 반복 머리말·꼬리말(boiler)이다(쪽 수가 4면 3표 이상). 같은 문자열의 첫 줄 표와 마지막 줄 표는 합산한다. | 코드 확인 |
| R-05 | 쪽 수 3 이상, 각 쪽 | 그 쪽의 첫 비공백 줄과 마지막 비공백 줄(한 줄뿐이면 그 줄)만 검사해, 앞뒤 공백을 뗀 줄이 boiler와 일치하거나 쪽번호 패턴(R-06)이면 그 줄을 지운다. 쪽 중간의 같은 문자열 줄은 지우지 않는다(머리말이 절 제목을 반복해도 본문 제목이 남는다). | 코드 확인 |
| R-06 | 쪽 가장자리 줄이 `\d{1,4}`(파이썬 `str` 정규식의 기본 `\d`라 유니코드 숫자 포함) 하나이거나 로마 숫자 1~99 | 쪽번호로 보고 지운다. 반복 여부와 무관하며 쪽 첫 줄이 홀로 있는 숫자여도(예: 장 번호만 크게 적힌 줄) 지운다. 5자리 이상 숫자, 100 이상 로마 숫자(`c`·`d`·`m` 단독), 정규 꼴이 아닌 철자(`MIX`, `CIVIL`, `DIM`, `MILD`, `VIVID`)는 쪽번호가 아니어서 남는다. 쪽 중간의 홀로 있는 숫자도 남는다. | 코드 확인 |
| R-07 | 줄을 지우고 남기는 방식 | 남는 줄은 내용 그대로(앞뒤 공백·빈 줄 포함)이고 쪽 사이에는 빈 줄이 더해지지 않는다. 쪽 3 이상 경로는 쪽을 `splitlines()`로 줄 단위로 쪼갰다가 `\n`으로 다시 잇기 때문에, 줄 구분자(`\r\n`, `\r`, U+2028 등 `splitlines`가 줄바꿈으로 보는 것)는 모두 `\n`이 된다. 쪽 3 미만 경로는 구분자를 바꾸지 않는다. 비공백 줄이 없는 쪽의 빈 줄은 남는다. 끝 줄바꿈은 합칠 때 `\n`.join이라 없어진다. | 코드 확인 |
| R-08 | 합쳐진 텍스트에서 ASCII `-` 바로 앞이 단어 문자, `-` 바로 뒤가 정확히 줄바꿈 하나, 그 바로 뒤가 단어 문자 | 하이픈과 줄바꿈을 지워 두 글자를 붙인다(`informa-\ntion` → `information`). 쪽 경계에도 적용된다(쪽 합친 뒤라서). 하이픈 뒤 공백, 다음 줄 들여쓰기, 줄바꿈 둘, 다른 하이픈 문자(U+2010 등)는 잇지 않는다. `\r\n`은 쪽 3 미만 경로에서는 잇지 않지만 쪽 3 이상 경로에서는 R-07 때문에 `\n`이 돼 이어진다. 진짜 하이픈 복합어도 붙을 수 있다(`well-\nknown` → `wellknown`, 원본 주석이 알려진 한계로 적음). `\w`는 파이썬 `str` 정규식의 기본값인 유니코드 단어 문자다. | 코드 확인 |
| R-09 | 텍스트에 `0.2070.110` 같은 소수점 둘 이상의 표기 | `clean_pdftotext`는 숫자 문자열을 고치지 않고 표시도 하지 않는다. `full_text.txt`로 가는 텍스트에는 표시가 없다. 표시(`possible_joined_decimal_cells`, 패턴 `\d+\.\d+\.\d+` 앞뒤가 단어 문자·점이 아님)는 쪽 사이드카 경로에만 있다(행 6). 이 패턴은 `1.2.3` 같은 절 번호·버전도 잡는다. | 코드 확인 |
| R-10 | 엔진 체인이 정리 결과를 받음 | 다음 엔진으로 넘길지는 **정리 뒤** 텍스트의 `strip()`이 비었는지로 정한다. 머리말·쪽번호만으로 이뤄져 정리 결과가 공백뿐이면 그 엔진은 실패로 취급돼 다음 엔진으로 간다. 마지막(pdfminer)까지 비면 `ExtractionError`(메시지는 설치 안내). | 코드 확인 |
| R-11 | 정리와 정화의 순서 | 엔진 반환(=정리 완료) → 체인 종료 → 정화(행 4). 정리는 제로폭 문자 등이 아직 남은 텍스트에서 동작한다. | 코드 확인 |
| R-12 | R-11 때문에 줄에 제로폭 문자가 섞인 머리말·쪽번호 | 줄 비교는 정확 문자열 일치(`strip()`은 제로폭 문자를 공백으로 보지 않음)와 쪽번호 정규식(`\s`도 마찬가지)이라, 이런 줄은 같은 머리말로 세어지지 않거나 쪽번호로 인식되지 않아 남을 수 있다. 정화가 뒤에 해당 문자를 지워도 줄은 이미 남아 있다. | 추론 |

- 불변식: 출력에 `\f`가 없다. 입력이 같으면 출력이 같다(시간·외부 상태 없음). 입력 텍스트의 비공백 줄 중 지워질 수 있는 것은 쪽의 첫·마지막 비공백 줄뿐이고(R-05), 그 밖의 변경은 하이픈 이음(R-08)과 쪽 경계 `\f`→`\n`뿐이다. 전제: 쪽 3 이상이면 합친 텍스트는 줄 목록을 `\n`으로 이은 것이다.
- 미결정: 없음.
- 확인 한계: 정적 읽기만 했고 실행하지 않았다. pdftotext·pdfminer가 마지막 쪽 뒤에도 `\f`를 붙여 `split` 조각 수가 실제 쪽 수 + 1이 되는지(그러면 쪽 수 2인 문서도 3 이상으로 취급)는 외부 도구의 출력 형식이라 확인하지 못했다. 재구현이 같은 `split("\f")` 규칙을 쓰면 결과는 같다. pypdf `extract_text()`의 줄 구성도 외부 라이브러리 동작이라 확인하지 않았다.

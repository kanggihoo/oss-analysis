# [Q] 프로필은 어떻게 만들어지는가 (`/setup`)

- **상위 개요**: [overview.md](../overview.md)
- **검증 수준**: `코드 확인` (`setup.md` 전체와 `documents/README.md`를 읽음). 실제 실행은 `미확인` (내 서류가 없어 돌리지 않았다)
- **범위**: 검색 설정(Section 9, `search-queries.md`)은 뺐다.

## 1. 질문 및 결론

- **질문**: 평가, 글쓰기, 면접이 모두 기대는 프로필을 어떻게 만들고 어떻게 믿을 만하게 유지하는가.
- **핵심 결론**: `/setup`은 내 서류에서 사실을 뽑아 7개 프로필 파일에 넣되, **서류끼리 어긋나면 내가 고를 때까지 멈추고, 추론으로 채운 내용에는 "검토 전에는 믿지 말라"는 표시를 붙이고, 내가 확인하기 전에는 아무것도 쓰지 않는다.** 이 세 가지가 "프로필은 사실의 원본"이라는 전제를 지키는 장치다.

## 2. 동작 설명

### 2-1. 이미 아는 것에 빗대면

**프로필 파일은 회계장부와 같다.** 영수증(CV, LinkedIn, 졸업증명서)을 보고 장부에 적고, 영수증끼리 금액이 다르면 장부에 적기 전에 먼저 묻는다. 비유가 맞지 않는 곳: 장부는 숫자만 적지만 프로필에는 **추론**(예: 추천서에서 읽은 일하는 방식)도 들어간다. 그래서 추론에는 따로 표시가 붙는다.

### 2-2. 세 가지 입력 경로 (`setup.md:9-70`)

| 경로 | 언제 | 하는 일 |
|---|---|---|
| A. 서류 폴더 | `documents/`에 파일이 있을 때 | 서류를 읽고 교차 확인한 뒤 프로필에 병합 |
| B. CV 한 개 | 붙여넣은 CV 하나만 있을 때 | 추출 → 요약 → 빈 곳만 질문 |
| C. 인터뷰 | 서류가 없을 때 | 아래 9개 영역을 대화로 묻는다 |

경로 A는 `documents/`의 폴더별로 읽을 것이 정해져 있다 (`setup.md:111-131`).

| 폴더 | 뽑는 것 |
|---|---|
| `cv/` | 이름·연락처, 학력, 경력(직함·회사·기간·bullet), 기술, 언어와 수준, 논문, 수상 |
| `linkedin/` | About(행동 성향 추론에 사용), 경력, 기술, **언어 수준**(구조화된 출처라 신뢰도 높음), 받은 추천서 전문 |
| `diplomas/` | 공식 학위명, 기관 공식 철자, 졸업일, 성적 |
| `references/` | 추천인, 추천서 전문(인용문), 쓰인 역량 표현 |
| `projects/` | 프로젝트명, 문제 영역, 기술 스택, 핵심 난제, **측정 가능한 결과** |
| `applications/<회사>_<직무>/` | 공고, 제출한 커버레터·CV, 결과(`outcome.md`). 결과가 `in_progress`인 것은 보정에서 뺀다 |

### 2-3. 실제 사례 한 번 (경로 A, 값은 형식을 보이려는 가짜 예시)

1. `documents/cv/`에 CV가 있고 `linkedin/`에 LinkedIn PDF가 있다.
2. 읽어 보니 CV에는 "Data Analyst, A사, 2021-2023", LinkedIn에는 "Data Scientist, A사, 2021-2023"이다.
3. **A4 교차 확인**: 서류끼리 날짜·직함·학력·회사 철자가 다르면 번호를 붙여 보여 주고 **내 답을 기다린다**. 답이 없으면 다음 단계로 가지 않는다.
   ```
   1. Role title mismatch - A사:
      CV says: "Data Analyst"
      LinkedIn says: "Data Scientist"
      Which is correct?
   ```
4. 내가 "CV가 맞다"고 답한다. 이제 기준이 정해졌다.
5. **A5 변경 목록**을 두 바구니로 만든다.
   - **추가**: 프로필에 아예 없는 것(새 자격증, 새 프로젝트, 새 추천인). 한꺼번에 보여 주고 "전부 적용? 건너뛸 번호?"를 묻는다.
   - **충돌**: 이미 있는 내용과 다른 것(다른 기간, 다른 직함). **하나씩** 보여 주고 `keep / replace / manual` 중 고르게 한다.
6. 내가 확인한 항목만 Edit으로 **부분 수정**한다. 파일 전체를 다시 쓰지 않는다.
7. **A7**: 서류가 못 채우는 것(커리어 목표, 에너지를 주는 일, 절대 안 되는 조건, 사용 언어와 수준, 희망 연봉, 통근 제약)을 이어서 묻는다. 언어는 평가의 Language Gate가 쓰므로 건너뛰지 않고 직접 묻는다고 적혀 있다.

### 2-4. 서류에서 어느 프로필 파일로 가는가 (`setup.md:167-186`)

| 목적지 | 출처 | 규칙 |
|---|---|---|
| `01` 독립 프로젝트 | `projects/` | 서류 본문에 있는 내용으로만 쓴다(근거 고정) |
| `02` 행동 프로필 | LinkedIn About, 추천서 | 반복되는 형용사·표현을 뽑아 "강한 행동", "일하는 방식" 등에 **추가만**. 항상 *[Inferred from … - review before relying on this]* 표시 |
| `03` 문체 | 이전 커버레터 | **2개 이상**에서 같은 패턴일 때만 "Patterns Observed"에 추가. 기존 규칙은 안 고친다 |
| `04` 평가 | 공고 + 결과 쌍 | 면접·합격은 "강한 적합 신호", 무응답·거절 2건 이상 반복은 패턴으로 "Calibration"에 추가. 채점 틀은 안 고친다 |
| `05` CV 템플릿 | 이전 CV의 프로필 문장 | **추출 전에 사실을 프로필과 대조**. 지원서마다 맞춰 쓴 초안은 사실의 원본이 아니라서, 사실이 흘러간 초안이 템플릿이 되면 안 된다 |
| `06` 커버레터 | 이전 커버레터 | 기존과 **구조적으로 다른** 시작·bullet·끝 패턴만 |
| `07` 면접 | CV bullet, LinkedIn, 추천서 | **STAR를 쓰지 않고 스텁만** 만든다 ("Complete Manually") |

### 2-5. 경로 C 인터뷰의 영역 (`setup.md:266-330`)

신원, 학력(자격증 포함), 경력(직함·기간·책임 3~5개·성과·도구), 기술, 논문·수상, 행동 프로필, 커리어 목표, 추천인. 행동 프로필은 공식 검사(PI, DISC, MBTI)가 없으면 다섯 가지 질문으로 합성한다: 잘 맞는 환경, 에너지를 빼앗는 것, 팀에서 일하는 방식, 결정 속도, 소통 방식. 자기 답을 "구조화해서 쓴다"는 방식이라 사용자가 마크다운을 몰라도 된다.

### 2-6. 프로필이 낡지 않게 하는 장치

- **재실행해도 안전**(idempotent): 먼저 읽고 이미 있는 내용은 다시 제안하지 않는다. 서류를 추가하고 `/setup`을 다시 돌려도 중복되거나 덮어쓰이지 않는다 (`setup.md:74`, "Design Principles").
- **섹션만 갱신**: `/setup --section <이름>`.
- **새 사실의 입구**: `/apply`와 `/interview` 중에 확인된 사실은 같은 턴에 `01`에 되쓴다 (q2 2-2).
- 개인정보 경고: 파일이 git에 추적되므로 **공개 포크에 푸시하지 말라**는 안내를 시작과 끝에 둔다 (`setup.md` Step 0, Step 4).

## 3. 사람들이 흔히 오해하는 것

- "setup이 프로필을 자동으로 완성한다": 아니다. 추가 항목은 내가 `yes`를 해야, 충돌은 내가 하나씩 골라야 쓰인다. 추론은 표시가 붙은 채 남고, 면접 답변은 스텁까지만이다.
- "서류에서 읽은 것은 다 사실이다": 서류끼리 다르면 어느 쪽이 맞는지 모른다. 그래서 멈추고 묻는다. 지원서마다 맞춰 쓴 이전 CV는 오히려 사실의 원본에서 제외된다.

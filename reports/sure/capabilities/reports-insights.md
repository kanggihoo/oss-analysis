# 대시보드·리포트·인사이트 (소득·지출 집계, 대시보드 위젯, 리포트, 인사이트 생성기 8종)

> 가족(family)의 거래를 한 통화(가족 통화)로 모아 기간별 소득·지출·카테고리 합계를 계산하고(`IncomeStatement`), 이를 대시보드 위젯(현금흐름 Sankey, 지출 추이, 월별 수입·지출 막대, 도넛)과 리포트(요약, 월별 추이, 거래 breakdown, "평소 대비 지출")로 보여 주며, 사용자별 위젯 배치 설정을 저장하고, 매일 밤 8개 생성기로 "인사이트"(예산 위험, 현금 부족 경고, 유휴 현금, 목표 소진, 순자산 마일스톤, 저축률 변화, 지출 이상, 구독 점검)를 만들어 중복 없이 갱신·만료하는 규칙을 정의한다.

이 문서에서 쓰는 이름은 다음과 같다. "집계"는 `IncomeStatement`가 거래 행에서 만드는 합계 전체를 부른다. 한 합계 행은 "분류"(`income`, `expense`, `investment`)와 카테고리가 정한다. "총합(gross)"은 같은 카테고리 안의 소득과 지출을 서로 상쇄하지 않은 합이고, "순집계(net)"는 카테고리마다 `지출 − 소득`을 계산해 양수면 순지출, 음수면 순소득으로 나눈 값이다. 가족 통화 금액을 코드는 `Money`로 감싸지만 이 문서는 숫자(decimal)로 쓴다. "합성 카테고리"는 DB 행이 없는 "미분류"와 "기타 투자"다. "생성기"는 `Insight::Generators::*` 하나다. "인사이트"는 `insights` 행 하나이고, `dedup_key`가 한 가족 안에서 그 행의 정체성이다.

## 1부. 동작 설명

### 1.1 한눈에 보는 흐름

원화(KRW) 가족이 11월 18일에 앱을 열었을 때의 대표 흐름이다. 기준은 1.4다.

1. 사용자가 대시보드(`GET /`)를 열면 기간(`@period`)이 정해진다. 쿼리의 `start_date`·`end_date`가 있으면 그 구간, 없으면 `period` 파라미터나 사용자 저장값(`default_period`, 기본 `last_30_days`)이다(R-16, R-17).
2. 서버는 사용자의 위젯 순서·숨김 설정으로 위젯 목록을 만든다. 숨긴 위젯은 데이터를 계산하지 않는다. 보이는 위젯마다 데이터 빌더가 `IncomeStatement`와 `BalanceSheet`, `InvestmentStatement`를 부른다(R-18~R-21, R-30).
3. `IncomeStatement`는 사용자가 재무에 포함하는 계정의 거래 중 이체·보류·예정·제외 표시·세금 우대 계정 등을 걸러 내고, 각 거래를 거래일 환율로 가족 통화로 바꿔 카테고리별로 더한다(R-01~R-08).
4. 현금흐름 Sankey와 도넛은 카테고리별 순집계를, 월별 막대와 지출 추이는 총합과 일별 합계를 쓴다(R-24~R-28).
5. 사용자가 위젯을 끌어 옮기거나 접거나 높이를 바꾸면 클라이언트가 `PATCH /dashboard/preferences`로 JSON을 보내고, 서버는 사용자 `preferences` JSON에 합쳐 저장한다(R-21).
6. 리포트(`GET /reports`)는 사용자가 고른 기간(월·분기·연초부터·최근 6개월·직접)의 요약·월별 추이·거래 breakdown·평소 대비 지출을 보여 준다. 일부는 `IncomeStatement`, 일부는 거래를 직접 읽는다(R-36~R-41).
7. 매일 06:00(cron `0 6 * * *`, 시간대 표기가 없고 주석만 UTC라 실제 시각은 스케줄러가 읽는 서버 시간대에 달린다, 추론)에 `GenerateInsightsJob`이 미리보기 기능을 켠 구성원이 있는 가족마다 생성기 8개를 돌려 인사이트 후보를 만들고, `dedup_key`로 기존 행과 비교해 새로 만들거나 되살리거나 갱신하고, 이번에 다시 나오지 않은 활성 인사이트를 만료시킨다(R-49~R-53).
8. 사용자는 대시보드 피드(상위 3개)나 `/insights` 목록에서 인사이트를 읽음 처리하거나 "확인함(acknowledge)"으로 숨긴다. 숫자가 의미 있게 바뀌면 숨긴 인사이트도 다시 활성이 된다(R-45, R-46, R-50).

### 1.2 범위·통합 지점

- 제공: `IncomeStatement` 집계 계약(총합, 순집계, 일별 지출, 월별·카테고리별 중앙값·평균, 계정 필터용 eligible 계정), 기간(`Period`) 해석과 사용자 기본 기간 저장, 대시보드 위젯 목록·정렬·숨김·가시성·배치 설정 저장, 위젯별 계산(Sankey, 도넛 둘, 월별 막대, 지출 추이와 카테고리 필터, 인사이트 피드), 미리보기 현금흐름 그래프(카테고리·계정 기준)와 월간 현금흐름 JSON, 리포트(요약·월별 추이·거래 breakdown·평소 대비 지출·섹션 배치·CSV 계약), 인사이트 모델·상태·생성 job·생성기 8종.
- 제외:
  - 순자산 시계열·재무상태표·`InvestmentStatement`의 계산. [account-balances](./account-balances.md) R-41~R-46, R-51~R-58이다. 이 문서는 대시보드·리포트가 그것을 부르는 위치만 R-30, R-41에 쓴다. 단 순자산 breakdown 시계열과 `NetWorthVelocity`는 account-balances 1.2가 이 행으로 넘겼으므로 R-35에서 쓴다.
  - 예산 화면과 예산 계산(`Budget`, `BudgetCategory`). [budgets](./budgets.md) 소관이다. 이 문서는 예산 생성기와 리포트가 예산 메서드를 부르는 계약(R-61, R-37)만 쓴다. budgets R-17의 정정은 R-15다.
  - 목표(`Goal`)의 상태·남은 금액·환산 불완전 판정. 목표 스펙(병렬 작성 중) 소관이다. 목표 소진 생성기가 부르는 경계만 R-62에 쓰고 닫히지 않은 점은 U-01이다.
  - 정기 거래 occurrence의 생성·금액 해석·일정(`schedule.occurrences_per_year`). [recurring-transactions](./recurring-transactions.md) 소관이다. 현금 부족 경고와 구독 점검이 쓰는 질의 조건만 R-56, R-58에 쓴다.
  - 가족 테넌시와 계정 접근(`AccountShare`, `accessible_by`, `included_in_finances_for`). 승인 범위 밖이다. 사용 지점과 판정식 요약만 쓰고 가정으로 둔다(U-02).
  - 푸시 알림 전송(APNs 클라이언트, `PushSubscription::Delivery`). 외부 연동이라 사용자가 따로 만든다. job이 전송을 요청하는 조건만 R-52에 쓴다.
  - 화면 배치·CSS·Stimulus·ERB·i18n 문구. masonry 배치 알고리즘(`dashboard_masonry_controller`)은 열지 않았다. 인사이트 본문 문구(`config/locales/views/insights/*.yml`)는 열지 않았고 `template_key`와 `facts` 이름까지만 계약으로 쓴다.
  - AI 어시스턴트 `get_income_statement`·`get_budget`, 리포트 인쇄 화면(`reports#print`)과 PDF·XLSX 내보내기(주석 처리된 코드). 소비자라는 사실만 R-14에 쓴다. CSV 내보내기는 행 9(부속)이므로 계약만 R-43에 쓴다.
- 외부 의존·선행 계약: PostgreSQL(`PERCENTILE_CONT`, `date_trunc`, `generate_series`, `FILTER`, `pg_try_advisory_lock`, jsonb 연산자 `?`, `->>`)과 `Rails.cache`(없어도 결과는 같다, R-13). 현재 사용자(`Current.user`)·가족(`Current.family`)·접근 계정 판정은 호출자가 제공한다. 거래 `kind`·`excluded`·보류·예정 규칙은 [transactions](./transactions.md) R-16·R-18·R-71, 환율 조회·소수 자릿수·부호는 [money-currency-rules](./money-currency-rules.md) R-10·R-26·R-36·R-41, 계정 `exclude_from_reports`·상태·잔액·순자산 시계열은 account-balances R-09·R-11·R-38·R-46이다. 예산 메서드는 budgets R-19·R-20이다.
- 소유 상태·부작용: 이 문서가 쓰는 테이블은 `insights`(행 생성은 생성 job의 `create!` 하나뿐이고, 상태 변경은 job·`InsightsController`·API v1 확인이 한다, R-14, R-46)와 사용자 `preferences`(jsonb)의 대시보드·리포트 키뿐이다. 대시보드 진입이 `users.default_period`를 쓸 수 있다(R-17). 리포트의 예산 지표가 `budgets`·`budget_categories` 행을 만들 수 있다(R-37). 집계 자체는 읽기 전용이다.

### 1.4 행동 규칙과 남은 질문

**A. IncomeStatement 집계 (대시보드·예산·인사이트 공통)**

| ID | 조건·입력 | 반드시 관찰될 결과·사후 상태 | 검증 수준 |
|---|---|---|---|
| R-01 | 기간 합계에 들어가는 거래(`Totals`의 거래 부분 질의) | 거래마다 다음을 모두 만족할 때만 센다. (1) 계정이 이 가족 소속이고 상태가 `draft`·`active`이고 `exclude_from_reports = false`다. (2) 세금 우대 계정이 아니다(R-02). ### 2.2 코드 읽는 순서

1. 집계: `scoped_transactions_query.rb`(필터·분류·환산 조각) → `totals.rb` → `income_statement.rb`(합계·순집계·일별·통계 진입) → `family_stats.rb`·`category_stats.rb`. 이 네 파일이 대시보드·예산·인사이트 모두의 숫자를 정한다.
2. 대시보드: `pages_controller.rb`의 위젯 빌더(`dashboard_section_builders`)에서 시작해 위젯별 `build_*`로 간다. 설정 저장은 `user.rb`의 `update_dashboard_preferences`.
3. 미리보기 Sankey·월간 현금흐름: `cash_flow_graph.rb` → `category_netting.rb`·`sankey.rb`·`account_sankey.rb` → `cash_flow.rb`.
4. 리포트: `reports_controller.rb#setup_report_data`부터. 평소 대비 지출은 `spending_comparison.rb`.
5. 인사이트: `generate_insights_job.rb`(진입, upsert, 만료) → `generator_registry.rb` → `generator.rb`(공통) → 생성기 8개 → `insight.rb`.
6. 원본 구현 전략: 거의 모든 집계가 Rails 캐시와 인스턴스 메모를 겹쳐 쓴다. 재구현은 매번 계산해도 같은 결과다(R-13).

### 2.3 비교·재사용 출처

- budgets 스펙(`./budgets.md`)과의 관계: R-15가 정정·확정 목록이다. 이 문서의 R-10·R-11이 budgets U-01을 닫는다. 메인이 budgets R-17·R-18의 "기타 투자" 문장과 U-01을 이 스펙의 R-05·R-11로 대체하는 것이 맞다(공용 파일이라 이 작업에서는 고치지 않았다).
- 같은 기능을 다른 레포에서 스펙으로 만든 것은 없다.

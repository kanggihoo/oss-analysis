# 일반 한국어 글쓰기 장르 규약

> 한국어 모국어 화자가 쓰는 글 7개 장르(문서·보고서, 개인·일상, 메신저, 동료 간 메일, 코드 리뷰 댓글, 공개 게시글, 대화문)마다 목표와 규칙, 전후 예시를 정한 지침이다.

## 1부. 동작 설명

### 1.1 한눈에 보는 흐름
1. 요청이 한국 고객 대상 글이나 이력서가 아니라 일반 한국어 글쓰기라면(문서, 개인 글, 채팅, 동료 메일, 공개 글, 코드 리뷰, 대화) `native-writing.md`의 해당 장르 절을 읽는다([response-format](./response-format.md) R-06).
2. 장르의 목표에 맞춰 규칙을 적용하되, "사실 먼저" 규칙(보호 항목)은 그대로 적용된다.
3. 장르 규칙은 SKILL.md의 편집 판단과 같이 쓰인다. 장르가 어투와 길이의 기본값을 정하고, 수정 수락은 [edit-and-stop-rule](./edit-and-stop-rule.md)이 정한다.

### 1.2 범위·통합 지점
- 제공: 장르 7개의 목표·규칙·전후 예시.
- 제외: 한국 고객 대상 비즈니스 채널([business-channel-rules](./business-channel-rules.md)), 이력서·지원서(별도 스킬, 이 스펙 범위 밖), 입력 모드 판별.
- 외부 의존·선행 계약: 입력 모드 S1, 보호 항목 S2. 고객 대상 메일은 `business-korean.md`의 B2B 영업 메일 절로 보낸다(`native-writing.md:87`).
- 소유 상태·부작용: 없음.

### 1.3 인터페이스와 데이터 의미
| 장르 | 목표 | 기본 방향 |
|---|---|---|
| 문서·보고서 | 명확하고 구조 있고 전문적이되 기업식 안개가 없게 | 같은 개념은 같은 용어, 필요한 격식 어휘 유지 |
| 개인·일상 | 계획·요청·반응이 자연스럽되 작성자의 개성을 납작하게 하지 않게 | 관계·감정·유머·친밀도를 유지, 사람들이 실제로 쓰는 말 |
| 메신저·채팅 | 실제 사람이 채팅에 쓴 것처럼 | 짧되 한 생각을 토막내지 않음. 관계에 맞춤(고객·상사와는 합쇼체 가능) |
| 동료 간 메일 | 정중하고 명확하고 마찰이 적게 | 인사·맺음은 관계에 비례, 요청을 일찍 |
| 코드 리뷰 댓글 | 명확하고 구체적이고 존중하되 요점을 숨기지 않게 | 작성자가 아니라 코드에 대해 말함, `개선의 여지` 대신 구체적 제안 |
| 공개·소셜 게시글 | 짧게 읽어도 믿을 만하고 이해하기 쉽게, 낚시나 압축 보고서가 아니게 | 실제 관찰·결과로 시작, 숫자는 범위·비교·측정 상태와 함께 |
| 대화문 | 화자의 목소리·관계·장면 압박을 보존 | 독특한 목소리를 일반 존댓말로 정상화하지 않음 |

### 1.4 행동 규칙과 남은 질문
| ID | 조건·입력 | 반드시 관찰될 결과·사후 상태 | 검증 수준 |
|---|---|---|---|
| R-01 | 문서·보고서 | 같은 개념에는 같은 용어. 행동을 가리는 번역투는 고치되 의미를 바꾸는 한정어·매개는 유지. 보고서에 맞는 격식 어휘는 짧다는 이유로 캐주얼하게 바꾸지 않음. 혼합 독자에게 필요한 전문 용어는 처음 한 번 설명하고 같은 영어 병기를 반복하지 않음. 섹션 제목만 반복하는 요약 문단을 피함. 비교·불일치가 중요하면 양쪽을 명시하고, 원문이 점검을 했다고만 하면 결함을 찾은 것처럼 쓰지 않음 | 코드 확인 |
| R-02 | 개인·일상 | 원문의 관계·감정·유머·친밀도를 유지. 사람이 그 상황에서 실제로 쓰는 말을 선호. 원문에 없는 따뜻함·농담·속어·친밀감·더 강한 감정을 더하지 않음 | 코드 확인 |
| R-03 | 메신저·채팅 | 메시지를 짧게 하되 연결된 하나의 생각을 고립된 진술로 자르지 않고 자연스러운 연결어미나 접속사를 쓴다. 매체가 아니라 관계에 맞춘다(고객·상사와의 채팅은 합쇼체 유지 가능, 줄임말·부드러운 어미는 어울릴 때만). 이미 없는 이모지·속어·과한 친근함을 더하지 않음 | 코드 확인 |
| R-04 | 동료 간 메일 | 인사·맺음을 관계에 비례하게. 요청을 일찍. 흐름을 늦추는 반복 사과와 의례적 문구를 제거. 고객에게 보내는 메일은 B2B 영업 메일 절을 본다 | 코드 확인 |
| R-05 | 코드 리뷰 댓글 | 작성자가 아니라 코드에 대해 말한다. `개선의 여지` 같은 막연한 평가를 구체적 제안으로 바꾼다. 불확실성은 리뷰어가 실제로 확신하지 못할 때만 유지한다. 요청된 변경이 불분명해질 만큼 부드럽게 하지 않는다 | 코드 확인 |
| R-06 | 공개·소셜 게시글 | 원문에 있는 실제 관찰·결과·긴장으로 시작. 문단·게시물마다 중심 생각 하나와 기반 작업을 못 본 독자를 위한 맥락. 숫자는 범위·비교·측정 상태와 함께 유지하고 검토한 데이터·편집·합성 사례·사용자 증거·채택을 같은 종류의 증거처럼 제시하지 않음. 실제 수행한 작업에 맞는 동사를 쓰고 리뷰를 돌파구처럼 쓰거나 추상 명사에 극적 동작을 시키지 않음. 내부 경로·비공개 구현은 민감하게 다루어, 게시 의도가 분명하면 독자에게 도움이 안 되는 세부를 제거하고 게시 의도·허락이 불분명하면 노출하지도 조용히 삭제하지도 말고 확인을 요청. 조작된 논쟁·수사적 낚시·참여 유도, 근거 없는 동의 요청 끝맺음을 피하고 원문이 뒷받침하는 시사점·교훈·저장소 링크·구체적 행동으로 끝낸다 | 코드 확인 |
| R-07 | 대화문 | 독특한 목소리를 일반적 존댓말로 정상화하지 않는다. 감정적 하위 텍스트와 속도를 유지한다. 장면·인물 목소리가 지지하지 않는 현대 채팅체를 피한다 | 코드 확인 |
| R-08 | 모든 장르 | 이 절들은 한국어 화자가 쓴 글에 대한 것이고 같은 "사실 먼저" 규칙이 적용된다(보호 항목은 [fact-protection](./fact-protection.md)) | 코드 확인 |

- 불변식: 장르 규칙이 어투와 길이를 바꿔도 사실·조건·약속은 바뀌지 않는다(R-08).
- 미결정: 없음.
- 확인 한계: 지침 문장 확인이다. 예시는 합성이고 기대 행동의 한 예이며 정확 일치 목표가 아니다(`native-writing.md:12-15`). 레포의 점수 기록(v0 골든셋)은 이 장르들을 포함하지만 이전 스킬 revision의 모델 채점이며 현재 지침을 대표하지 않는다([eval-procedure-and-records](./eval-procedure-and-records.md)).

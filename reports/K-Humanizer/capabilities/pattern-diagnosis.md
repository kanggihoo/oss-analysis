# 번역투·어미·흐름 진단표

> 한국어 문장이 왜 어색한지 진단하고 "언제 고치고 언제 유지하는지"를 정하는 진단표 7개와 그 사용 규칙이다. 금지어 목록이 아니다.

## 1부. 동작 설명

### 1.1 한눈에 보는 흐름
1. 편집·번역 중 문장이 뻣뻣하거나 번역투로 읽힌다고 느끼면 `patterns.md`를 연다([edit-and-stop-rule](./edit-and-stop-rule.md) R-04가 호출한다).
2. 그 문장의 특징이 7개 표 중 어느 행의 첫 칸과 맞는지 찾는다.
3. 맞더라도 그 문장이 실제로 그 때문에 뻣뻣하거나 번역투일 때만 둘째 칸대로 고친다. 셋째 칸의 조건이면 유지한다.
4. 고친 뒤 문단 흐름을 다시 읽는다.

### 1.2 범위·통합 지점
- 제공: 표 7개의 구조와 사용 규칙, 접속·연결어미 규칙, 합친 문장 재검토 규칙, 고객 대상 외래어·내부 용어 규칙.
- 제외: 실제 수정 여부의 최종 판단(편집 수락 조건, [edit-and-stop-rule](./edit-and-stop-rule.md) R-07), 사실 보호([fact-protection](./fact-protection.md)).
- 외부 의존·선행 계약: 없음.
- 소유 상태·부작용: 없음.

### 1.3 인터페이스와 데이터 의미
표 7개의 구조와 주제는 다음과 같다. 개별 행은 1.5의 C-ID로 가져간다.

| 표 | 행이 다루는 것 (첫 칸의 예) | 열 구조 |
|---|---|---|
| Translationese and English-shaped grammar | `~를 통해`, `~에 대해`, `~에 있어서`, `가지고 있다`, `~에 의해`, `~하게 되었다`, 반복된 `~할 수 있다`, `단순히 X가 아니라 Y`, `~와 관련하여`, 영어 직역으로 숨은 행동, 영어에서 온 대명사(`당신`·`그것`·`우리는`·`귀하의`), `~이 가능합니다`, 이중 부정, `진행`, `~을 제공합니다`, 직역한 영어 관용구 (16행) | 원문에 X가 있다 / 조건이 맞을 때 쓸 것 / 유지하거나 다르게 다룰 때 |
| Register and endings | 합쇼체·해요체 혼용, 소비자 앱의 `~하시겠습니까?`, 격식 서두, `~하도록 하겠습니다`, 번역된 명령형 CTA, 겹친 사과·감사 (6행) | 같음 |
| Abstract nouns, filler, and empty weight | `전략적`·`효과적` 군집, `가능성`·`중요성` 등 추상 명사, `결론적으로`, `시사하는 바가 크다`, `다양한`·`의미 있는`, 출처 없는 `전문가들은`, `~라는 점입니다` (7행) | 같음 |
| Reader-facing specificity | `좋은 경험`, 양쪽이 없는 `어긋남`, 공간 은유, 대상·방법 없는 `꼼꼼히 살폈다`, 극적 동작을 쓴 홍보 문장 (5행) + 산문 규칙(제품 페이지의 `이 화면은 …입니다` 자기소개, 의미 없는 `한눈에` 제거) | 같음 |
| English and insider wording | 내부 용어를 일반 독자용으로 풀어 쓰는 표(컨텍스트→맥락 등 16행). 소프트웨어·내부 프로세스 글에만 쓴다 | 내부 용어 / 선호할 표현 (2열) |
| Sentence and paragraph flow | 원문이 뒷받침하는 관계(이유→결과, 대조·제한, 순서, 같은 주제의 추가) → 가능한 연결 → 한계 (4행) | 원문이 지지하는 관계 / 가능한 연결 / 경계 |
| Rhythm and punctuation | `-고`·`-며` 뒤 쉼표, 영어식 쉼표·대시·느낌표, 반복되는 문장 시작 접속어, 같은 길이·어미, 억지 3항 병렬, `~구축`·`~개선`·`~강화` 명사 종결 (7행) | 원문이 이렇게 한다 / 쓸 것 (2열) |

### 1.4 행동 규칙과 남은 질문
| ID | 조건·입력 | 반드시 관찰될 결과·사후 상태 | 검증 수준 |
|---|---|---|---|
| R-01 | 표의 첫 칸과 문장이 맞는다 | 그것만으로 고치지 않는다. 문장이 실제로 그 때문에 뻣뻣하거나 번역투로 읽힐 때만 행을 적용하고, 이미 독자에게 맞는 평범한 표현은 유지한다 | 코드 확인 |
| R-02 | 어떤 단어든 | 금지어는 없다. `통해`, `제공`, `진행`, `관련하여`, `대해`는 문장·독자에 맞으면 평범한 한국어다. 정확한 격식 표현을 짧다는 이유로 캐주얼한 유의어로 바꾸지 않는다(`품질 관리에 중점을 두었습니다`와 `…집중했습니다`는 뜻이 다르다). 번역 문장도 단어별 목록이 아니라 채널 안에서 문장 전체로 판단한다 | 코드 확인 |
| R-03 | 사용자 대상 고객 문구 | `포인트`(적립), `쿠폰`, `리뷰`, `구독`, `노쇼`, `라이더` 같은 외래어는 고객 자신의 어휘이므로 유지한다. 제품이 이미 한국어 UI·도움말에서 쓰는 용어가 있으면 어디서나 그 용어를 쓴다 | 코드 확인 |
| R-04 | 비전문 독자에게 필요한 전문 용어·약어 | 첫 사용 때 짧게 설명하고 같은 영어 병기를 문서 전체에서 반복하지 않는다. 제품명·코드 식별자·설정 키·채용 공고 키워드는 그대로 둔다. 필요한 어색한 용어는 구체적 설명 근처에 쓴다 | 코드 확인 |
| R-05 | 용어를 다른 모호한 명사로 바꾸려는 경우 | 바꾸지 않는다(`품질 게이트를 고도화했다`→`품질 기준을 고도화했다`는 추상이 그대로). 실제 규칙이나 점검을 말한다. 법률·의학·학술·요리·제품·기술의 정확한 용어와 확립된 용어는 정밀도가 필요하면 유지하고, 문서화된 방법·범주를 근거 없는 유행어로 바꾸지 않는다 | 코드 확인 |
| R-06 | 이어지는 산문 | 문장 수를 줄이거나 접속·주어를 지우기 전에 문단으로 읽는다. 주어는 독자가 누가 행동하는지 알 수 있는 동안만 생략한다. 다음 문장이 무엇을 더하고 대조하고 설명하고 이어 가는지 흐름을 유지하고 그것을 쉽게 하는 가장 작은 변경만 한다 | 코드 확인 |
| R-07 | 접속 표현 선택 | 이유→`그래서`·`따라서`·`-아서/-어서`는 원문이 그 인과를 세운 경우에만, 대조→`하지만`·`다만`·`-지만`·`-는데`는 실제 대조·제한일 때만, 순서→`이후`·`그다음`·`-고 나서`·`-한 뒤`는 순서를 인과로 바꾸지 않고, 추가→`또`·`-고`·`-면서`·구체적 지시어는 지시 대상이 분명할 때만(`-면서`는 실제로 겹치는 행동에만). 기존 접속어가 일을 하면 유지하고 문장 경계마다 넣거나 동의어를 돌려 쓰지 않는다. 연결이 불명확하면 구체적 공통 주어·지시어를 되살린다 | 코드 확인 |
| R-08 | 인접한 짧은 문장이 같은 주어·한 생각 / 한 문장에 너무 많은 내용 | 앞의 것은 연결어미로 합치는 것을 고려하고 뒤의 것은 완결된 생각에서 나누되 다음과의 연결을 유지한다. 이미 일관된 산문은 건드리지 않는다 | 코드 확인 |
| R-09 | 합친 문장을 유지하기 전 | 합쳐진 사실 각각이 자기 상태·조건·시점 한정어를 유지하고 어느 서술어·한정어가 어느 사실의 것인지 독자가 알 수 있어야 한다. 현재 상태와 가능한 미래 변화는 별개의 사실이며 공유된 어미나 연결어미 사슬이 하나를 다른 것으로의 전이처럼 읽히게 해서는 안 된다. 합치기가 이를 흐리면 더 분명한 접속이나 완결된 절로 나눈다. 관련 없는 사실을 합치거나 이력서 bullet·UI 라벨·의도적으로 끊은 대사를 리듬 때문에 합치지 않는다 | 코드 확인 |
| R-10 | 문장부호·서식 | 도착지에서 기대되는 문장부호와 서식을 따른다. 읽기를 어렵게 하거나 제공된 스타일 가이드와 충돌할 때만 부호를 바꾸고, 범위·묶음·필수 서식을 나타내는 부호와 인용문·공식 명칭·코드·식별자·플레이스홀더·URL은 유지한다 | 코드 확인 |
| R-11 | 제품 페이지·대시보드·문서의 `이 화면은 … 하는 화면입니다` 자기소개, 확인할 수 없는 `한눈에`·장식 부제·굵은 라벨·균형 잡힌 태그라인 | 제목·UI가 이미 말하는 것이면 제거하고 실제 항목·상태로 바꾼다. 실제 주장(한 화면에 모두 보여 주는 랜딩 등)이거나 범위·제약·대상을 더하는 부제는 유지한다 | 코드 확인 |

- 불변식: 표의 어느 행도 단독으로 수정 근거가 되지 않는다(R-01).

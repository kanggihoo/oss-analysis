# 이력서 증거 경계·재작성

> 이력서·경력기술·포트폴리오 요약·LinkedIn 프로필·지원서를 자연스럽게 다듬되, 모든 주장을 제공된 증거 안에 두고 개인/팀 기여, 계획/완료, 지표의 측정 조건을 구분하게 하는 `k-humanizer-resume` 스킬의 핵심 규칙이다.

## 1부. 동작 설명

### 1.1 한눈에 보는 흐름
1. 호스트가 `k-humanizer-resume`을 불러온다(이력서·경력기술·포트폴리오 요약·LinkedIn·지원서, 또는 `k-humanizer`가 위임한 경우. [response-format](./response-format.md) R-07).
2. 다듬기 전에 증거를 식별한다: 사실·행동·결과·숫자·기간, 개인/주도/공유/지원, 측정됨/관찰됨/계획/미검증, 공개 가능한 용어.
3. 경계가 빠져 있고 다듬으면 주장 강도가 바뀔 것이면 원문 강도를 유지하거나 증거 공백을 표시한다.
4. 조건부 재작성 표 25행과 읽는 순서(문제·범위 → 판단·행동 → 확인된 결과)를 적용한다.
5. 마지막 점검 11항목으로 확인하고, 붙여넣기 가능한 한국어로 시작하는 응답을 낸다.

### 1.2 범위·통합 지점
- 제공: 증거 식별, 재작성 규칙(`SKILL.md`의 규칙과 `resume.md`의 표·읽는 순서·예시·점검), 이력서 하드 페일, 이력서 전용 채점 점검(전체 문서용 포함).
- 제외: 작업 유형 분류·섹션별 역할·공고 맞춤([resume-workflow](./resume-workflow.md)), 직무별 맥락([resume-role-context](./resume-role-context.md)), 지원 동기([application-motivation](./application-motivation.md)), 직무별 평가 점검(직무 스펙에 있음).
- 외부 의존·선행 계약: 5축 점수와 하드 페일 개념([evaluation-rubric](./evaluation-rubric.md)), 응답 모양과 위임(S4, [response-format](./response-format.md)). `k-humanizer`가 설치돼 있으면 그 `patterns.md`를 진단에 쓴다.
- 소유 상태·부작용: 없음.

### 1.3 인터페이스와 데이터 의미
| 연산·데이터 | 입력·출력 / 타입 | 의미·제약 |
|---|---|---|
| 증거 식별 4항목 | 원문 → 메모(내부) | (1) 사실·행동·결과·숫자·기간, (2) 개인/주도/공유/지원, (3) 측정됨/관찰됨/계획/미검증, (4) 공개 가능한 용어·프로젝트명 |
| 조건부 재작성 표 | 25행 × (원문에 X가 있다 / Y를 쓴다 / Z는 하지 않는다) | 행 주제: `저는` 시작; 자기평가 형용사; `기여했다`·`고도화했다`; 행동을 숨기는 동사; 측정 없는 개선 주장; 숫자와 조건; 팀·회사 결과; 계획·미출시 변경; 도구 나열; 긴 배경; `전 과정`·`전반`; 일반 리크루터용 내부 용어; 고유명·방법·분야 용어; 공고 반영과 맞춤; 같은 경험의 다른 직무 재사용; 어색한 필수 키워드; 연차+도구 나열 소개; 관련 없는 프로젝트 구조 재작성; 섹션 간 같은 문장 반복; 비공개 프로젝트명; 미래형 `~하고자 합니다`; 모든 bullet의 같은 3단 틀; 테스트·비교만 했다는 원문; 행동을 숨기는 은유; AI 사용을 `직접 검토했다`로만 서술 |
| 읽는 순서 | 문제·범위 → 판단·행동 → 확인된 결과 | 문장 틀이 아니라 읽는 순서. 결과를 측정하지 못했으면 행동만으로 한 bullet이 될 수 있다 |
| 마지막 점검 | 11항목 | 모든 주장이 증거·기여 경계 안, 팀 결과는 팀 결과, 계획·제안·구현·병합·출시·관찰 결과의 구분, 지표의 조건, 측정 안 된 효과를 사실로 쓰지 않음, 독자가 일·결정·결과를 알 수 있음, 공고 용어·분야 이름 유지, 고유명·방법 유지, 직무 강조는 책임에서 도출, 테스트를 결함 발견으로 쓰지 않음, 비공개 이름·근거 없는 서비스 분류 추가 안 함 |

### 1.4 행동 규칙과 남은 질문
| ID | 조건·입력 | 반드시 관찰될 결과·사후 상태 | 검증 수준 |
|---|---|---|---|
| R-01 | 이력서·경력기술·포트폴리오 요약·LinkedIn 프로필·지원서 | 이 스킬이 처리한다. 그 밖의 한국어는 `k-humanizer`로 보낸다. 목표는 지원자가 신경 써서 쓴 것처럼 읽히되 원문이 뒷받침하지 않는 것을 더하지 않는 것이며, AI 탐지 점수는 목표 밖이다 | 코드 확인 |
| R-02 | 재작성 전 | 증거 4항목을 식별한다. 경계가 빠져 재작성이 주장 강도를 바꿀 것이면 원문 강도를 유지하거나 증거 공백을 표시하고 그럴듯한 성과로 메우지 않는다 | 코드 확인 |
| R-03 | 사용자가 메모로 초안을 요청 | 제공된 증거만 쓴다. 확인된 행동은 측정된 결과가 없어도 그 자체로 서도록 둔다 | 코드 확인 |
| R-04 | 모든 재작성 | 광범위한 자기 설명보다 문제·범위, 판단·행동, 확인된 결과를 앞세운다. 증거가 뒷받침하지 않는 `탁월한`·`혁신적인`·`압도적인`은 제거한다. 숫자는 비교·측정 조건과 함께 유지한다. 개인·주도·공유·지원을 구분하고 계획을 완료로, 팀 결과를 개인 결과로, 측정 안 된 효과를 지표로 바꾸지 않는다. 효과의 증거가 없으면 구체적 행동을 유지하거나 공백을 표시한다 | 코드 확인 |
| R-05 | 직무·분야 | 운영·기획·QA·디자인·마케팅·고객 응대·리서치·교육의 확립된 언어와 실제 일을 유지하고 모든 분야를 하나의 성과 틀로 만들지 않는다. 리크루터·채용 담당이 실제 쓰는 분야 용어(영어 포함)를 유지하고 독자가 필요할 때만 내부 표현을 설명한다 | 코드 확인 |
| R-06 | 선택·삭제·순서 변경 | 사용자가 구성·맞춤·구조 검토를 요청할 때만 한다. 그렇지 않으면 사용자가 물은 구절만 고치고 이미 되는 표현을 유지한다 | 코드 확인 |
| R-07 | 문체 | 문서에 이미 있는 bullet 스타일에 맞춘다. 소개·지원 글은 완결된 문장, 압축된 이력서 bullet에서는 `설계`·`구현`·`검증`·`담당` 같은 간결한 행동 명사 종결도 자연스럽다. 한 섹션 안에서 이유 없이 명사 종결과 완결 서술을 섞지 않고, `개선`·`강화` 같은 추상어 뒤에 행동이 숨는 명사 종결은 고쳐 쓴다 | 코드 확인 |
| R-08 | 표의 각 행 | 원문에 X가 있을 때 Y를 쓰고 Z는 하지 않는다(표 25행의 구체 내용은 C-02). 예: 계획·제안·미출시 변경은 `제안했다`·`검증했다`·정확한 알려진 상태로 쓰고 완료 전에 `구축했다`·`출시했다`·`도입했다`·`개선했다`로 쓰지 않는다 | 코드 확인 |
| R-09 | 문장 순서 | 문제·범위 → 판단·행동 → 확인된 결과 순서를 선호하되 틀이 아니다. 한 bullet이 행동만 가질 수 있고, 판단과 조건이 중요하면 두 문장이 필요할 수 있다. 섹션 역할(소개는 포지셔닝, 기술은 도구, 경력은 증거)을 지켜 같은 성과를 세 섹션에 반복하지 않는다. 모든 직무에 같은 종류의 증거를 요구하지 않으며 지표는 해석 가능한 조건과 함께 있을 때만 유용하다. 선택이 왜 통했는지 설명하는 제약·발견·방법은 주장 가까이에 둔다 | 코드 확인 |
| R-10 | 이력서 하드 페일 | 일반 하드 페일에 더해 다음이면 Meaning Fidelity를 1로 제한: 팀 결과를 개인 결과로, 계획·제안·후보·미출시 변경을 완료로, 측정 안 된 성능·비용·안정성·생산성 효과 추가, 제공된 비교 대상·표본·평가자를 지표에서 삭제, 비공개 프로젝트명 공개나 저장소로부터 개인 소유 추론, 검증된 방법·분야 용어를 다른 것으로 교체. 조작된 사실·지표·인과 효과·소유 주장은 한국어가 자연스러워도 실패 | 코드 확인 |
| R-11 | 이력서 전용 채점 | 5축 점수 뒤에 증거 경계, 기여 경계, 측정 무결성, 결정 명료성, 독자 적합을 독립적으로 점검한다. 전체 이력서·경력 문서면 목표 명료성, 섹션 규율, 증거 분포, 반복 통제, 출력 사용성도 점검한다. 사용자가 메모로부터 구성·공고 맞춤·전체 검토를 요청했다면 구조 재작성을 감점하지 않고 사실 경계는 그대로 둔 채 편집 절제를 요청 기준으로 채점한다 | 코드 확인 |
| R-12 | 응답 | 붙여넣기 가능한 한국어로 시작한다. 누락 사실이 소유권·완료 상태·주장 강도를 실질적으로 바꿀 때만 질문을 더한다. 노트·질문은 요청한 언어로 쓰고 변경 설명은 사용자가 물을 때 한다 | 코드 확인 |
| R-13 | `k-humanizer`가 설치돼 있다 | 번역투·AI 문체 진단에 그 `patterns.md`를 쓴다 | 코드 확인 |

- 불변식: 재작성 후에도 소유(개인/팀)·상태(계획/완료)·측정 조건이 원문보다 강해지지 않는다(R-04, R-10).
- 미결정: 없음.

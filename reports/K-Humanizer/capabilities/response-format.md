# 응답 형식·참조 선택

> 결과를 붙여넣기 가능한 한국어로 시작하고 사례별로 필요한 노트·질문만 덧붙이게 하며, 용도에 맞는 참조 파일이나 다른 스킬로 보내는 지침이다. 공유 계약 S4(스킬 간 위임)를 소유한다.

## 1부. 동작 설명

### 1.1 한눈에 보는 흐름
1. 호스트가 스킬의 `description`을 보고 이 스킬을 불러온다. 이력서·지원서면 `k-humanizer-resume`으로 넘긴다.
2. 작업에 맞는 참조를 읽는다: 비즈니스 채널은 `business-korean.md`, 문서·개인·채팅·동료 메일·공개 글·코드 리뷰·대화문은 `native-writing.md`, 평가·비교는 `evaluation.md`.
3. 작성·편집을 마친 뒤 결과를 R-01~R-05 형식으로 낸다.

### 1.2 범위·통합 지점
- 제공: 응답의 구성 순서와 사례별 노트·질문 규칙, 노트·질문의 언어, 참조 선택, 스킬 간 위임(S4).
- 제외: 번역·편집 자체([edit-and-stop-rule](./edit-and-stop-rule.md)), 노트에 쓸 사실 판단([input-mode-and-authority](./input-mode-and-authority.md), [fact-protection](./fact-protection.md)). `agents/openai.yaml`과 플러그인 매니페스트는 feature map 행 14(부속, 제외)다.
- 외부 의존·선행 계약: 입력 모드 S1과 보호 항목 S2. 호스트가 스킬 `description`으로 호출 여부를 정한다.
- 소유 상태·부작용: 없음.

### 1.3 인터페이스와 데이터 의미 (S4 포함)
| 연산·데이터 | 입력·출력 / 타입 | 의미·제약 |
|---|---|---|
| 응답 구성 | 한국어 본문 → (선택) 노트 → (선택) 질문 | 본문이 맨 앞. 앞에 아무것도 두지 않는다 |
| 노트 | 1~2문장 | 고친 실질 차이(빠진 조건, 추가된 약속, 명백한 불일치를 고치려고 바꾼 어투)만. 일상적 기본값은 노트하지 않는다 |
| 질문 | 필드당 하나 | 자리표시자 또는 미해결 절이 한국어 안에 보이는 상태에서 뒤에 붙인다 |
| 노트·질문의 언어 | 요청의 언어 | 한국어를 못 읽는 사용자가 답할 수 있게 하기 위함 |
| 참조 선택 표 | 용도 → 파일 | 비즈니스 채널 → `business-korean.md` 비즈니스 절, 이력서·경력기술·포트폴리오 요약·지원서 → `k-humanizer-resume`, 문서·개인 글·채팅·동료 간 메일·공개 글·코드 리뷰·대화 → `native-writing.md`의 해당 절, 편집·번역 검토·비교 → `evaluation.md`, 문구 진단 → `patterns.md` |
| 스킬 간 위임(S4) | `k-humanizer` → `k-humanizer-resume` | 이력서 계열은 k-humanizer가 직접 다루지 않고 넘긴다. 반대로 resume 스킬은 k-humanizer가 설치돼 있으면 그 `patterns.md`를 번역투·AI 문체 진단에 쓰고, 그 밖의 한국어는 k-humanizer로 보낸다 |

### 1.4 행동 규칙과 남은 질문
| ID | 조건·입력 | 반드시 관찰될 결과·사후 상태 | 검증 수준 |
|---|---|---|---|
| R-01 | 모든 응답 | 붙여넣기 가능한 한국어로 시작하고 그 앞에 아무것도 두지 않는다. 문자열 키, 제목·프리헤더 필드, 목록 항목, 의도적 줄바꿈은 유지하되 그 안에서는 입력 모드가 허용하는 만큼 문장을 재배열·합치기·나누기 할 수 있다 | 코드 확인 |
| R-02 | 단순 편집·번역, 이미 자연스러웠던 글 | 한국어만 낸다. "수정할 부분이 없습니다" 같은 판정, 수정 목록, 숫자·용어를 유지했다는 확인 문구를 쓰지 않는다 | 코드 확인 |
| R-03 | 원문과의 어긋남을 고쳤거나 다른 실질적 차이가 있다 | 실제 차이(빠진 조건, 추가된 약속, 분명한 불일치를 고치려고 바꾼 어투)를 한두 문장으로 말한다. 일상적 기본값은 노트하지 않는다 | 코드 확인 |
| R-04 | 중요한 사실이 없거나 어느 버전이 우선인지 미해결 | 한국어 안에 자리표시자나 미해결 절이 눈에 보이게 남고 그 뒤에 해결에 필요한 질문을 붙인다(독립적으로 빠진 사실마다 하나) | 코드 확인 |
| R-05 | 노트·질문을 쓸 때 | 요청의 언어로 쓴다. 요청하지 않으면 다른 톤·버전을 내놓지 않는다. 변경 이유는 사용자가 물으면 설명한다. 검토 요청에는 의미 오류와 선택적 스타일 선택을 구분한다 | 코드 확인 |
| R-06 | 용도별 참조 | 위 참조 선택 표대로 읽을 파일을 정한다 | 코드 확인 |
| R-07 | 이력서·경력기술·포트폴리오 요약·지원서 | `k-humanizer-resume`로 넘긴다. resume 스킬은 k-humanizer 설치 시 그 `patterns.md`를 진단에 쓰고, 다른 한국어는 k-humanizer로 보낸다 | 코드 확인 |

- 불변식: 응답의 첫 줄은 본문(R-01).
- 미결정: 없음.
- 확인 한계: 지침 문장 확인이다. R-05의 "요청의 언어"는 레포 자신이 관측으로는 지켜지지 않았다고 적는다. 영어로 요청해도 기본 상태 점검 3건은 모두 한국어로 답했고, 현재는 사용자가 영어 설명을 원한다고 요청에 함께 적으라고 안내한다(`README.md` 버전 기록 아래 문단, `CHANGELOG.md` 0.5.0 "Still open"). 호스트가 `description`으로 스킬을 고르는 방식과 resume 스킬의 위임 실제 동작은 확인하지 않았다.

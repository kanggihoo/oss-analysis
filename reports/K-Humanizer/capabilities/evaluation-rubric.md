# 평가 루브릭 (일반)

> 번역·편집 결과 하나를 입력 모드별로 5개 축에서 1~5점으로 채점하고, 도메인별 점검·Red Flags·비즈니스 하드 페일로 "그대로 쓸 수 있는가"를 판정하는 루브릭이다. 공유 계약 S3(평가 5축 점수)를 소유한다.

## 1부. 동작 설명

### 1.1 한눈에 보는 흐름
1. 채점 전에 입력 모드(S1)를 확인한다. 같은 출력이 모드에 따라 절제된 것일 수도 지나친 것일 수도 있다.
2. 출력 하나를 5개 축(의미 충실, 한국어 자연스러움, 맥락 적합, 편집 절제, 실용성)에서 1~5로 채점한다.
3. 5점을 낸 뒤 도메인별 위험을 점검한다.
4. Red Flags에 걸리면 문장이 매끄러워도 점수는 2 이하다.
5. 비즈니스 하드 페일에 걸리면 의미 충실을 1로 제한하고 치명적 실패로 표시한다. 자연스러운 한국어여도 적용된다.

### 1.2 범위·통합 지점
- 제공: 모드별 채점 방법, 5축의 1/3/5 기준, 도메인별 점검, Red Flags, 비즈니스 하드 페일 13개, 연결 사례와 범위 검토 사례.
- 제외: 이력서 확장 점검과 이력서 하드 페일(행 10), 평가셋 형식·검증 스크립트·실행 절차(행 15·16, 부속 제외).
- 외부 의존·선행 계약: S1(모드), S2(보호 항목). 채점 점수 필드 이름은 `scripts/validate_model_baseline.py`의 `SCORE_FIELDS`가 쓴다.
- 소유 상태·부작용: 없음.

### 1.3 인터페이스와 데이터 의미 (S3)
| 연산·데이터 | 입력·출력 / 타입 | 의미·제약 |
|---|---|---|
| 5축 점수 | 정수 1~5 × 5 | `meaning_fidelity`, `korean_naturalness`, `context_fit`, `edit_discipline`, `practical_usefulness`(점수 기록의 필드 이름. 문서의 축 이름은 Meaning Fidelity·Korean Naturalness·Context Fit·Edit Discipline·Practical Usefulness) |
| 축별 기준 | 5 / 3 / 1 | 5는 만족, 3은 약간 부족, 1은 심각. 중간 값은 사이로 쓴다(원문은 5·3·1만 정의) |
| 모드별 채점 기준 표 | 모드 → 의미의 출처, 변경량 판단 | 한국어만: 자연스러운 글을 그대로 둔 것이 높은 점수. 영어+한국어 초안: 사용자가 지목한 버전(없으면 영어)이 의미의 출처. 영어만: 처음부터 한국어로 쓴 글처럼 채점하고 문장 재구성은 예상된 일 |
| Red Flags | 점수 상한 2 | 새 사실·약속·지표·사과·감정 추가 등 |
| 하드 페일 | Meaning Fidelity 상한 1 + 치명 실패 표시 | 13개 항목 |

# 이력서 작업 유형·섹션 역할·맞춤

> 이력서·경력 문서 요청이 어떤 작업인지 분류해 기본 응답을 정하고, 증거 기록 8칸·섹션별 역할·공고 맞춤 절차·출력 패턴을 정하는 지침이다. 기본은 인간화(내용·순서 유지)이고 구성·맞춤은 사용자가 요청할 때만 한다.

## 1부. 동작 설명

### 1.1 한눈에 보는 흐름
1. 입력이 완성된 bullet / 전체 이력서 / 원자료 / 공고+기존 경력 중 무엇인지 분류한다.
2. 요청이 내용·순서 변경을 허용하는지 확인한다. 허용하지 않으면 인간화만 한다(경력 이야기·섹션·순서 유지).
3. 각 경력에서 증거 8칸을 뽑는다(내부 메모, 사용자가 요청하지 않으면 보여 주지 않음).
4. 구조·맞춤이 요청 범위면 섹션별 역할과 맞춤 절차를 적용한다.
5. 출력 패턴대로 응답한다. 붙여넣기 가능한 이력서가 앞, 진단은 뒤.

### 1.2 범위·통합 지점
- 제공: 작업 유형 표, 증거 기록 표, 섹션별 역할, 맞춤 절차, 흔한 실패 표, 출력 패턴 3종, 최종 문서 점검.
- 제외: 재작성 문장 규칙([resume-evidence-rewrite](./resume-evidence-rewrite.md)), 직무별 용어([resume-role-context](./resume-role-context.md)), 지원 동기 글 상세([application-motivation](./application-motivation.md)).
- 외부 의존·선행 계약: 이력서 증거 경계 스펙.
- 소유 상태·부작용: 없음.

### 1.3 인터페이스와 데이터 의미
| 연산·데이터 | 입력·출력 / 타입 | 의미·제약 |
|---|---|---|
| 작업 유형 | 완성된 bullet / 완성된 이력서·경력 문서 / 원자료·회의 메모·할 일 목록 / 공고+기존 경력 | 기본 응답: bullet은 범위·순서·강도를 유지하고 붙여넣기용 bullet 반환(중요한 주장 문제만 설명). 이력서는 경력 이야기 유지, 섹션·경력 순서는 구조 검토 요청 전까지 유지. 원자료는 요청 시에만 구성(확인된 사실 추출, 초안에 영향 주는 증거 공백만 나열). 공고+경력은 요청 시에만 맞춤(검증된 경력을 재배열하고 공고를 복사하거나 일치를 지어내지 않음) |
| 증거 기록 8칸 | 문제·범위 / 판단 / 행동 / 소유 / 상태 / 결과 / 측정 / 공개 | 칸마다 "누락 시 안전한 처리"가 있다: 알려진 일을 유지하고 긴박함·사업 중요성을 만들지 않음, 행동만 쓰고 전략적 소유를 암시하지 않음, 특성만 있으면 행동을 요청, 기본을 단독 소유로 하지 않음, 가장 최근 확인된 상태 유지, 명확한 행동·결정은 결과 없이 서도록 둠, 알려진 조건에 숫자를 붙이거나 근거 없는 해석은 생략, 이름은 일반화하되 기능 범위 유지 |
| 섹션별 역할(구조가 요청 범위일 때) | 요약 / 경력 / 프로젝트·포트폴리오 / 기술·도구 / 학력·자격·활동 / 지원 글 | 요약: 목표 업무를 검증된 경험과 잇는 짧은 소개. 경력: bullet 하나에 요점 하나. 프로젝트: 맥락·개인 기여·중요한 판단·산출물·확인된 반응. 기술: 이름 유지, 사용 방식별 그룹화, 숙련도 추정 금지. 학력·활동: 사실 그대로. 지원 글: 완결 문장 |
| 출력 패턴 | 완성 bullet / 원자료 / 전체 이력서 검토 | 아래 R-08 |

### 1.4 행동 규칙과 남은 질문

|---|---|---|---|
| R-01 | 모든 이력서 작업 | 기본 임무는 제공된 내용·분야·목소리를 보존하면서 AI식 한국어를 제거하는 것이다. 사용자가 요청할 때만 구성하거나 구조를 바꾼다 | 코드 확인 |
| R-02 | 입력 분류 | 위 작업 유형 표대로 기본 응답을 정한다 | 코드 확인 |
| R-03 | 요청이 내용·순서 변경 허용 여부를 정한다 | 국소 표현 수정은 주장을 보존하는 한 bullet 전체를 교체해도 된다. 구조 재작성이 요청되면 완성본을 원문과 비교해 중요한 기여와 결정이 남아 있는지 확인한다 | 코드 확인 |
| R-04 | 각 경력 | 8칸을 뽑되 원문이 뒷받침하는 것만 쓴다. 누락 칸은 표의 안전한 처리를 따른다. 이 표는 사용자가 증거를 보자고 하지 않으면 자동으로 보여 주지 않는다 | 코드 확인 |
| R-05 | 인간화만 요청 | 원래 섹션과 순서를 보존한다. 구성·구조 검토·전체 재작성일 때만 섹션 역할을 적용한다. 전환자는 이미 한 전이 가능한 일을 앞세우되 이전 직무를 다른 이름으로 바꾸거나 새 분야 경험을 암시하지 않는다. 이미지·링크·보고서·프로토타입·테스트 기록은 원본이 개인 기여와 연결해 줄 때만 증거이고 저장소나 파일이 단독 소유를 증명하지 않는다. 출석만으로는 프로젝트 결과가 아니다 | 코드 확인 |
| R-06 | 사용자가 맞춤·재배열·구조 변경을 요청하고 공고를 줌 | 공고의 실제 책임·기대 결정·증거 요구를 뽑고, 각 경력을 직접 증거 / 전이 증거 / 미지원으로 표시하고, 직접 증거를 앞세우고, 사실을 바꾸지 않고 설명할 수 있을 때만 전이 증거를 쓰고, 실제 공백은 키워드나 더 센 직함으로 덮지 않고 보이게 두며, 목표 독자의 판단에 도움이 안 되는 세부를 제거한다. 혼합 직무 공고는 가장 중요한 책임을 중심으로 구성한다 | 코드 확인 |
| R-07 | 흔한 실패 10개(모든 bullet이 도구·업무로 시작, 모든 bullet에 퍼센트 요구, 공고 키워드를 특성으로 반복, `협업`·`소통`·`문제 해결` 단독, 같은 성과가 요약·기술·경력에 반복, 기술 세부가 bullet을 점령, 다른 직무와 비교로 직무 설명, `개선`·`강화`·`고도화` 명사 종결 일색, 명사 종결과 서술 혼용, 분야 전환자) | 표의 더 나은 처리를 따른다(예: 질적 증거가 의미 있으면 유지, 키워드는 증명하는 경험 옆에 한 번) | 코드 확인 |
| R-08 | 응답 | 완성 bullet은 수정본 먼저, 주장이 약해지거나 삭제되거나 증거 안전상 미해결일 때만 짧은 노트. 원자료는 `수정본:` 아래 붙여넣기용 문구와 `확인 필요:` 아래 주장을 실질적으로 바꿀 누락 사실 하나(현재 문구가 정확하고 쓸 수 있으면 `확인 필요`를 쓰지 않음). 전체 이력서 검토는 섹션 이름 아래 `바로 사용:`, `근거 보완:`, `삭제 또는 이동:`을 필요한 만큼만 쓰고 다시 쓴 문서를 검토 노트보다 앞에 둔다 | 코드 확인 |
| R-09 | 최종 확인 | 상단 1/3이 하나의 목표 방향을 전하는가, 처음 두 bullet이 목표 직무의 채용 질문에 답하는가, 모든 주장이 제공 증거에 매핑되는가, 소유·완료 상태가 보이는가, 숫자가 조건을 유지하는가, 섹션마다 새 정보를 더하는가, 성격 주장·공고 키워드에 기대지 않는가, 직무에 중요한 증거를 쓰고 모든 bullet을 지표 틀에 억지로 넣지 않았는가, 훑어볼 만큼 간결하고 면접에서 이야기할 만큼 구체적인가 | 코드 확인 |

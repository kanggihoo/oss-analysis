# 작성·편집과 멈춤 기준

> 의미를 먼저 읽고 한국 독자가 알아챌 문제만 고치되, 이미 자연스러운 글은 손대지 않고, 끝에서 원문과 대조해 빠진 것과 새로 생긴 의미가 없는지 확인하게 하는 지침이다.

## 1부. 동작 설명

### 1.1 한눈에 보는 흐름
1. 의미를 먼저 읽는다: 누가 무엇을 왜 어떤 조건에서 하고 결과가 무엇인가.
2. 한국 독자가 알아챌 것(번역투, 과한 격식, 영어 관용구, 불필요한 대명사, 긴 명사화 문장, 어투 혼용, 번역된 명령형 CTA, AI 반복 문구)을 찾는다. 진단은 [pattern-diagnosis](./pattern-diagnosis.md)를 쓴다.
3. 고칠지는 R-07 조건으로 결정한다. 고칠 이유를 이름 붙일 수 없으면 원문을 둔다.
4. 고치는 범위는 사용자가 가리킨 구절이고, 이미 자연스러우면 그대로 반환한다.
5. 끝에서 원문과 대조해 주장·조건·숫자·플레이스홀더·책임·이유와 사라진 것, 합친 절의 시점을 확인한다.

### 1.2 범위·통합 지점
- 제공: 읽기 순서, 점검 대상, 수정 수락 조건, 범위 제한, 최종 대조.
- 제외: 입력 모드별 작업·충돌 해소([input-mode-and-authority](./input-mode-and-authority.md)), 어투·기본값([situation-defaults-and-questions](./situation-defaults-and-questions.md)), 진단표 내용([pattern-diagnosis](./pattern-diagnosis.md)), 보호 항목([fact-protection](./fact-protection.md)), 출력 모양([response-format](./response-format.md)).
- 외부 의존·선행 계약: 입력 모드 S1, 보호 항목 S2, 진단표.
- 소유 상태·부작용: 없음.

### 1.3 인터페이스와 데이터 의미
| 연산·데이터 | 입력·출력 / 타입 | 의미·제약 |
|---|---|---|
| 수정 수락 조건 | 후보 수정 → 수락/기각 | 범위 안에서 이름 붙일 수 있는 구체적 문제 하나가 있어야 수락: 의미·사실 오류, 깨진 문법, 한국 독자가 알아챌 번역투, 사용자나 맥락이 정한 어투·장르 불일치 |
| 최종 대조 항목 | 결과 ↔ 원문 | 주장, 조건, 숫자, 플레이스홀더, 책임자와 결정 이유, 사라진 것, 합친 절의 사실별 상태·조건·시점 |

### 1.4 행동 규칙과 남은 질문
| ID | 조건·입력 | 반드시 관찰될 결과·사후 상태 | 검증 수준 |
|---|---|---|---|
| R-01 | 모든 작성·편집 | 의미(주체·행동·이유·조건·결과)를 먼저 읽고 나서 한국 독자의 눈에 띌 것을 본다 | 코드 확인 |
| R-02 | 점검 대상 | 번역투와 영어 어순, 채널에 비해 과한 격식, 한국 독자가 쓰지 않는 영어 관용구, 한국어가 생략하는 대명사·주어(`당신`·`그것`·`우리는` — 독자가 누가 행동하는지 알 수 있을 때만 생략하고 행위자가 바뀌면 다시 쓴다), 긴 명사화 문장, 이유 없이 섞인 어투와 브랜드에 안 맞는 어투, 번역된 명령형 CTA, 반복되는 AI식 표현 | 코드 확인 |
| R-03 | 문장 판단 | 문단 안에서 독자와 채널에 맞게 판단한다. 금지어는 없다. 분량 할당을 맞추려고 줄이지 않는다. 더 짧거나 더 캐주얼한 유의어는 수정이 아니다 | 코드 확인 |
| R-04 | 이어지는 산문, 전문 용어 | 문단으로 읽고 인과·대조·순서·지시를 담는 연결어를 유지한다. 독자가 실제로 쓰는 분야 용어(영어·외래어 포함)를 유지하고 필요할 때만 낯선 용어를 설명한다. 문구·리듬 진단에 [pattern-diagnosis](./pattern-diagnosis.md)를 쓴다 | 코드 확인 |
| R-05 | 원문에 행동·결과·이유가 없다 | 주장을 좁게 유지하거나 공백을 표시한다. 작성자의 표현이나 제공된 샘플은 어투의 근거일 뿐 사실의 출처가 아니다 | 코드 확인 |
| R-06 | 범위 | 주변 글은 맥락으로 쓰되 사용자가 물은 구절만 고친다. 제공된 한국어는 더 큰 요청이 없는 한 목소리와 구조를 유지한다. 영어에서 번역할 때는 [input-mode-and-authority](./input-mode-and-authority.md)가 허용하는 대로 문장을 재구성하되 필드·키·목록 항목·의도적 서식은 유지한다. 구조 변경·다른 자료 선택·새 구절 작성은 사용자가 요청할 때만. 도착지의 문장부호·서식을 따른다 | 코드 확인 |
| R-07 | 제공된 한국어를 편집할 때 | 범위 안의 구체적 문제를 이름 붙일 수 있을 때만 수정을 받아들인다: 의미·사실 오류, 깨진 문법, 한국 독자가 알아챌 번역투, 사용자나 맥락이 정한 어투·장르 불일치 | 코드 확인 |
| R-08 | 원래 단어가 거기서 유효하고 평범하며 수정이 유의어 교체·조사 다듬기·"고쳤다는 티"뿐이다 | 원문을 유지한다. 이미 자연스러운 한국어는 바꾸지 않고 그대로 돌려준다 | 코드 확인 |
| R-09 | 결과 확인 | 원문과 대조해 각 주장·조건·숫자·플레이스홀더, 누가 책임지고 왜 결정했는지를 확인하고 사라진 것이 없는지 본다. 절을 합쳤으면 각 사실이 자기 상태·조건·시점 한정어를 유지하는지, 현재 상태가 가능한 미래 변화처럼 읽히지 않는지 본다. 문맥 안에서 읽어 끊긴 문장, 새로 암시된 원인, 작성자 목소리를 납작하게 만든 일반적 표현을 잡는다 | 코드 확인 |

- 불변식: 수정은 R-07의 이름 붙일 수 있는 문제 하나에 대응한다. 대응하는 문제가 없으면 원문을 반환한다(R-08).
- 미결정: 없음.
- 확인 한계: 지침 문장 확인이다. 레포의 개발 점검에서 편집 절제와 문단 흐름이 열린 문제로 남아 있다(`CHANGELOG.md` 0.5.0). 실제 모델이 R-07을 지키는지는 확인하지 않았다.

# 입력 모드 판별·원문 권위 해소

> 사용자가 준 텍스트가 한국어만 / 영어 원문+한국어 초안 / 영어만 중 무엇인지에 따라 에이전트가 맡을 작업과 고칠 범위를 정하고, 영어와 한국어가 상업 조건에서 충돌하면 어느 쪽을 따를지 정하는 지침이다. 공유 계약 S1(입력 모드 어휘)을 소유한다.

## 1부. 동작 설명

### 1.1 한눈에 보는 흐름
1. 사용자 요청에 한국어 텍스트와 영어 텍스트가 어떻게 들어 있는지 본다. 한국어만이면 모드 A, 영어 원문과 한국어 초안이 같이 있으면 모드 B, 영어만 있고 한국어를 요청하면 모드 C다.
2. 모드에 따라 작업이 정해진다. A는 한국어 편집, B는 원문과 대조해 어긋남을 고친 뒤 어색한 한국어를 고침, C는 한국어 어순으로 번역·현지화.
3. B에서 한국어 초안과 영어가 가격·날짜·한도·정책·약속에서 어긋나면, 조용히 한쪽을 고르지 않고 R-04~R-08 순서로 판단한다: 사용자가 정한 쪽이 있으면 따른다 → 한국어가 영어를 명백히 오역했으면 고치고 한 줄로 알린다 → 어느 쪽이 맞는지 불명확하고 상업 조건이 달라지면 질문 하나 또는 해당 절을 미해결로 표시한다.
4. 결과 형식은 [response-format](./response-format.md)이 정한다.

### 1.2 범위·통합 지점
- 제공: 모드 3종의 정의와 모드별 작업·범위, 영어-한국어 충돌 해소 규칙, 한→영 번역의 취급.
- 제외: 모드를 정한 뒤의 작성·편집 방법([edit-and-stop-rule](./edit-and-stop-rule.md)), 어투·기본값([situation-defaults-and-questions](./situation-defaults-and-questions.md)), 보호할 사실 목록([fact-protection](./fact-protection.md)). 한국어와 영어가 섞인 입력이나 한 요청에 여러 모드가 섞인 경우는 원본이 정하지 않았다.
- 외부 의존·선행 계약: 없음. 입력은 호스트가 모델에 주는 요청 텍스트다.
- 소유 상태·부작용: 없음. 대화 안에서만 판단하고 파일을 쓰지 않는다.

### 1.3 인터페이스와 데이터 의미 (S1)
| 연산·데이터 | 입력·출력 / 타입 | 의미·제약 |
|---|---|---|
| 모드 A `Korean only` | 입력: 한국어만. 작업: Edit the Korean | 목소리·구조를 유지하고 어투를 일관되게 둔다. 어투 변경은 사용자가 요청했거나 맥락이 채널·브랜드 불일치를 분명히 보여 줄 때만. 주변 글은 맥락으로 읽되 요청이 가리킨 구절만, 그것도 제대로 동작하지 않는 곳만 고친다 |
| 모드 B `English source with a Korean draft` | 입력: 영어 원문 + 한국어 초안. 작업: 원문과 대조해 어긋남을 고치고 그다음 어색한 한국어를 고침 | 사용자가 원문이라고 지목한 텍스트가 기준이고, 지목이 없으면 영어가 기준. 정확하고 자연스러운 한국어 표현은 유지한다 |
| 모드 C `English only, Korean requested` | 입력: 영어만 + 한국어 요청. 작업: 번역·현지화 | 문장마다 한국어 어순으로 쓴다. 한국어가 더 자연스러우면 문장을 합치거나 나누거나 순서를 바꾸되 모든 사실과 조건을 유지한다. 단어 대 단어 대응이나 기계번역과의 최소 차이를 목표로 삼지 않는다 |
| 평가 fixture의 모드 값 | `korean_edit`, `bilingual_edit`, `english_to_korean` | 각각 모드 A, B, C에 대응한다. 사람이 읽는 모드 이름과 fixture 필드 값이 다른 이름이다 |
| 한→영 번역 | 요청 시에만 | 충실하게 번역하고 이 스킬의 한국어 스타일 지침은 영어에 적용하지 않는다 |

### 1.4 행동 규칙과 남은 질문
| ID | 조건·입력 | 반드시 관찰될 결과·사후 상태 | 검증 수준 |
|---|---|---|---|
| R-01 | 한국어만 입력 | 모드 A로 처리: 목소리·구조 유지, 일관된 어투 유지, 요청 범위 밖 수정 없음. 어투는 사용자 요청이나 명백한 채널·브랜드 불일치가 있을 때만 바꾼다 | 코드 확인 |
| R-02 | 영어 원문 + 한국어 초안 | 모드 B로 처리: 사용자가 지목한 텍스트(없으면 영어)를 기준으로 어긋남을 고치고 어색한 한국어를 고친다. 정확하고 자연스러운 초안 표현은 남긴다 | 코드 확인 |
| R-03 | 영어만 입력 + 한국어 요청 | 모드 C로 처리: 한국어 어순으로 쓰고, 합치기·나누기·순서 변경은 허용하되 사실과 조건은 그대로. 기계번역과의 차이를 줄이는 것은 목표가 아니다 | 코드 확인 |
| R-04 | 한국어 초안과 영어가 가격·날짜·한도·정책·약속에서 다르다 | 조용히 한쪽을 고르지 않는다. R-05~R-07 중 하나로 처리한다 | 코드 확인 |
| R-05 | 사용자가 한 버전을 승인·최신·권위 있는 것으로 지목했다 | 그 버전을 다시 묻지 않고 따른다. 다른 버전이 이를 덮어쓰지 않는다 | 코드 확인 |
| R-06 | 한국어가 영어를 명백히 오역했고(빠진 예외, 약해진 "only" 등) 한국어가 권위 있다는 표시가 없다 | 한국어를 고치고 한 줄로 그 사실을 알린다 | 코드 확인 |
| R-07 | 어느 버전이 우선인지 불명확하고 선택이 상업 조건을 바꾼다 | 초점이 분명한 질문 하나를 하거나, 한국어를 유지하고 그 절을 미해결로 표시한다. 그 절을 검증된 붙여넣기용 문구로 내놓지 않는다 | 코드 확인 |
| R-08 | 한국어에 원화 가격, VAT 문구, 한국 특유의 정책이 있다 | 그것만으로 한국어가 승인됐다고 보지 않는다. 한국 시장에 대한 가정으로 승인이나 현지 정책을 추론하지 않는다 | 코드 확인 |
| R-09 | 한국어를 영어로 번역해 달라는 요청 | 요청받았을 때만 한다. 충실하게 번역하고 이 스킬의 한국어 스타일 지침은 영어에 적용하지 않는다 | 코드 확인 |
| R-10 | 영어와 한국어가 승인 표시 없이 같이 주어지고 요청에 한국어가 현지 정책으로 영어를 덮어쓴다는 단서가 없다 | 영어가 기본 원문이고 한국어를 그것과 대조한다. "어느 쪽이 승인됐는가"를 묻지 않는다. 상업 조건(가격·세금 처리·환불 조건)이 충돌하고 어느 쪽도 승인되지 않았으면 한쪽을 고르지 않고 질문 하나를 하며, 두 값을 모두 대안으로 보여 준다 | 코드 확인 (평가 문서·fixture에 있고 `SKILL.md`에는 이 형태로 없음, 2.1) |

- 불변식: 승인 표시가 없는 상업 조건 충돌을 "검증된 최종 문구"로 내놓지 않는다(R-07, R-10).
- 미결정: 없음. 한국어·영어 혼합 입력이나 여러 모드가 섞인 요청의 처리는 원본이 정하지 않았으므로 이 스펙의 범위 밖이다(1.2).
- 확인 한계: 모든 R-ID는 지침 문장을 읽은 결과다. LLM이 실제로 모드를 맞게 고르는지는 확인하지 않았다. 레포의 2026-11-07 개발 점검에서 "질문을 해야 하는 사례"를 놓친 경우가 있었다(`evals/reports/2026-11-07-business-korean/business-review.md`의 실행 표: `ask_one_question` 충족 0/2, 2/3, 0/2. [eval-procedure-and-records](./eval-procedure-and-records.md) R-10).

Vision Solver와 Math Animator 모듈은 시각적 입력을 통해 수학 문제를 분석하고, Manim 라이브러리를 사용해 고품질의 수학 애니메이션이나 정적 다이어그램을 생성하는 특화된 파이프라인을 제공합니다. 또한 이미지를 대화형 GeoGebra 시각화로 변환하는 vision-to-geometry 시스템도 포함합니다.

## 1. 시스템 개요

이 모듈은 사용자 요청과 선택적 시각 첨부파일을 렌더링된 비디오, 이미지 또는 대화형 코드 산출물로 변환하는 다단계 파이프라인으로 동작합니다. 수학적 정확성과 시각적 명확성을 모두 보장하기 위해 "Plan-Design-Code-Render-Fix" 사이클을 사용합니다.

### 핵심 구성 요소
- **`VisionSolverAgent`**: 수학 문제 이미지 처리, 기하 요소 식별, GeoGebra(GGB) 명령 생성을 담당하는 특화 에이전트입니다 [deeptutor/api/routers/vision_solver.py:13-13]().
- **`MathAnimatorPipeline`**: 특화 에이전트와 렌더링 서비스 사이의 흐름을 관리하는 중앙 오케스트레이터입니다.
- **`ManimRenderService`**: 샌드박스 환경에서 생성된 Python 코드를 실행해 `.mp4` 또는 `.png` 파일을 생성합니다 [deeptutor/agents/math_animator/renderer.py:35-50]().
- **`VisualizeCapability`**: 표준 텍스트 기반 시각화와 Manim 서브프로세스 경로 사이의 라우팅을 처리하는 통합 기능 클래스입니다 [deeptutor/capabilities/visualize.py:50-61]().
- **`VisualizePipeline`**: `AnalysisAgent`, `CodeGeneratorAgent`, `ReviewAgent`를 사용해 차트와 다이어그램 같은 비-Manim 시각화를 생성하는 별도의 파이프라인입니다 [deeptutor/capabilities/visualize.py:97-103]().
- **`ReviewAgent`**: 지연 시간과 토큰 비용을 줄이기 위해 `html` 렌더 타입에 대해서는 LLM 검토를 건너뛰도록 최적화되어 있습니다 [deeptutor/agents/visualize/agents/review_agent.py:38-46]().

## 2. 수학 애니메이션 파이프라인

생성 과정은 개별 단계로 나뉩니다. 이 파이프라인은 최소 지속 시간(12-30초)과 특정 "teaching beats" 같은 교육 기준을 충족하도록 특화된 프롬프트를 사용합니다 [deeptutor/agents/math_animator/prompts/en/code_generator_agent.yaml:29-30]().

### 파이프라인 데이터 흐름
다음 다이어그램은 자연어 요청이 Math Animator 모듈 내부에서 코드 실행으로 전환되는 과정을 보여주며, `VisualizeCapability`와 특화된 Manim 경로의 상호작용을 강조합니다.

**수학 애니메이션 생성 흐름**
```mermaid
graph TD
    UserRequest["User Message + Attachments"] -->|"UnifiedContext"| VizCap["VisualizeCapability.run"]
    VizCap -->|"pipeline.run_analysis"| Analysis["AnalysisAgent.process"]
    
    subgraph "Manim_Subprocess_Path"
        Analysis -->|"_run_manim_path"| ManimPipe["MathAnimatorPipeline"]
        ManimPipe -->|"CodeGeneratorAgent"| CodeGen["Code Generation Stage"]
        CodeGen -->|"initial_code"| RenderService["ManimRenderService.render"]
        RenderService --|"ManimRenderError"| Retry["code_retry Stage"]
        Retry --|"Repair Prompt"| CodeGen
    end
    
    RenderService --|"RenderResult"| Summary["Summary Stage"]
    Summary --> FinalOutput["Final Video/Image + Explanation"]
```

## 3. Vision-to-Geometry Solver

`VisionSolverAgent`는 수학 문제의 정적 이미지와 대화형 GeoGebra 시각화 사이의 다리 역할을 합니다. 이 기능은 실시간 분석을 위해 REST와 WebSocket 엔드포인트 모두를 통해 노출됩니다 [deeptutor/api/routers/vision_solver.py:48-129]().

### Vision 처리 흐름
이 다이어그램은 vision 분석 요청이 GeoGebra 스크립트를 생성하는 책임을 가진 구체적인 코드 엔티티로 어떻게 매핑되는지 보여줍니다.

**Vision Solver 로직 매핑**
```mermaid
graph LR
    WS["WebSocket /vision/solve"] -->|"resolve_image_input"| ImgTool["Vision Tool"]
    ImgTool -->|"VisionSolverAgent.process"| Agent["VisionSolverAgent"]
    Agent -->|"bbox_output"| BBox["Element Detection"]
    BBox -->|"final_ggb_commands"| GGB["GeoGebra Commands"]
    GGB -->|"format_ggb_block"| Script["GGB Script Block"]
```

## 4. 일반 시각화 에이전트

`VisualizeCapability`는 3단계 파이프라인을 통해 데이터 차트, 플로차트, 사용자 정의 SVG 일러스트레이션 같은 비애니메이션 요청을 처리합니다 [deeptutor/capabilities/visualize.py:35-45]().

### 지원되는 렌더 타입
이 파이프라인은 요청에 따라 최적의 `render_type`을 결정합니다 [web/lib/visualize-types.ts:4-9]():
- **`svg`**: 사용자 정의 일러스트레이션이나 자유형 그래픽에 사용됩니다.
- **`chartjs`**: 정량 데이터에 사용됩니다.
- **`mermaid`**: 플로차트와 마인드맵 같은 구조화된 다이어그램에 사용됩니다.
- **`html`**: 복잡한 대화형 시각화에 사용되며, `ReviewAgent`는 성능 최적화를 위해 이 타입에 대해 LLM 검토를 건너뜁니다 [deeptutor/agents/visualize/agents/review_agent.py:38-46]().
- **`manim_video` / `manim_image`**: 특화된 Manim 기반 출력입니다 [web/lib/visualize-types.ts:11-18]().

## 5. Manim 렌더링 및 실행

`ManimRenderService`는 Manim 엔진을 실행하는 데 필요한 로컬 파일 시스템과 서브프로세스를 관리합니다.

### 렌더링 모드
이 서비스는 두 가지 주요 출력 모드를 지원합니다 [deeptutor/agents/math_animator/renderer.py:52-69]():
1.  **비디오 모드**: 전체 `Scene` 서브클래스를 MP4 비디오로 렌더링합니다 [deeptutor/agents/math_animator/renderer.py:71-82]().
2.  **이미지 모드**: 코드 블록이 `### YON_IMAGE_n_START ###` 앵커로 감싸져 있어야 합니다 [deeptutor/agents/math_animator/renderer.py:18-21](). 각 블록은 Manim `-s` 플래그를 사용해 독립적인 정적 프레임으로 렌더링됩니다 [deeptutor/agents/math_animator/renderer.py:84-122]().

### 서브프로세스 상호작용
이 서비스는 `subprocess.Popen`과 reader thread, `asyncio.Queue`를 조합해 실시간 스트리밍 출력을 유지하면서도 `SelectorEventLoop`가 `asyncio` 서브프로세스를 지원하지 않을 수 있는 환경과의 호환성을 보장합니다 [deeptutor/agents/math_animator/renderer.py:155-178]().

## 6. 오류 복구와 코드 수정

`MathAnimatorPipeline`은 환경 문제와 코드 환각을 처리함으로써 견고한 생성 과정을 제공합니다.

### 수정 로직
렌더링 오류가 발생하면 시스템은 `retry_system` 프롬프트를 사용해 복구 사이클을 트리거합니다 [deeptutor/agents/math_animator/prompts/en/code_generator_agent.yaml:61-76]():
- **환경 제약**: 로컬 LaTeX가 없으면 `Tex` 또는 `MathTex`를 피하고, 대신 `Text`나 기하학적 시각화를 사용하도록 생성기에 지시합니다 [deeptutor/agents/math_animator/prompts/en/code_generator_agent.yaml:35-36]().
- **버전 호환성**: `stroke_dash_pattern`(Manim v0.20.1에서 지원되지 않음)이나 `self.save_state()`(`MovingCameraScene`에서 지원되지 않음) 같은 특정 매개변수와 메서드는 명시적으로 금지되며, 수정 과정에서 표적이 됩니다 [deeptutor/agents/math_animator/prompts/en/code_generator_agent.yaml:37-38](), [deeptutor/agents/math_animator/prompts/en/code_generator_agent.yaml:70-72]().
- **카메라 로직**: 오류가 `self.camera.frame`과 관련되어 있으면, 수정 로직은 클래스를 `MovingCameraScene`으로 승격시키거나 카메라 애니메이션을 제거합니다 [deeptutor/agents/math_animator/prompts/en/code_generator_agent.yaml:72-75]().

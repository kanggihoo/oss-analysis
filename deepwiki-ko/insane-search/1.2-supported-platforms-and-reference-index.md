## 플랫폼별 핵심 검색 로직

### X/Twitter: 다중 경로 전략
X/Twitter는 표준 스크래핑에 대해 강하게 보호되어 있습니다(402/403 반환). `insane-search`는 인증이 필요 없는 구조화된 JSON 엔드포인트를 우선 사용하여 이를 우회합니다.

1.  **개별 Tweet**: 시스템은 `cdn.syndication.twimg.com/tweet-result?id={id}&token=a`를 사용합니다. 이는 가장 안정적인 경로이며 전체 텍스트, 참여 수치, 작성자 메타데이터를 제공합니다 [skills/insane-search/references/twitter.md:89-115]().
2.  **타임라인**: Syndication API(`/srv/timeline-profile/screen-name/{handle}`)는 좋아요와 리트윗을 포함해 최근 약 100개의 Tweet을 가져오는 데 사용됩니다 [skills/insane-search/references/twitter.md:13-22]().
3.  **탐색**: 키워드 검색이 요청되면 시스템은 `WebSearch(query="site:x.com {keyword}")`를 통해 Tweet ID를 얻은 뒤, 전체 콘텐츠를 위해 `tweet-result`로 단계 상승합니다 [skills/insane-search/references/twitter.md:116-121]().

**출처:** [skills/insane-search/references/twitter.md:89-121](), [PLATFORMS.md:15-15]()

### Reddit: JSON보다 RSS
2026년 6월 기준, Reddit의 비인증 `.json` 엔드포인트는 WAF에 의해 차단됩니다(403). `insane-search`는 WAF 규칙의 예외로 남아 있는 **Atom/RSS 피드(`.rss`)**로 폴백을 구현합니다 [skills/insane-search/references/json-api.md:8-12]().

*   **엔드포인트 패턴**: `https://www.reddit.com/r/{subreddit}/hot.rss?limit=25`
*   **데이터 절충점**: RSS는 전체 본문 HTML을 제공하지만 `score`(업보트)와 `num_comments`는 제공하지 않습니다. 이러한 필드에 대해서는 시스템이 **Application-Only OAuth**에 대한 참조를 제공합니다 [skills/insane-search/references/json-api.md:28-64]().

**출처:** [skills/insane-search/references/json-api.md:6-64]()

### Naver(한국): 신원 스푸핑 및 URL 변형
Naver는 "Access Denied" 차단을 우회하기 위해 특정 헤더와 URL 구조를 요구합니다.

*   **Naver Blog**: 시스템은 `blog.naver.com` URL을 `m.blog.naver.com`으로 변환하고, `Referer: https://m.naver.com/` 헤더와 함께 iPhone User-Agent를 적용합니다 [skills/insane-search/references/naver.md:7-16]().
*   **Naver Search**: 검색 엔드포인트에 접근하기 전에 먼저 홈페이지를 방문하여 세션 "쿠키 워밍"을 수행하기 위해 `curl_cffi`를 사용합니다 [skills/insane-search/references/naver.md:57-71]().
*   **Finance**: 인증 없이 실시간 주식 시계열 데이터에 접근하기 위해 `api.finance.naver.com/siseJson.naver`에 직접 접근합니다 [skills/insane-search/references/naver.md:43-56]().

**출처:** [skills/insane-search/references/naver.md:1-95]()

## 범용 스케줄러(적응형 단계 상승)

명시적으로 색인되지 않은 모든 플랫폼(예: LinkedIn, Coupang, Medium, 지역 포럼)에 대해 시스템은 `fetch_chain.py` 스케줄러를 사용합니다. 이는 Phase 0 예외와 일치하지 않는 한 모든 URL을 범용 챌린지로 취급하여 **No-Site-Name Rule**을 처리합니다.

### 범용 처리 기능
스케줄러는 사이트의 동작에 따라 다음 기법을 자동으로 적용합니다.
*   **신원 스푸핑**: `curl_cffi`를 통해 TLS 지문(Safari, Chrome, Firefox)을 순환합니다 [PLATFORMS.md:64-64]().
*   **메타데이터 복구**: 전체 본문 콘텐츠가 가려진 경우 `OGP`와 `JSON-LD`를 추출합니다 [PLATFORMS.md:67-67]().
*   **쿠키 브리징**: 성공한 `Phase 3`(Playwright) 세션의 쿠키를 향후 요청을 위해 `Phase 2`(curl_cffi) 풀로 다시 전달합니다 [skills/insane-search/references/playwright.md:65-65]().

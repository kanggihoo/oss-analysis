이 페이지는 `insane-search` 엔진의 unit testing suite를 문서화합니다. 테스트는 가능한 경우 결정적이고 네트워크가 필요 없도록 설계되어, diversity scheduler, response validation, self-learning store 같은 핵심 로직이 live site 동작에 의존하지 않고 지원되는 모든 플랫폼에서 올바르게 동작하도록 보장합니다.

## 테스트 스위트 개요

테스트 스위트는 `skills/insane-search/engine/tests/`에 위치하며 `test_u1.py`부터 `test_u7.py`까지의 명명 규칙을 따릅니다. 이러한 테스트는 multi-AI review에서 나온 수정 사항을 고정하고 WAF 우회 로직의 regression을 방지합니다.

## U1: Scheduler Diversity 및 Validator v2

`test_u1.py` 파일은 fetch grid가 높은 entropy를 유지하고 validator가 복잡한 WAF 응답을 올바르게 분류하는지 보장합니다.

### Grid Diversity 구현
scheduler는 작은 시도 예산 안에서 모든 TLS 계열과 URL 변환을 포괄해야 합니다. `t_scheduler_diversity_under_cap`은 처음 11번의 시도(probe를 제외한 예산)에 다음이 포함되는지 검증합니다.
* **TLS Families:** `safari`, `safari_ios`, `chrome`, `chrome_android`, `edge`. [skills/insane-search/engine/tests/test_u1.py:58-60]()
* **Transforms:** `original` 및 `mobile_subdomain`. [skills/insane-search/engine/tests/test_u1.py:59-61]()

### Validator v2 로직
validator는 정상 페이지가 챌린지처럼 보일 수 있는 edge case를 처리하도록 업데이트되었습니다.
* **Small JSON:** 유효한 JSON 응답은 작더라도 `CHALLENGE`가 아니라 `Verdict.WEAK_OK`로 표시됩니다. [skills/insane-search/engine/tests/test_u1.py:90-95]()
* **Akamai _abck:** 쿠키에 `~-1~`이 포함되어 있으면 미해결 상태입니다. validator는 비최종인 `Verdict.SUSPECT_OK`를 반환하여 grid가 계속 진행되도록 합니다. [skills/insane-search/engine/tests/test_u1.py:98-103]()
* **Soft Marker Overrides:** "captcha" 같은 "soft" 키워드가 나타나더라도 `success_selector`가 일치하면 verdict가 `Verdict.STRONG_OK`로 승격됩니다. [skills/insane-search/engine/tests/test_u1.py:106-110]()

**출처:** [skills/insane-search/engine/tests/test_u1.py:52-62](), [skills/insane-search/engine/validators.py:69-80](), [skills/insane-search/engine/validators.py:120-123]()

## U5: Self-Learning Store(learning.py)

`test_u5.py`는 self-learning store의 영속성 및 퇴출 로직을 검증합니다. store는 성공한 fetch route(impersonate × referer × transform)를 기록하여 동일 호스트를 이후 방문할 때 재발견을 건너뜁니다.

### 학습 상태 머신
테스트 스위트는 `learning.py`에 정의된 strike 기반 퇴출 정책을 실행합니다.

성공한 Fetch가 Learned State로 가는 경로
```mermaid
graph TD
    "Start_Fetch" --> "Lookup_Host"
    "Lookup_Host" -- "Not Found" --> "Run_Full_Grid"
    "Lookup_Host" -- "Found" --> "Promote_Route_to_Probe"
    "Run_Full_Grid" -- "Success" --> "record_success()"
    "record_success()" --> "Update_wins_and_reset_strikes"
    "Update_wins_and_reset_strikes" --> "Save_to_learned.json"
    
    "Promote_Route_to_Probe" -- "Real_Failure" --> "record_failure(penalize=True)"
    "record_failure(penalize=True)" --> "Increment_consecutive_fails"
    "Increment_consecutive_fails" -- "Fails >= 2" --> "Evict_Entry"
    "Increment_consecutive_fails" -- "Fails < 2" --> "Keep_Entry"
```

### 테스트되는 주요 동작
* **LRU Capping:** `MAX_ENTRIES`를 초과하면 least-recently-used 엔트리가 pruning되는지 검증합니다. [skills/insane-search/engine/tests/test_u5.py:109-122]()
* **Failure Classification:** strike를 받는 "real" failures(WAF blocks)와 strike를 받지 않는 "transient" failures(429s, network errors)를 구분합니다. [skills/insane-search/engine/tests/test_u5.py:84-89]()
* **Key Scoping:** 동일 호스트의 `desktop` 및 `mobile` route가 별도로 저장되는지 보장합니다. [skills/insane-search/engine/tests/test_u5.py:126-129]()

**출처:** [skills/insane-search/engine/learning.py:8-16](), [skills/insane-search/engine/learning.py:32-37](), [skills/insane-search/engine/tests/test_u5.py:67-75]()

## U7: SSRF 및 Redirect Guards

`test_u7.py` 파일은 `engine/safety.py`와 `engine/transport.py`의 안전 메커니즘을 다룹니다. 이 테스트는 도구가 내부 인프라를 probe하는 데 사용될 수 없도록 보장합니다.

### Safety 검증 Grid
테스트는 `classify_url`이 다음 패턴을 차단하는지 검증합니다.
* **Loopback:** `127.0.0.1`, `[::1]`, `localhost`. [skills/insane-search/engine/tests/test_u7.py:20-29]()
* **Cloud Metadata:** `169.254.169.254`. [skills/insane-search/engine/tests/test_u7.py:21-21]()
* **Private Ranges:** `10.0.0.0/8`, `192.168.0.0/16`. [skills/insane-search/engine/tests/test_u7.py:22-24]()
* **Invalid Schemes:** `ftp://`, `file://`. [skills/insane-search/engine/tests/test_u7.py:27-28]()

### Redirect 처리
`SessionPool._fetch_following`은 redirect chain의 모든 hop을 검증하는지 확인하기 위해 테스트됩니다. public URL이 internal IP로 redirect하면 chain은 `ssrf_redirect_blocked`로 중단됩니다. [skills/insane-search/engine/tests/test_u7.py:64-71]()

**출처:** [skills/insane-search/engine/tests/test_u7.py:18-34](), [skills/insane-search/engine/tests/test_u7.py:64-72]()

## Smoke 및 Regression Tests

`test_smoke.py`는 `example.com` 같은 무해한 엔드포인트에 접근하여 end-to-end 동작을 검증하는 integration 수준 coverage를 제공합니다.

### 구현 세부사항
* **Body Size Heuristics:** `t_validator_tiny_body_is_challenge`는 `SMALL_BODY_THRESHOLD`(3000 bytes)보다 작은 body를 가진 200 OK 응답이 override되지 않는 한 `CHALLENGE`로 표시되는지 검증합니다. [skills/insane-search/engine/tests/test_smoke.py:29-38]()
* **URL Transform Permutations:** `t_url_transforms`는 `iter_transformed`가 `www`와 apex 도메인 모두에 대해 `m.` 서브도메인을 올바르게 생성하는지 보장합니다. [skills/insane-search/engine/tests/test_smoke.py:82-92]()
* **Trace Integrity:** 모든 `fetch` 결과가 실패 시에도 `Attempt` 객체의 완전한 `trace`를 포함하도록 보장합니다. [skills/insane-search/engine/tests/test_smoke.py:112-119]()

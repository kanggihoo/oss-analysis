이 페이지는 `toolbox/mdcode/demo/` 디렉터리에 제공된 엔드투엔드 데모 스크립트를 문서화합니다. 이 데모들은 `kcmd` 도구를 사용해 서로 다른 Google Cloud 리소스, 특히 BigQuery 데이터셋과 Dataplex 기반 Knowledge Base의 메타데이터를 코드로 관리하는 방법을 보여줍니다.

## 데모 시나리오 개요

데모는 세 가지 주요 워크플로로 분류됩니다.
1.  **BigQuery Dataset**: `StandardLayout`(YAML 기반)을 사용해 구조화된 데이터 자산의 메타데이터를 관리합니다.
2.  **Knowledge Base**: `DocumentsLayout`(Markdown 기반)을 사용해 Dataplex Entry Group 안의 문서형 Entry 집합을 관리합니다.
3.  **OKF Wiki**: [Open Knowledge Format](https://github.com/GoogleCloudPlatform/knowledge-catalog/tree/main/okf) bundle을 Knowledge Catalog로 동기화하는 과정을 보여줍니다.

### 사전 요구 사항 및 구성
모든 데모에는 BigQuery 및 Dataplex API가 활성화된 GCP 프로젝트가 필요합니다 [toolbox/mdcode/demo/README.md:3-9](). 사용자는 `gcloud`를 통해 인증하고 기본 프로젝트와 region을 설정해야 합니다 [toolbox/mdcode/demo/README.md:13-17]().

## BigQuery Dataset 데모

이 시나리오는 BigQuery 리소스 메타데이터(데이터셋 및 테이블)를 로컬 YAML 파일로 동기화하는 과정을 보여줍니다.

### 워크플로 실행
1.  **Setup**: `setup.ts` 스크립트는 `bq` CLI를 사용해 `demo_ecommerce`라는 데이터셋과 public GA4 샘플 데이터로 채워진 `events` 테이블을 생성합니다 [toolbox/mdcode/demo/bq/setup.ts:7-31](). 또한 `bq-dataset` scope를 가진 `catalog.yaml` 매니페스트를 생성합니다 [toolbox/mdcode/demo/bq/setup.ts:36-58]().
2.  **Pull**: `kcmd pull`을 실행하면 메타데이터가 다운로드됩니다. BigQuery scope이므로 각 Entry가 `.yaml` 파일인 `StandardLayout`을 사용합니다 [toolbox/mdcode/demo/README.md:39-42]().
3.  **Update**: `update.ts` 스크립트는 로컬 YAML 파일을 수정하여 `dataplex-types.global.overview` Aspect를 추가하거나 변경합니다 [toolbox/mdcode/demo/bq/update.ts:4-15]().
4.  **Push**: `kcmd push`를 실행하면 로컬 YAML 변경 사항이 Dataplex Knowledge Catalog로 다시 동기화됩니다 [toolbox/mdcode/demo/README.md:59-60]().
5.  **Cleanup**: `cleanup.ts` 스크립트는 BigQuery 스키마를 삭제합니다 [toolbox/mdcode/demo/bq/cleanup.ts:4-15]().

## Knowledge Base 데모

이 시나리오는 Dataplex Entry Group 안에서 "Knowledge Base"(Markdown 문서 컬렉션)를 관리하는 과정을 보여줍니다.

### 기술적 구현
Knowledge Base 데모는 `DocumentsLayout`을 사용합니다. 이 레이아웃에서 로컬 표현은 Markdown 본문이 `overview` Aspect에 매핑되고 메타데이터(title 또는 tag 등)는 YAML frontmatter에 저장되는 `.md` 파일로 구성됩니다.

1.  **Setup**: `setup.ts`는 `demo_kb`라는 Dataplex Entry Group을 생성하고 `gcloud dataplex entries create`를 사용해 여러 Entry(예: `index`, `topic1`, `dir/topic1`)로 채웁니다 [toolbox/mdcode/demo/kb/setup.ts:12-51]().
2.  **Manifest Generation**: `demo_kb` Entry Group을 가리키는 `kb` scope가 포함된 `catalog.yaml`을 생성합니다 [toolbox/mdcode/demo/kb/setup.ts:60-78]().
3.  **Library Usage**: BigQuery 데모와 달리 KB `update.ts` 스크립트는 `kcmd` 라이브러리를 프로그래밍 방식으로 사용하는 방법을 보여줍니다. `CatalogSnapshot.fromPath`를 통해 `CatalogSnapshot`을 초기화하고 [toolbox/mdcode/demo/kb/update.ts:4-4](), `lookupEntry`로 Entry를 조회한 뒤 [toolbox/mdcode/demo/kb/update.ts:6-6](), `updateEntry`를 호출해 `dataplex-types.global.overview` Aspect를 수정합니다 [toolbox/mdcode/demo/kb/update.ts:10-14]().

## OKF Wiki 데모

OKF(Open Knowledge Format) 데모는 표준화된 문서 bundle과 Knowledge Catalog 사이의 통합을 보여줍니다.

### 기능
*   **Documents Layout**: 17개의 Markdown 파일(GA4 샘플)로 이루어진 디렉터리 구조를 `okf_ga4` Entry Group의 Entry로 매핑합니다 [toolbox/mdcode/demo/README.md:123-130]().
*   **Path-to-Entry Mapping**: `references/metrics/event_count.md` 같은 파일 경로는 `references/metrics/event_count` 같은 Entry 이름으로 자동 변환됩니다 [toolbox/mdcode/demo/README.md:145-147]().
*   **Aspect Mapping**: Markdown 본문은 `dataplex-types.global.overview`에 저장되고, frontmatter 필드(`title`, `description`, `tags`)는 특정 Entry 필드 또는 Aspect에 매핑됩니다 [toolbox/mdcode/demo/README.md:127-129]().

### 실행 요약
| Step | Action | Description |
| :--- | :--- | :--- |
| **Setup** | `bun setup.ts` | `okf_ga4` Entry Group과 `catalog.yaml`을 생성합니다 [toolbox/mdcode/demo/README.md:131-141](). |
| **Publish** | `kcmd push` | 로컬 `catalog/` 디렉터리(OKF GA4 bundle로 미리 채워짐)를 클라우드에 동기화합니다 [toolbox/mdcode/demo/README.md:143-153](). |
| **Modify** | `.md` 파일 편집 | 사용자는 파일 시스템에서 Markdown 또는 frontmatter를 직접 편집할 수 있습니다 [toolbox/mdcode/demo/README.md:155-159](). |
| **Cleanup** | `bun cleanup.ts` | Entry Group을 삭제합니다 [toolbox/mdcode/demo/README.md:165-171](). |

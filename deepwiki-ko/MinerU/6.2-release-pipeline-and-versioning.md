MinerU 프로젝트는 버전 관리, 자동화된 테스트, PyPI로의 패키지 배포 및 문서 배포를 관리하기 위해 GitHub Actions 기반의 강력한 CI/CD 인프라를 활용합니다. 이 파이프라인은 모든 릴리스가 여러 Python 환경에서 검증되고 문서가 `master` 및 `dev` 브랜치와 동기화된 상태로 유지되도록 보장합니다.

## 릴리스 워크플로우 오케스트레이션

기본 릴리스 프로세스는 `.github/workflows/python-package.yml`에 정의되어 있습니다. 이 워크플로우는 `*released` 패턴과 일치하는 git 태그가 생성되거나 수동 `workflow_dispatch`를 통해 트리거됩니다 [[.github/workflows/python-package.yml:6-10]](). 이는 `update-version`, `check-install`, `build`, `release`라는 네 가지 순차적 작업(job)으로 구성됩니다.

### 1. 버전 관리 (`update-version`)
이 작업은 내부 Python 패키지 버전을 Git 태그와 동기화합니다. 버전 문자열을 추출하여 코드베이스에 작성하기 위해 특화된 스크립트인 `update_version.py`를 사용합니다.

*   **로직**: `get_version()` 함수는 최신 태그를 찾기 위해 `git describe --tags`를 실행합니다 [[update_version.py:7-9]]().
*   **검증**: `mineru-<version>-released`와 같은 형식을 예상합니다. 유효한 경우, `version_parts[1]`을 사용하여 `<version>` 구성 요소를 추출합니다 [[update_version.py:10-12]]().
*   **주입**: `write_version_to_commons(version)` 함수는 해당 문자열을 `mineru/version.py`에 `__version__` 변수로 작성합니다 [[update_version.py:20-23]]().
*   **지속성**: 워크플로우는 전용 `RELEASE_TOKEN`을 사용하여 이 변경 사항을 `master` 브랜치에 다시 커밋합니다 [[.github/workflows/python-package.yml:38-56]]().

### 2. 설치 검증 (`check-install`)
여러 버전 간의 호환성을 보장하기 위해 파이프라인은 Python 3.10, 3.11, 3.12, 3.13 버전 매트릭스에서 패키지 설치를 시도합니다 [[.github/workflows/python-package.yml:60-63]](). 모든 핵심 의존성이 올바르게 해결되는지 확인하기 위해 `pip install -e .[core]`를 사용하여 개발 모드 설치를 수행합니다 [[.github/workflows/python-package.yml:82-85]]().

### 3. 빌드 및 아티팩트 생성 (`build`)
설치가 검증되면 파이프라인은 배포 파일을 빌드합니다:
*   `build` 및 `wheel` 패키지를 설치합니다 [[.github/workflows/python-package.yml:103-106]]().
*   `.whl` 파일을 생성하기 위해 `python -m build --wheel`을 실행합니다 [[.github/workflows/python-package.yml:108-110]]().
*   최종 릴리스 작업을 위해 결과물인 wheel 파일을 `wheel-file`이라는 이름의 GitHub 아티팩트로 업로드합니다 [[.github/workflows/python-package.yml:112-117]]().

### 4. 배포 (`release`)
마지막 단계는 외부 배포를 처리합니다:
*   **GitHub 릴리스**: `softprops/action-gh-release`를 사용하여 GitHub에서 공식 릴리스를 생성하고 wheel 파일을 첨부합니다 [[.github/workflows/python-package.yml:132-139]]().
*   **PyPI 배포**: `twine`을 사용하여 패키지를 PyPI에 업로드합니다. 업로드 시 PyPI 토큰(`__token__`)을 사용하기 전에 `twine check dist/*`를 수행합니다 [[.github/workflows/python-package.yml:140-144]]().

다음 다이어그램은 Git 태그에서 PyPI 릴리스에 이르는 흐름을 보여줍니다.

## 버전 관리 스크립트 구현

`update_version.py` 스크립트는 Git 메타데이터와 Python 패키지 메타데이터 간의 브리지 역할을 합니다.

**버전 관리 로직 다이어그램**
```mermaid

    "Entry[main]" --> "Call[get_version]"
    "Call[get_version]" --> "Cmd[git_describe_--tags]"
    "Cmd[git_describe_--tags]" --> "Check{ValidTagFormat?}"
    "Check{ValidTagFormat?}" -- "Yes: mineru-3.4.0-released" --> "Extract[3.4.0]"
    "Check{ValidTagFormat?}" -- "No" --> "Fallback[0.0.0]"
    "Extract[3.4.0]" --> "Call2[write_version_to_commons]"
    "Fallback[0.0.0]" --> "Call2[write_version_to_commons]"
    "Call2[write_version_to_commons]" --> "IO[Write_to_mineru/version.py]"
    "IO[Write_to_mineru/version.py]" --> "Var[__version__]"
```

## 문서 배포

문서는 MkDocs를 통해 관리되며 GitHub Pages에 자동으로 배포됩니다. 설정은 `mkdocs.yml`에 저장됩니다 [[mkdocs.yml:1-161]]().

*   **워크플로우**: `Publish docs via GitHub Pages` 워크플로우는 `master` 및 `dev` 브랜치로의 푸시에 의해 트리거됩니다 [[.github/workflows/mkdocs.yml:2-6]]().
*   **소스**: 리포지토리를 체크아웃하고 빌드 소스로 특별히 `dev` 브랜치를 사용합니다 [[.github/workflows/mkdocs.yml:13-16]]().
*   **필수 요구사항**: `/docs/requirements.txt`를 가리키는 환경 설정을 통해 의존성을 설치합니다 [[.github/workflows/mkdocs.yml:22]]().
*   **배포**: `mhausenblas/mkdocs-deploy-gh-pages` 액션이 `RELEASE_TOKEN`을 사용하여 `gh-pages` 브랜치에 빌드 및 푸시를 처리합니다 [[.github/workflows/mkdocs.yml:17-21]]().
*   **기능**: 문서는 `i18n` 플러그인을 통해 다국어(영어 및 중국어)를 지원하며 [[mkdocs.yml:120-132]](), Material 테마를 사용합니다 [[mkdocs.yml:9]]().
*   **에셋**: 사이트 브랜딩을 위해 `docs/images/logo.png` 및 `docs/images/logo.svg`를 사용합니다 [[mkdocs.yml:34-35]](), [[docs/images/logo.svg:1-22]]().
*   **커스터마이징**: `docs/stylesheets/extra.css`에 정의된 사용자 정의 CSS는 Gradio 데모 페이지의 레이아웃을 처리하며, 구체적으로 보조 사이드바를 숨기고 `.mineru-demo-page` 클래스를 가진 요소들의 콘텐츠 너비를 확장합니다 [[docs/stylesheets/extra.css:1-22]](). 이는 Gradio 데모 인덱스 페이지에서 iframe이 올바르게 렌더링되도록 보장하는 데 사용됩니다 [[docs/en/demo/index.md:6-8]](), [[docs/zh/demo/index.md:6-8]]().

**Sources:** [[.github/workflows/mkdocs.yml:1-23]](), [[mkdocs.yml:1-161]](), [[docs/images/logo.svg:1-22]](), [[docs/stylesheets/extra.css:1-41]](), [[docs/en/demo/index.md:1-9]](), [[docs/zh/demo/index.md:1-9]]()

## 기여자 라이선스 동의서 (CLA)

MinerU는 법적 규정 준수를 보장하기 위해 모든 풀 리퀘스트에 대해 CLA 확인을 시행합니다.

*   **워크플로우**: `.github/workflows/cla.yml`은 `issue_comment` (생성됨) 및 `pull_request_target` (열림, 닫힘, 동기화)에 의해 트리거됩니다 [[.github/workflows/cla.yml:1-6]]().
*   **활성화**: 사용자가 "I have read the CLA Document and I hereby sign the CLA" 또는 "recheck"이라는 댓글을 작성하면 확인 프로세스가 실행됩니다 [[.github/workflows/cla.yml:20]]().
*   **저장**: 서명은 전용 `cla` 브랜치의 `signatures/version1/cla.json` 경로에 있는 JSON 파일에 저장됩니다 [[.github/workflows/cla.yml:28-31]]().
*   **허용 목록 (Allowlist)**: 특정 메인테이너(예: `myhloli`, `dt-yy`, `Focusshang`, `renpengli01`, `icecraft`, `drunkpig`, `wangbinDL`, `qiangqiang199`, `GDDGCZ518`, `papayalove`, `conghui`, `quyuan`, `LollipopsAndWine`, `Sidney233`)는 CLA 확인에서 제외됩니다 [[.github/workflows/cla.yml:32]]().
*   **문서**: CLA 문서는 `https://github.com/opendatalab/MinerU/blob/master/MinerU_CLA.md`에서 호스팅됩니다 [[.github/workflows/cla.yml:29]]().

**Sources:** [[.github/workflows/cla.yml:1-44]]()

## 추가 CI/CD 워크플로우

### CLI 통합 테스트
`mineru-cli-test` 워크플로우는 `master` 또는 `dev`로의 모든 푸시 시점에 CLI 기능을 검증합니다 [[.github/workflows/cli.yml:4-9]]().
*   **환경**: 신속한 의존성 관리 및 가상 환경 설정을 위해 `astral-sh/setup-uv`를 사용합니다 [[.github/workflows/cli.yml:28-34]]().
*   **설치**: `uv pip install .[test]`를 사용하여 테스트 추가 패키지(extras)를 포함해 패키지를 설치합니다 [[.github/workflows/cli.yml:36]]().
*   **커버리지**: `coverage run`을 실행하기 전에 메트릭을 재설정하는 `tests/clean_coverage.py`를 실행하고, 보고서를 생성하기 위해 `tests/get_coverage.py`를 실행합니다 [[.github/workflows/cli.yml:37-39]]().

**CLI 테스트 실행 흐름**

    "Clean[tests/clean_coverage.py]" --> "Run[coverage_run]"

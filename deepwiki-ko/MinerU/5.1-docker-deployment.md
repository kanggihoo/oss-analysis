MinerU는 환경 설정을 단순화하고 다양한 하드웨어 아키텍처 전반에서 호환성을 보장하기 위해 포괄적인 Docker 기반 배포 생태계를 제공합니다. 여기에는 표준 NVIDIA GPU, 화웨이 어센드(Ascend) NPU 및 다양한 특수 하드웨어 가속기(MLU, MUSA, GCU, DCU, PPU, MACA, CAMB, COREX, KXPU, NPU)에 대한 지원이 포함됩니다.

## Docker 아키텍처 개요

MinerU Docker 전략은 하드웨어 가속 추론을 즉시 사용할 수 있도록 제공하기 위해 특수 베이스 이미지(주로 `vllm-openai` 또는 하드웨어 벤더 전용 PyTorch 이미지)에 의존합니다. 배포는 모델 다운로드 속도 및 의존성 해결을 최적화하기 위해 지역별 구성(글로벌 vs. 중국)으로 나뉩니다.

### 컨테이너화된 환경에서의 시스템 데이터 흐름

다음 다이어그램은 Docker 환경이 호스트 하드웨어를 MinerU 애플리케이션 레이어와 연결하는 방식을 보여줍니다.

**컨테이너와 하드웨어 매핑**

## 표준 배포 (NVIDIA GPU)

MinerU는 표준 GPU 환경을 위해 주로 모델 소스 및 미러 레지스트리가 다른 두 개의 기본 Dockerfile을 제공합니다.

### 1. 글로벌 vs. 중국 구성
- **글로벌:** 공식 Docker Hub 이미지(`vllm/vllm-openai:v0.21.0`)를 사용하고, `mineru-models-download -s huggingface -m all`을 통해 **HuggingFace**에서 모델을 다운로드합니다 [docker/global/Dockerfile:5-24]().
- **중국:** `docker.m.daocloud.io` 미러를 사용하고, `mineru-models-download -s modelscope -m all`을 통해 **ModelScope**에서 모델을 다운로드합니다 [docker/china/Dockerfile:5-24]().

### 2. 베이스 이미지 선택
기본 베이스 이미지는 `vllm/vllm-openai:v0.21.0`로, Volta, Turing, Ampere, Ada Lovelace, Hopper, Blackwell 아키텍처(7.0 <= Compute Capability <= 12.1)를 지원합니다 [docker/global/Dockerfile:1-6](). CUDA 12.9 호환성을 위해 대안으로 구체적인 `-cu129` 태그가 제공됩니다 [docker/china/Dockerfile:6]().

### 3. Docker Compose를 통한 실행
MinerU는 서로 다른 서비스 컴포넌트를 관리하기 위해 Docker Compose 프로필을 사용합니다. `docker/compose.yaml` 파일은 OpenAI 호환 서버, FastAPI 백엔드, Router 및 Gradio 프론트엔드를 위한 서비스를 정의합니다.

| 프로필 | 서비스 | 진입점 (Entrypoint) | 기본 포트 |
| :--- | :--- | :--- | :--- |
| `openai-server` | `mineru-openai-server` | `mineru-openai-server` | 30000 |
| `api` | `mineru-api` | `mineru-api` | 8000 |
| `router` | `mineru-router` | `mineru-router` | 8002 |
| `gradio` | `mineru-gradio` | `mineru-gradio` | 7860 |

**출처:** [docker/compose.yaml:1-123](), [docs/zh/quick_start/docker_deployment.md:41-97]()

## 특수 하드웨어 배포

MinerU는 특화된 Dockerfile을 통해 다양한 하드웨어 가속기를 지원합니다. 이러한 이미지는 종종 벤더가 제공하는 환경과의 호환성을 보장하기 위해 특정 버전의 `numpy` 및 `opencv-python`을 포함합니다 [docker/china/mlu.Dockerfile:26-28](), [docker/china/gcu.Dockerfile:20-23]().

### 하드웨어별 백엔드
중국 국산 카드는 종종 다중 추론 백엔드(일반적으로 `vllm` 또는 `lmdeploy`)를 지원합니다. 예를 들어 Cambricon MLU 구성은 Dockerfile of의 `BACKEND` 인수를 수정하여 백엔드 간에 전환을 허용하며, 이는 활성화되는 가상 환경과 설치되는 헬퍼 패키지(예: `qwen-vl-utils`)에 영향을 미칩니다 [docker/china/mlu.Dockerfile:4-7](), [docker/china/mlu.Dockerfile:20-32](). 

### 특수 하드웨어 매트릭스
다음 표는 다양한 가속기에 특화된 Docker 구성을 요약한 것입니다:

| 하드웨어 | Dockerfile | 베이스 이미지 예시 | 주요 의존성 |
| :--- | :--- | :--- | :--- |
| **MLU** (Cambricon) | `mlu.Dockerfile` | `lmdeploy_dlinfer/camb:mineru25` | `numpy==1.26.4`, `opencv-python==4.11.0.86` [docker/china/mlu.Dockerfile:26-27]() |
| **NPU** (Ascend) | `npu.Dockerfile` | `ascend/vllm-ascend:v0.11.0` | 모델 다운로드 중 `TORCH_DEVICE_BACKEND_AUTOLOAD=0` 설정 [docker/china/npu.Dockerfile:32]() |
| **MACA** (Metax) | `maca.Dockerfile` | `maca/vllm:maca.ai3.1.0.7...` | `torchvision` 버전 패치 [docker/china/maca.Dockerfile:20-21]() |
| **GCU** (Enflame) | `gcu.Dockerfile` | `gcu:docker_images_topsrider...` | Ubuntu Noble을 위한 사용자 지정 APT 소스 [docker/china/gcu.Dockerfile:6-15]() |
| **PPU** (T-Head) | `ppu.Dockerfile` | `mineru/ppu:ppu-pytorch2.6.0...` | `mineru[core]>=3.4.0`, `numpy==1.26.4` [docker/china/ppu.Dockerfile:21-22]() |
| **MUSA** (MooreThreads) | `musa.Dockerfile` | `vllm-musa-qy2-py310:v0.8.4` | MUSA를 위한 `vision.git` 수동 빌드 [docker/china/musa.Dockerfile:18-20]() |
| **COREX** (Iluvatar) | `corex.Dockerfile` | `corex:4.4.0_torch2.7.1...` | `mineru[core]>=3.4.0` [docker/china/corex.Dockerfile:17]() |

## 빌드 및 런타임 구현

### 구현 로직: 진입점 및 환경
모든 MinerU Dockerfile은 빌드 단계 동안 번들된 로컬 캐시에서 모델이 로드되도록 `MINERU_MODEL_SOURCE=local`을 설정하는 공통 `ENTRYPOINT` 패턴을 공유합니다 [docker/global/Dockerfile:27](), [docker/china/Dockerfile:27]().

### 빌드 타임 모델 통합
시작 대기 시간을 줄이기 위해 `mineru-models-download` 명령을 사용하여 `docker build` 프로세스 중에 모델을 미리 다운로드합니다. 중국 지역 Dockerfile의 경우 `-s modelscope` 플래그를 사용합니다 [docker/china/Dockerfile:24](). MLU와 같은 하드웨어의 경우 백엔드 선택(vllm/lmdeploy)에 따라 다운로드를 실행하기 전에 활성화할 가상 환경이 결정됩니다 [docker/china/mlu.Dockerfile:35-39]().

### 자원 관리
`docker/compose.yaml` 및 표준 `docker run` 명령은 구체적인 자원 제약 조건을 구현합니다:
- **공유 메모리:** 대규모 VLM 텐서 및 IPC 통신을 지원하려면 `--shm-size`를 통해 `32g` 이상으로 설정할 것을 권장합니다 [docs/en/quick_start/docker_deployment.md:31]().
- **Ulimits:** 고부하 추론 중 메모리 할당 실패를 방지하기 위해 `compose.yaml`에 `memlock: -1` 및 `stack: 67108864`가 구성되어 있습니다 [docker/compose.yaml:16-18]().
- **GPU 메모리 사용률:** VRAM 부족 문제를 완화하기 위해 서비스에 `--gpu-memory-utilization` 매개변수를 전달할 수 있습니다(주석에 기본적으로 `0.5`로 지정됨) [docker/compose.yaml:15]().

### 서비스 오케스트레이션
Docker 환경은 종종 CLI 레이어에서 정의된 특수 서버를 시작합니다. 예를 들어 `mineru-router`는 여러 `mineru-api` 업스트림 인스턴스를 집계하거나 `--local-gpus auto`를 사용하여 로컬 워커를 관리할 수 있습니다 [docker/compose.yaml:70-78]().

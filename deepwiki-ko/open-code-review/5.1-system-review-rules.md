**System Review Rules** subsystem은 language-specific 및 path-specific review checklists를 정의하기 위한 유연한 pattern-based mechanism을 제공합니다. file glob patterns를 특정 natural language instructions에 매핑함으로써 OpenCodeReview는 C/C++ 코드의 memory leaks 검사, MyBatis XML mappers의 SQL injection 식별, Kotlin의 null-safety 적용처럼 코드베이스의 서로 다른 부분에 적절한 scrutiny를 LLM이 적용하도록 보장합니다.

## 핵심 로직과 데이터 구조

시스템은 ordered list of patterns와 default fallback rule을 유지하는 `SystemRule` struct를 중심으로 구성됩니다.

### 데이터 모델
- **`SystemRule`**: root configuration object입니다. `DefaultRule` string과 ordered slice of `PathRules`를 포함합니다 [internal/config/rules/system_rules.go:27-30]().
- **`PathRule`**: declaration order를 보존하는 단일 pattern-to-rule entry입니다 [internal/config/rules/system_rules.go:21-24]().
- **`Resolver` Interface**: file path에 대한 review rule을 resolve하기 위한 contract를 정의합니다 [internal/config/rules/system_rules.go:16-18]().

### Ordered Pattern Matching
시스템은 JSON configuration에 정의된 rules의 순서를 보존합니다. 이는 **first match wins**이기 때문에 중요합니다 [internal/config/rules/system_rules.go:127-135](). file path가 여러 patterns와 매칭되면 `path_rule_map`에서 더 앞에 나타나는 rule이 선택됩니다.

### JSON Deserialization
표준 Go JSON unmarshaling은 maps로 unmarshaling할 때 key order를 보장하지 않습니다. 이를 해결하기 위해 `SystemRule`은 custom `UnmarshalJSON` method를 구현합니다 [internal/config/rules/system_rules.go:33-81](). streaming approach의 `json.Decoder`를 사용해 source JSON에 나타난 정확한 순서대로 `path_rule_map` object의 keys를 캡처합니다 [internal/config/rules/system_rules.go:53-79]().

## Pattern Matching 및 Brace Expansion

시스템은 `doublestar` library를 통해 `**`를 사용한 recursive directory matching을 포함한 advanced globbing을 지원합니다. 또한 patterns 내부의 comma-separated lists를 지원하기 위해 custom `expandBraces` 함수를 구현합니다 [internal/config/rules/system_rules.go:154-175]().

- **Recursive Matching**: `**/*.java`는 모든 subdirectory의 Java file과 매칭됩니다 [internal/config/rules/system_rules.json:11]().
- **Brace Expansion**: `**/*.{yaml,yml}` 같은 patterns는 `**/*.yaml`과 `**/*.yml`이라는 두 distinct patterns로 확장됩니다 [internal/config/rules/system_rules.go:151-153]().

**Brace Expansion Logic**
`expandBraces` 함수는 `{`와 `}`의 첫 occurrence를 식별하고, content를 comma로 split한 뒤, 각 option에 prefix와 suffix를 적용해 string list를 생성합니다 [internal/config/rules/system_rules.go:154-175]().

출처: [internal/config/rules/system_rules.go:127-175](), [internal/config/rules/system_rules_test.go:10-41]()

## Rules 로딩

Rules는 embedded defaults 또는 project-specific files에서 로드됩니다. 시스템은 `NewResolver`를 사용해 system defaults로 fallback하기 전에 repository level의 rules를 우선 적용합니다.

| Method | Source | 설명 |
| :--- | :--- | :--- |
| `LoadDefault()` | Embedded Binary | embedded `rulesFS`에서 `system_rules.json`과 관련 docs를 parsing합니다 [internal/config/rules/system_rules.go:87-109](). |
| `NewResolver(repoDir, customPath)` | Filesystem | `<repoDir>/.opencodereview/rule.json`의 project-level rules를 system defaults와 merge합니다 [internal/config/rules/system_rules_test.go:182-237](). |

embedded rules는 `//go:embed` directive를 사용해 정의되며, `rule_docs/`의 mapping JSON과 markdown documentation files를 모두 포함합니다 [internal/config/rules/system_rules.go:83-84]().

출처: [internal/config/rules/system_rules.go:83-109](), [internal/config/rules/system_rules_test.go:206-237]()

## Built-in Review Checklists

기본 `system_rules.json`에는 다양한 languages와 configuration formats를 위한 specialized checklists가 포함되어 있습니다.

### 주요 언어 Rules
- **Java (`**/*.java`)**: logical errors(NPEs, loop conditions), performance(N+1 queries, loops 내 DB), thread safety(race conditions, atomic operations)에 초점을 둡니다 [internal/config/rules/rule_docs/java.md:1-42]().
- **C/C++ (`**/*.{cpp,cc,hpp,c}`)**: memory management(`malloc/free` pairing), RAII principles, buffer overflow protection, smart pointer usage를 대상으로 합니다 [internal/config/rules/rule_docs/c.md:5-50](), [internal/config/rules/rule_docs/cpp.md:10-33]().
- **Kotlin (`**/*.kt`)**: null safety(`!!` 회피), coroutine management, idiomatic collection operations(예: `asSequence`)를 강조합니다 [internal/config/rules/rule_docs/kotlin.md:1-82]().
- **SQL/MyBatis (`**/*{mapper,dao}*.xml`)**: SQL injection risks(`${}` 오용), full table scan risks, JOIN condition logic을 구체적으로 표시합니다 [internal/config/rules/rule_docs/mapper_dao_xml.md:6-34]().

### Configuration Rules
- **Dependency Managers**: 
    - **`pom.xml`**: production environments에서 `SNAPSHOT` versions를 표시합니다 [internal/config/rules/rule_docs/pom_xml.md:1]().
    - **`build.gradle`**: snapshots보다 specific version numbers를 권장합니다 [internal/config/rules/rule_docs/build_gradle.md:1]().
    - **`package.json`**: `latest` 또는 `*` version ranges를 표시합니다 [internal/config/rules/rule_docs/package_json.md:1]().
- **Data Formats**:
    - **JSON/YAML**: key spelling errors와 configuration best practices를 검사합니다 [internal/config/rules/rule_docs/json.md:1](), [internal/config/rules/rule_docs/yaml.md:1]().

## Review Agent에서의 사용

`Agent`는 review process 중 이러한 rules를 활용해 각 파일의 prompt를 보강합니다. agent가 특정 파일에 대한 subtask를 준비할 때 `Resolve(path)`를 호출해 특정 checklist를 가져옵니다. 그런 다음 이 checklist가 LLM context에 주입됩니다.

또한 `FileFilter` struct는 동일한 `expandBraces` 및 `doublestar` logic을 사용해 `rule.json`의 user configuration을 기반으로 파일을 포함하거나 제외할지 결정합니다 [internal/config/rules/system_rules.go:192-232]().

## 2. 판단 패턴 분류

| 패턴 | 설명 | 레포 | 장점 | 단점 |
|---|---|---|---|---|
| **A. 토론형** | 여러 역할 LLM이 토론하고 매니저 LLM이 결론 | TA, CN | 근거가 풍부하고 반대 의견을 강제로 검토 | 호출 15~40회로 비쌈. 숫자 기준 없음. 재현성 낮음 |
| **B. 규칙 프롬프트 + 코드 하향** | 숫자 규칙을 프롬프트에 적고, LLM 1회 호출 후 코드가 매수를 약화 | DSA | 저렴(1회). 규칙이 명시적. 위험한 방향으로만 막음 | 규칙이 A주 개념에 맞춰져 있음 |
| **C. 코드 점수가 LLM을 덮어씀** | 지표 합의 점수가 강하면 코드가 결정, 약하면 LLM | QD | 숫자 기준이 전부 코드에 있어 재현 가능 | LLM 역할이 "해설"로 줄어듦. 중립 구간에서는 여전히 LLM |
| **D. LLM 의견 → 코드 비중** | LLM은 방향과 확신도만, 비중·한도·수량은 코드 | AHF | 판단과 실행이 깔끔하게 분리됨. 테스트 가능 | 입력이 펀더멘털뿐. 메모리 없음 |
| **E. 자유 에이전트 + 실행 게이트** | 에이전트가 자유롭게 조사·판단하고, 코드는 주문 직전에만 막음 | VT, OA | 유연함 | 결정 스키마가 없어 일관성·채점이 어려움 |
| **F. 리서치 Q&A** | 판단이 아니라 조사 답변 | DX | 리서치 루프 참고용 | 매매 결정 없음 |

## 3. 판단 규칙에 숫자가 어디 있는가

| 레포 | 숫자 기준 위치 | 대표 규칙 |
|---|---|---|
| TA | **없음** (감성 프롬프트의 StockTwits 70/30, 90/10 정도) | "충돌은 Hold의 이유가 아니다. 더 강한 쪽에 커밋하라" |
| DSA | 프롬프트 + 코드 상수 | MA5 이격도 5% 초과 시 추격 금지, 정배열 필수, 점수 80/60/40/20 구간 |
| QD | **코드** (프롬프트에는 RSI 30/70 같은 기준이 한 줄도 없음) | 합의 점수 ±20, 확신도 60 미만 + 합의 없음이면 HOLD, 포지션 = 위험예산 1% ÷ 손절거리 |
| AHF | 코드 (비중 공식, 한도) + 프롬프트 (페르소나별 정성 기준) | 종목당 최대 25%, 총노출 1.0, Graham "P/E 15~20 초과 시 정당화 필요" |
| CN | 프롬프트 (깊이별 라운드 수) | 등급 결정용 수치 없음 |
| VT | 프롬프트만 (코드 집행 없음) | Sharpe 0.5, MDD 40% |
| OA | 코드 도구 내부 (로테이션 z-score 등) | 판단 규칙 수치 없음 |
| DX | 스킬 프롬프트 (DCF) | 성장률 상한 15%, 영구성장률 2.5%, 검증 ±30% |

## 4. 출력 형식

| 레포 | 결정 값 | 확신도·점수 | 가격 계획 |
|---|---|---|---|
| TA | 5등급 Buy/Overweight/Hold/Underweight/Sell (+ `REVIEW`) | 없음 | Trader가 진입가·손절가 (절대 가격) |
| CN | 낙관/신중/중립 | confidence 0~1, risk_score 0~1 | 목표가 `None` 고정 |
| AHF | bullish/neutral/bearish | confidence 0~100 → [−1, +1] 신호 | 없음 (비중으로 대체) |
| DSA | buy/hold/sell + action 8종 | 점수 0~100, confidence_level | 1차·2차 매수가, 손절가, 목표가, 비중 X/10 |
| QD | BUY/SELL/HOLD | confidence 0~100 | 진입가·손절가·목표가 (현재가 ±10% 이내), 포지션 % |
| VT | 자유 서술 (swarm PM은 long/short/wait/hedge) | PM 프롬프트의 0~100%뿐 | 서술형 |
| OA | 스키마 없음 (마크다운, 커밋 메시지) | 없음 | 주문 자체 |
| DX | 자유 텍스트 | 없음 | 없음 |

## 5. 실패 처리 (Q4-6)

| 레포 | 파싱·LLM 실패 시 | 평가 |
|---|---|---|
| TA | 자유 텍스트로 재시도 → 실패하면 **`REVIEW` (거래 불가)** | 안전. 가장 참고할 만함 |
| AHF | 해당 페르소나 **기권 (0)**. 데이터 오류는 예외로 올림 | 안전 |
| DSA | 무결성 재시도 1회 | 보통 |
| CN | 중립으로 기본값 주입 (fail-open 중립) | 주의 |
| QD | LLM 실패 시 HOLD 기본값을 "유효한 응답"으로 처리하고, 합의 점수가 방향성이면 LLM 없이 BUY/SELL 가능. 보고서 빌드 예외 시 게이트 없이 통과. AI 진입 필터는 fail-open | **위험**. 피해야 할 패턴 |

## 8. 우리 시스템에 대한 결론 (의견)

**B + C + D 조합**을 권한다.

1. **지표·점수는 코드로 계산한다** (C). 프롬프트에는 계산 결과만 넣는다.
2. **LLM은 방향, 확신도, 근거만 낸다** (D). 출력 스키마를 고정한다.
3. **코드가 위험한 쪽으로만 막는다** (B). 매수 하향만 하고 상향은 하지 않는다.
4. **비중과 한도는 코드가 계산한다** (D). 그다음 사람이 승인한다.
5. **실패하면 `REVIEW`로 처리한다** (TA). 거래하지 않는다. QD의 fail-open은 반드시 피한다.
6. **사후 채점은 TA 방식**으로 한다. N일 뒤 수익률을 채점하고 교훈을 최종 판단 단계에만 넣는다.

토론형(A)은 비용 대비 효과를 검증한 뒤 선택적으로만 쓴다. 예: 확신도가 애매한 종목에만 bull/bear 1라운드.

# [Q3] 6번(실제 소재 검출)은 어떻게 이루어지나

- **상위 개요**: [overview.md](../overview.md)
- **검증 수준**: `assets.py` 전체를 읽었다. 임계값이 실제 영상에서 어떻게 작동하는지는 실행하지 않았다.

## 1. 결론

"소재 검출"은 **재제작할 때 사용자가 원본 파일을 직접 제공해야 하는 부분(실사 영상, 사진, 스크린샷, 화면 녹화)을 찾는 것**이다. 이미지 모델로 다시 만들 수 있는 것(AI·3D·코드 렌더 화면)과 구분한다. 방법은 두 겹이다.

1. **shot 전체 단위**: 2번 행이 정한 라벨에서 곧바로 정한다. `live_action`이면 실사 소재, `screen_capture`면 화면 녹화/스크린샷, `film_footage`면 영화 원본, `static_hold`·`still_motion`이면 이미지 출처(사진·스크린샷이면 실제 소재, AI 이미지·그래픽이면 아님) (`material_summary`) (`코드 확인`).
2. **shot 안에 끼어 있는 조각(embedded)**: 렌더된 레이아웃 안에 붙여 넣은 스크린샷·사진·영상 조각을 픽셀 통계로 찾는다 (`detect_embedded`) (`코드 확인`).

## 2. `detect_embedded`의 판정 순서

호출 위치: `pipeline.py:260`, **모든 shot에서** 그 shot의 샘플 프레임과 OCR 결과로 부른다. 가운데 프레임 1장으로 모양을 찾고, 여러 프레임으로 "움직이는가"를 본다.

| 단계 | 하는 일 | 근거 |
|---|---|---|
| ① 블록 분류 | 16×16 블록마다 밝기 표준편차가 2 미만이면 **평평**(단색), 6 초과이고 밝기 엔트로피가 3.4 초과이면 **사진 질감** | `block_classes`, `_entropy` |
| ② 후보 사각형 | (a) Canny 윤곽에서 화면 3~90%를 차지하고 채움률 0.85 초과인 사각형(카드·창·붙은 스크린샷), (b) 밝고(V>200) 채도 낮은(S<60) 큰 연결영역(웹·앱·문서 패널), (c) 사진 질감 블록의 연결영역. 겹치는 후보는 NMS로 제거 | `_rects`, `_light_panels`, `_photo_regions`, `_nms` |
| ③ 후보마다 특징 계산 | 사진 질감 블록 비율, 밝기·채도, 후보 안의 OCR 문자 수와 **작은 글자**(높이 3% 미만) 수, 샘플 프레임 사이 변화량(안쪽 표준편차 > 4 이고 바깥의 2.5배 초과면 **움직임**) | `detect_embedded` |
| ④ 분류 | 사진 질감 비율 ≥ 0.35이고 글자 면적 < 20%이고 자막 띠(아래쪽 얇은 영역)가 아니면 → **사진/이미지**(움직이면 **영상 조각**). 밝은 패널 안에 작은 글자 6개 이상(또는 15개 이상)이면 → **스크린샷**(움직이면 **화면 녹화**) | 같은 함수 |
| ⑤ 중복 제거 | 더 큰 영역에 70% 이상 포함되는 작은 영역은 버린다 | `_dedupe` |

- **스크린샷·화면 녹화만 `real_material: True`로 확정**하고, 사진/영상 조각은 `None`(진짜인지 AI 이미지인지 **미확정**)으로 둔다. 이유는 주석대로 "VLM이나 사람이 봐야 하기 때문" (`코드 확인`).

## 3. VLM이 있을 때

VLM 답의 `embedded_assets`(`is_real_material`, `kind`, `description`)가 `material_summary`에서 합쳐진다. 이때 두 가지를 구분한다.

- **items**: 프레임 안에 실제로 들어 있는 실제 소재 픽셀. 재제작에 파일 필요.
- **references**: AI·3D로 생성된 그림이 "무엇을 그렸나"(상품, 로고, 인물). 픽셀은 생성물이므로 소재가 아니라 **참조 이미지로 준비할 것**. 실사 shot 안의 영상 조각 등은 참조로도 올리지 않는다.
- 최종 `origin`은 `real / ai_generated / rendered / mixed / third_party / unknown` 중 하나이고, 생성·렌더 기반 위에 실제 소재가 있으면 `mixed`가 된다.

## 4. 한계와 미확인

- 자막 띠를 사진으로 오인하는 문제와 다크 테마 스크린샷 누락은 `eval/RESULTS.md`가 스스로 적은 한계다(문서 근거, `미확인`).
- 임계값(2.0, 6.0, 3.4, 0.35 등)은 평가 세트에 맞춘 값으로 보이지만 조정 근거는 읽지 않았다.

# 프레임 캡처·인코딩 엔진

> 컴파일된 컴포지션 페이지의 URL과 프레임 번호·시각을 받아, Chrome(Puppeteer)으로 페이지를 열고 프레임마다 `window.__hf.seek`로 시각을 맞춘 뒤 BeginFrame, screenshot, drawElement 중 하나로 한 장을 캡처하고, 비디오 요소는 FFmpeg로 미리 뽑은 프레임 이미지를 페이지에 주입해 그린 다음, 캡처한 프레임을 FFmpeg에 파이프나 파일로 넘겨 비디오 스트림을 만드는 엔진이다.

용어: 컴포지션은 영상 한 편 또는 한 장면을 설명하는 HTML 파일이고 바깥 요소에 `data-composition-id`가 있다. 이 문서의 "호출자"는 엔진 함수를 부르는 쪽이고 지금은 producer의 렌더 오케스트레이터(행 5, 아직 안 씀)다. 페이지 안쪽 전역과 seek의 의미는 [runtime-seek.md](./runtime-seek.md)가 소유한다. 이 문서는 그 스펙의 R-ID를 링크만 하고 다시 풀어 쓰지 않는다.

## 1부. 동작 설명

### 1.1 한눈에 보는 흐름 [필수]

대표 입력은 "1920x1080, 30fps, JPEG 프레임, 컴포지션 하나, 비디오 요소 하나"다. 단계 순서는 R-ID가 기준이고 병렬 가능한 부분은 따로 적는다.

1. 호출자가 file server를 띄운다. producer `createFileServer`가 `index.html`을 내줄 때 `<head>` 맨 앞에 `HF_EARLY_STUB`, `RENDER_CAPTURE_MODE_SHIM`, 호출자가 넘긴 `VIRTUAL_TIME_SHIM`을, head 끝에 core 런타임을, `</body>` 앞에 `buildRenderModeScript`와 `HF_BRIDGE_SCRIPT`를 끼운다. 이 스크립트들이 페이지에 `window.__hf.seek`와 `window.__hf.duration`을 만든다(R-01).
2. 호출자가 비디오 요소마다 `extractAllVideoFrames`로 FFmpeg 프레임 이미지를 미리 뽑고, 같은 호출자가 `FrameLookupTable`과 `createVideoFrameInjector`로 "시각 t에 어떤 이미지를 붙일지" 훅을 만든다(R-30~R-39).
3. 호출자가 `createCaptureSession`을 부른다. 엔진이 캡처 모드(beginframe 또는 screenshot)를 정하고 Chrome 인자를 만들어 브라우저를 빌리고 page를 열고 viewport를 맞춘다(R-03~R-08).
4. 호출자가 `initializeSession`을 부른다. 엔진이 `index.html`로 이동하고 `pollHfReady`로 `__hf.seek`와 `__hf.duration > 0`을 기다리고(타임아웃 45초, 10초 후 fast-fail), 서브 컴포지션 timeline·미디어·이미지·폰트를 기다린 뒤 drawElement 또는 투명 배경 설정과 static dedup 준비를 하고 세션을 `isInitialized`로 만든다(R-09~R-14).
5. 호출자가 `getCompositionDuration`으로 길이를 읽고 프레임 수를 정한 뒤, 프레임 N마다 `t = N × den / num`을 계산해 `captureFrameToBuffer(session, N, t)` 또는 `captureFrame`을 부른다. 엔진은 t를 프레임 격자로 내림하고, 페이지에서 `__hf.seek(t)`를 실행하고, 늦은 이미지와 seek 완료를 기다리고, 비디오 프레임 훅을 실행한 뒤 모드별 경로로 JPEG 또는 PNG 버퍼를 돌려준다(R-15~R-27).
6. 호출자가 버퍼를 프레임 순서대로 `StreamingEncoder.writeFrame`에 넣거나(streaming), 파일로 쓴 뒤 `encodeFramesFromDir`를 부른다(R-40~R-47). FFmpeg가 H.264/H.265/VP9/ProRes 스트림을 만든다.
7. 호출자가 `closeCaptureSession`으로 page와 브라우저를 돌려준다(R-53).

프레임 사이 병렬은 session(page) 하나당 직렬 루프를 여러 개 두는 방식이다. 한 session 안에서는 프레임을 한 장씩, 같은 session의 BeginFrame 시각이 단조 증가해야 하므로 frameIndex 오름차순으로 캡처한다(R-29). 워커 분배와 순서 맞춤은 행 5다.

### 1.2 범위·통합 지점 [필수]

- 제공: (a) 캡처 페이지 계약과 그 계약을 만드는 producer 주입 스크립트, (b) Chrome 실행·옵션·샌드박스·시작 실패 진단, (c) 세션 생성·초기화·프레임 캡처 API와 캡처 경로 선택, (d) 비디오 프레임 추출·캐시·주입, (e) streaming·디렉터리 인코더와 인코딩 인자, (f) 캡처 실패 분류와 경고 코드, (g) 엔진 공개 API 표와 설정값 표.
- 제외(이유):
  - 렌더 단계 전체, 워커 병렬 분배, 재시도, 취소, 진행 이벤트, 경고 정책(경고를 보고 렌더를 멈출지)은 행 5다. 엔진은 입력·출력·실패 계약까지만 쓴다. `parallelCoordinator.ts`는 읽지 않았다.
  - HDR(`hdrCapture.ts`, `rgb48le` 입력, HDR 색 변환), 모션 블러(`motionBlur.ts`, `pageMotionBlur.ts`, `captureAccumulatedFrame`), static dedup의 예측·검증 세부(`computeStaticFrameSet`, `verifyStaticFramesSafe` 등)는 개념 한 문단과 위치만 적는다(1.2 끝의 "분리 제안").
  - 오디오 추출·믹싱과 `muxVideoWithAudio`의 오디오 인자는 행 6이다. R-47은 호출 위치만 쓴다.
  - 분산 렌더(`chunkStreamingEncoder.ts`, in-page encode, `renderChunk`)는 행 17이다.
  - drawElement의 세부(`finalizeDrawElementInit`, worker encode, risk frame 계획, PSNR self-verify, `threeDProjection`)는 선택 조건과 실패 경계만 쓰고 내부는 읽지 않았다.
- 외부 의존·선행 계약: 선행 스펙은 [runtime-seek.md](./runtime-seek.md)다. 페이지 쪽 전역 `__renderReady`·`__player.renderSeek`·`__hfWaitForSeekCompletion`의 의미는 그 스펙의 R-05, R-08, R-20~R-23, R-35를 따른다. 호출자가 제공해야 하는 것은 file server 주소, 프레임 시각 계산, 비디오 추출 결과와 훅, 인코더 호출 순서, 경고 정책이다. 외부 프로그램은 Chrome(chrome-headless-shell), FFmpeg, ffprobe다.
- 소유 상태·부작용: 엔진은 `CaptureSession`(browser lease, page, 캡처 모드, BeginFrame 시계, 경고 목록, static dedup 버퍼)을 소유한다. 디스크에는 `outputDir`의 `frame_NNNNNN.{jpg,png}`, 실패 때의 `outputDir/diagnostics/frame-error-N.*`, 비디오 추출 디렉터리, 추출 캐시(`<tmpdir>/hyperframes-extract-cache-<uid>` 기본)를 만든다. 프로세스로는 Chrome과 FFmpeg 자식 프로세스가 있다. 페이지에는 `<img class="__render_frame__">`를 `<video>` 바로 뒤에 넣고 `<video>`를 `visibility: hidden !important`로 숨긴다.
- 분리 제안: 이 행은 R-ID가 50개를 넘는다. 읽기 순서상 (1) 캡처 경로·drawElement 게이트·static dedup·모션 블러·HDR, (2) 비디오 추출·캐시·주입, (3) 인코더·인자는 따로 써도 서로 의존이 약하다. 이 스펙은 1, 2, 3의 핵심 경로를 모두 담았고 1의 drawElement 내부·static dedup 세부·모션 블러·HDR은 위치만 적었다.

### 1.3 인터페이스와 데이터 의미 [필수]

#### 1.3.1 엔진이 캡처 페이지에 기대하는 계약

| 이름 | 누가 만드나 | 엔진이 읽는 방식·의미 |
|---|---|---|
| `window.__hf.seek(t, options)` | producer `HF_BRIDGE_SCRIPT`(R-01). 런타임 코드는 만들지 않는다(runtime-seek 1.3.1) | 프레임마다 `page.evaluate`로 부른다. 함수가 아니면 호출을 건너뛴다. `options`는 `HfSeekOptions`(`suppressEvents`, `subFrameDivisions`)를 그대로 넘긴다 |
| `window.__hf.duration` | `HF_BRIDGE_SCRIPT`의 getter | 초 단위 숫자. `pollHfReady`는 0보다 클 때만 준비된 것으로 본다. `getCompositionDuration`은 `?? 0`으로 읽는다 |
| `window.__hfStartupError` | core 런타임(runtime-seek R-35) | 문자열이면 `pollHfReady`가 그 문자열로 즉시 `Error`를 던진다 |
| `window.__hfFlushSync` | `HF_EARLY_STUB` | 있으면 `page.goto` 직후 한 번 부른다. GSAP tween 큐를 rAF 없이 비운다 |
| `window.__hfWaitForSeekCompletion` | core 런타임(runtime-seek R-22) | 프레임마다 인자 없이 `await`한다. 인자 `timeoutMs`가 없으므로 페이지 쪽 상한은 없다(R-18) |
| `window.__hfReseekGpu(t)` | core 런타임 어댑터 | 비디오 프레임을 주입한 직후 있으면 부른다(R-37) |
| `window.__hf.colorGrading.waitForActiveLuts` | core 런타임(행 12) | 프레임마다 있으면 `await`한다(R-16) |
| `window.__timelines`, `[data-composition-id]`, `data-no-timeline` | 컴포지션 작성자 | 서브 컴포지션 timeline 대기가 읽는다(R-12). `data-no-timeline`이 붙은 호스트는 대기에서 뺀다 |
| `video[data-start]`, `window.__hfMediaId`, `window.__hfMediaEl` | 컴포지션과 런타임 | 비디오 주입이 `<video>`를 찾는 열쇠다(R-38) |
| `window.__HF_VIRTUAL_TIME__.seekToTime(ms)` | `VIRTUAL_TIME_SHIM` | `__hf.seek`가 부른다. 엔진이 직접 부르지 않는다(R-28) |
| `window.__hfVariables` | 엔진 | `CaptureOptions.variables`가 있으면 `evaluateOnNewDocument`로 JSON 문자열을 파싱해 넣는다(R-01) |
| `window.__hf_page_composite_pending` 외 `__hf_page_composite_prepare·resolve` | 셰이더 전환 라이브러리 | seek 반환 뒤 pending이면 beginframe·drawelement가 아닌 모드에서만 3단계 합성을 한다. 내부는 제외 |

#### 1.3.2 엔진 공개 API (오케스트레이터가 부르는 것)

모든 이름은 `@hyperframes/engine`(`packages/engine/src/index.ts`)의 export이고, producer의 `frameCapture.ts`, `browserManager.ts`, `chunkEncoder.ts`는 같은 이름을 다시 export만 한다(R-02 근거 2.1). 오류 규약은 `index.ts` 머리 주석이 정한다. 캡처·브라우저 함수는 던지고(throw), FFmpeg 래퍼는 `{ success, error? }`를 돌려주고, 정리 함수는 던지지 않는다.

| 연산 | 입력 → 출력 | 의미·제약·실패 |
|---|---|---|
| `createCaptureSession(serverUrl, outputDir, options, onBeforeCapture?, config?)` | URL, 디렉터리, `CaptureOptions`, 훅, `Partial<EngineConfig>` → `CaptureSession` | `outputDir`을 `recursive`로 만들고 브라우저를 빌리고 빈 page를 만든다. 아직 이동하지 않고 `isInitialized`는 false다. 브라우저를 못 찾거나 시작하지 못하면 throw. 생성 중 실패하면 page와 브라우저를 닫고 다시 던진다(R-01) |
| `initializeSession(session)` | 세션 → void | R-09~R-14. 이동 실패·ready 실패·`VfxFailureError`·`VariablesInvalidError`(strictVariables)·WebGPU 필요한데 불가(`WebGpuUnavailableError`)는 던진다. 경고는 `session.warnings`에 쌓고 계속하지만, `CaptureOptions.onSubTimelineScriptFailure` 훅이 있으면 script 실패 경고 직후 그 훅이 던져 init을 중단시킬 수 있다(R-12) |
| `getCompositionDuration(session)` | 세션 → 초 | 초기화 전이면 throw. `__hf.duration ?? 0`이다. 호출자가 `data-duration` 클램프 값을 따로 쓸 수 있도록 `CaptureOptions.compositionDurationSeconds`가 있다 |
| `getCompositionLengthSource(session)` | 세션 → 길이 출처 또는 null | `__hf.lengthSource`(runtime-seek R-29) |
| `captureFrame(session, frameIndex, time)` | → `{ frameIndex, time(양자화), path, captureTimeMs }` | `outputDir/frame_%06d.{jpg,png}`에 쓴다. 확장자는 캡처 형식으로 정한다(R-25). 실패하면 던진다 |
| `captureFrameToBuffer(session, frameIndex, time)` | → `{ buffer, captureTimeMs }` | 같은 경로를 메모리로 돌려준다. drawelement 모드에서는 프레임당 15초 deadline(R-23) |
| `captureFrameToBufferPipelined`, `captureFramesBatchPipelined`, `recaptureDrawElementFrameForVerify`, `completeDeferredDrawElementInit`, `discardWarmupCapture` | | drawElement worker-encode 경로. 이 스펙은 이름만 적는다 |
| `prepareCaptureSessionForReuse(session, outputDir, hook)` | | 세션을 다른 렌더 단계가 이어 쓰게 한다. `outputDir`, 훅, 성능 카운터, 마지막 프레임 버퍼를 초기화한다. armed된 `staticFrames`는 유지한다 |
| `closeCaptureSession(session)` | → void | 던지지 않는다. 여러 번 불러도 안전하다(R-53) |
| `getCapturePerfSummary(session)` | → `CapturePerfSummary` | 프레임 수, 평균·p50·p95·p99, 경고, dedup 통계 등 |
| `probeBeginFrameLiveness(page, timeoutMs, frameTimeTicks?, intervalMs?)` | → boolean | 초기화된 BeginFrame 세션에서 출력 없는 `beginFrame` 하나를 timeout과 경주시킨다. 시간 초과나 프로토콜 오류는 false이고 호출자는 false이면 screenshot 캡처로 다시 한다. 시각은 warmup과 첫 캡처 사이(`beginFrameTimeTicks − 5×간격`, `deriveBeginFrameProbeTimeTicks`)에 놓아야 단조 증가가 유지된다 |
| `extractAllVideoFrames(videos, baseDir, options, signal?, config?, compiledDir?)` | → `ExtractionResult { success, extracted[], errors[], totalFramesExtracted, durationMs, phaseBreakdown }` | 소스별 실패는 던지지 않고 `errors`에 담는다(R-35) |
| `createFrameLookupTable(videos, extracted, fps?)` → `createVideoFrameInjector(table, config?)` | → `FrameLookupTable`, `BeforeCaptureHook` 또는 null | `createFrameLookupTable`은 항상 table을 돌려주고, `createVideoFrameInjector`는 호출자가 table에 null을 넘길 때만 null을 돌려준다(R-36, R-37) |
| `spawnStreamingEncoder(outputPath, options, signal?, config?)` | → `StreamingEncoder { writeFrame, close, getExitStatus, getExitError, getExitFailureReason }` | FFmpeg를 시작한 뒤 resolve한다. FFmpeg 실패는 던지지 않고 `writeFrame`이 false를, `close`가 `success: false`를 돌려준다(R-41) |
| `createFrameReorderBuffer(start, end)` | → `waitForFrame`, `advanceTo`, `waitForAllDone`, `abort` | 병렬 워커가 순서대로 `writeFrame`하게 하는 장벽(R-41) |
| `encodeFramesFromDir(framesDir, framePattern, outputPath, options, signal?, config?, onFramesEncoded?)` | → `EncodeResult` | 디렉터리 프레임을 한 번에 인코딩(R-45) |
| `encodeFramesChunkedConcat(…, chunkSizeFrames, …)` | → `EncodeResult` | 청크별 인코딩 뒤 concat copy(R-45) |
| `getEncoderPreset(quality, format, hdr?, proresProfile?, chromaSubsampling?)`, `ENCODER_PRESETS` | → `{ preset, quality, codec, pixelFormat, hdr? }` | R-42 |
| `muxVideoWithAudio`, `applyFaststart`, `packageHls` | | 오디오 합성·후처리(R-47, 행 6·5) |
| `classifyCaptureFailure(error, { signal?, workerDiagnostics?, pageErrorLines? })`, `isFatalCaptureFailure`, `isTransientBrowserError` | → `CaptureFailure`(`kind`) | R-48 |
| `resolveConfig(overrides?)`, `DEFAULT_CONFIG` | → `EngineConfig` | 1.3.3 |

`CaptureOptions`의 필수는 `width`, `height`, `fps`(`{num, den}` 유리수)이다. 나머지는 모두 선택이고 이 스펙에서 의미가 있는 것은 `format`(기본 jpeg), `quality`(기본 80), `transparent`, `deviceScaleFactor`(기본 1), `captureBeyondViewport`, `videoMetadataHints`, `skipReadinessVideoIds`, `variables`, `strictVariables`, `compositionDurationSeconds`, `requiresWebGpu`, `lockWarmupTicks`다. 모션 블러·dedup·drawElement·분산 관련 필드는 제외다.

CSS 효과 스캔용 임시 세션(`cssEffectRiskFrames`)도 `enableBrowserPool: false`다. `ready`인데 `browser.connected`가 false이면 그 entry를 강제 close하고 새로 띄운다. entry가 `closing`이면 새 entry(새 세대)를 만들어 `available`을 교체한다. `pooled`가 false이거나 키가 없으면 새 entry를 만들고 `refCount`는 1이며 `pooled`일 때만 `available`에 등록한다. 지문이 다르면(예: 창 크기가 다른 `args`) 다른 브라우저다. (c) `launch` 실패는 entry를 `available`·`entries`에서 지우고 throw하며, launch 중 close가 요청됐거나(`closeRequested`) launch가 끝났을 때 `ready`가 아니면 `Browser pool drained during acquisition`으로 throw하고 `refCount`를 되돌린다. (d) `lease.release()`는 한 번만 유효하다(두 번째는 no-op). `refCount`가 0이 되면 `requestClose(false)`로 정상 `browser.close()`를 하고 `release`는 그 close가 끝날 때까지 기다린다. `forceRelease()`는 `refCount`가 0이 될 때 강제 종료(`forceCloseBrowserProcess`)를 요청하고 이미 닫는 중이면 그 close를 강제로 올린다. 마지막 lease가 닫히면 브라우저도 닫히므로 풀은 동시에 쓰는 lease 사이에서만 재사용하고 유휴 브라우저를 남기지 않는다. (e) `releaseBrowser(browser)`는 그 브라우저의 lease가 정확히 하나일 때만 그 lease를 release하고 둘 이상이면 throw한다(`forceReleaseBrowser`는 둘 이상이면 아무것도 안 한다). lease가 없는 브라우저는 그냥 `browser.close()`한다. (f) `drain()`은 모든 entry에 `requestClose(false)`를 걸고 `DRAIN_FORCE_CLOSE_MS`(1000ms)까지 기다린 뒤 아직 남은 entry를 강제 close로 올린다. 진행 중 drain이 있으면 같은 promise를 돌려준다. `drainBrowserPool`은 `drain`, `closeBrowserPool`은 `closed = true`를 먼저 세워 이후 `acquire`를 막은 `drain`이다. 호출부는 producer 서버 종료(`drainBrowserPool`)와 studio 서버 종료(`closeBrowserPool`)다. 동시 lease 상한은 코드에 없다. `closeCaptureSession`의 `release`는 lease 단위이고 한 lease를 두 번 돌려주지 않는다 | 코드 확인 |

| R-55 | 세그먼트 분할 추출, 상위집합(superset) 추출, 변환 키, tail probe | (a) 분할: `sampleAtOutputFps`(`finalFrameOnly`가 아님)이고 `frameRanges`가 있거나 `totalFrames > 0`이면 `runSegmentedExtraction`을 쓴다. `totalFrames`는 CFR이면 `min(창 프레임 수, 소스 끝 전 프레임 수)`, VFR이면 창 프레임 수이고 `segmentFrames = round(120 × fps)`다. `splitFrameRanges`는 각 range를 `min(range.frames, totalFrames − range.firstFrame)`로 자르고 `segmentFrames`씩 나눈다(`totalFrames`가 0이면 상한 없음). 세그먼트 k의 seek는 `startTime + firstFrame/fps`이고 ffmpeg 인자는 `<hwaccel> <decode 인자> -noaccurate_seek -ss <ffmpegSeek(seek)> -i <src> -t <(frames+1)/fps> -frames:v <frames> -start_number <firstFrame+1> -vf <필터(seek)> <인코딩 인자>`다. 한 프레임 더 읽고 자기 프레임만 남기며 파일 이름은 `frame_%05d`의 1 기준 번호라 세그먼트끼리 이름이 겹치지 않는다. (b) 실행: 세그먼트를 `min(세그먼트 수, usableCpuCount()/2)`개 워커가 순서대로 가져가고 각 `runFfmpeg`는 프로세스 전체 공유 동시성 제한(`inExtractionSlot`, 같은 한도)을 거치므로 소스가 여러 개여도 ffmpeg는 그 한도까지만 돈다. 시간 상한은 `ffmpegProcessTimeout + ceil(lead-in초 × 소스fps × 1000 / 30)`이고 lead-in은 `keyframeGapSeconds`(seek 직전 keyframe까지 거리, ffprobe)다. 세그먼트 하나가 실패하면 나머지를 abort하고 결과는 abort가 아닌 첫 실패, 없으면 abort인 실패를 돌려준다. 취소로 일부가 실행되지 않았으면 abort 실패를 돌려주고 모두 성공이면 마지막 결과를 돌려준다. 한 프레임도 안 나오면 `zero_output`이다. (c) 소스의 모든 슬롯 계산(`extractionFrameCountForDuration`)은 길이와 fps를 BigInt 유리수로 놓고 CFR은 `1e-4`프레임(`SLOT_EDGE_TOLERANCE_BELOW_EXPORT_SNAP_FRAMES`) 아래 경계까지 한 슬롯으로 봐서 올림하고, VFR은 단순 올림, 최소 1이다. (d) 소스 프레임 격자 스냅(`undoTickRoundingOnTheSourceFrameGrid`): 프레임 시각을 `lead + round((PTS×TB + seek − lead) × FR) / FR − seek`로 바꿔 모든 프로세스가 같은 격자(`lead`는 스트림 시작 오프셋 `videoStartOnMediaTimeline`)를 쓰게 한다. 소스 fps가 0이면 `FR`이 NaN이라 `setpts`가 `PTS`를 그대로 두고, 소스 fps가 양수이면 끝에 한 틱짜리 마지막 프레임을 지키려 `tpad=stop_mode=clone:stop=1`을 앞에 둔다. (e) 변환 키: `toneMapHdrToSdr`이고 HDR 소스이면 키는 zscale이 있거나 macOS가 아니면 `hdr2sdr-hable-srgb`, macOS에서 zscale이 없으면 `hdr2sdr-videotoolbox-hdr`(렌더당 한 번 stderr 경고)다. macOS HDR 소스가 톤매핑되지 않으면 필터 앞에 `format=nv12`를 두고 HDR 그대로 Chrome에 넘긴다. SDR→HDR는 `sdr2hdr-<transfer>`이고 필터는 `colorspace=all=bt2020:iall=bt709:range=tv`다. 캐시 키의 변환 부분은 `[sdr2hdr, hdr2sdr, final-frame, shown-<ceil w>x<ceil h>]` 중 있는 것을 `+`로 잇는다. SDR 소스(또는 톤매핑된 소스)는 `sdrCanvasColourFilters`(행렬이 unknown이면 높이 720 이상이고 vp9·av1이 아니면 bt709, 아니면 smpte170m으로 태그한 뒤 `setparams=color_primaries=bt709:color_trc=iec61966-2-1`)를 거치고 JPEG이면 `shownBox` 반분 스케일과 BT.601 full range 필터가 더 붙는다. (f) 상위집합: 캐시 miss만 대상이다. 키(`videoPath`, fps, 형식, sdr→hdr, hdr→sdr 키, `final`/`range`)가 같은 miss를 모아 `mediaStart` 순으로 정렬하고 앞 창의 끝보다 `1e-9` 넘게 뒤에서 시작하면 끊어 겹침 묶음을 만든다. 묶음은 2개 이상이고 `finalFrameOnly`가 없고 VFR이 없고 모든 `mediaStart` 차가 fps의 정수 프레임(`1e-4` 허용)이고 합집합 길이가 길이 합 이하일 때만 상위집합이 된다. 조건이 안 맞으면 직접 추출한다. 합집합은 `baseStart = 최소 mediaStart`부터 한 번 추출하고(캐시 루트 아래 임시 폴더, 하드링크가 되도록 같은 파일시스템) 멤버 i는 상위집합 프레임 `offsetFrames_i + k`를 `frame_%05d`로 hardlink(실패하면 복사)해 `min(요청 프레임 수, 가용 프레임 수)`개를 만들며 개수가 다르면 throw한다. 상위집합 추출이 실패하면 취소가 아닌 한 멤버를 각각 직접 추출로 폴백하고 취소이면 멤버마다 취소 오류를 담는다. 중복 제거 키는 `videoPath, extractionMediaStart, videoDuration, fpsKey, format, sdr→hdr, hdr→sdr, final/range`라 같은 키의 요소는 한 번만 추출하고 결과를 나눈다. (g) `deferRangeExtraction`: CFR이고 `finalFrameOnly`가 아니고 변환이 없는 창이 1초(`ceil(fps)` 프레임) 넘으면 추출을 미루고 정확한 `totalFrames`와 `deferredRange`(`startTime`, `durationSeconds`, `format`)만 돌려준다. 창 끝이 소스 끝보다 1초 이상 안쪽이면 기대 프레임 수를 쓴다. 끝에 닿으면 저장된 마지막 프레임 시각으로 `tailFramesFromFinalFrame`이 마지막 `ceil(fps)` 슬롯 중 프레임이 있는 수를 계산한다(소스 fps가 정확한 정수나 1000/1001 형이 아니거나, 늦게 시작하는 스트림의 마지막 패킷이 한 프레임 길이가 아니거나, 슬롯 경계 거리가 `5e-5`~`5e-4` 슬롯이면 null). null이면 tail probe로 마지막 프레임 구간만 `frameRanges`로 추출해(원격 URL이면 `tailProbe`로 `HF_TAIL_PROBE_SLOTS`(기본 16) 한도를 쓴다) 센다. 전체가 기대치의 60% 이하이거나 probe가 실패하면 미루지 않고 일반 추출로 간다. 미룬 소스는 이 호출에서 캐시를 조회하지 않는다 | 코드 확인(`hdrToSdrToneMapFilter` 내용과 `keyframeGapSeconds`의 ffprobe 호출 외 세부는 미확인) |

## 2부. 근거

### 2.1 요구사항별 근거 feature map [필수]

검증은 repo@`5979991` 기준이다. 아래 검색은 모두 Grep(ripgrep)이고 테스트(`*.test.ts`)·`dist`·`node_modules`는 뺐다.

문서와 구현의 차이: (1) `docs/concepts/determinism.mdx:60-64`는 캡처를 BeginFrame으로 설명하면서(Capture 단계) 64줄에서 screenshot 캡처의 결정성(raster tile 전체 재그림)도 따로 설명한다. 구현의 기본 경로는 호출 경로에 따라 갈린다. programmatic `resolveConfig()`와 CLI Docker는 screenshot이고 로컬 Linux CLI(`auto` + `forceScreenshot: false` override)는 BeginFrame이라, 문서의 BeginFrame 서술은 오히려 로컬 Linux CLI 경로와 맞는다(R-03, R-04). (2) 문서는 페이지 계약을 `seekFrame(frame)`이라 쓰지만 엔진 코드에는 그 이름이 없고 계약은 `__hf.seek(t, options)`다(R-17, 검색: engine `src`의 `seekFrame`).

# 런타임·타임라인 seek

> 컴포지션 HTML이 로드된 브라우저 페이지 안에서, `window.__timelines`·clip 창(clipWindow)·미디어 clock을 시각 t로 맞추고(seek), 부모(Studio·플레이어·렌더러)가 보내는 `postMessage` control을 받아 재생 상태·timeline·ready 신호를 돌려주는 런타임이다. 프리뷰 재생과 렌더 캡처가 같은 런타임 코드를 쓴다.

## 1부. 동작 설명

### 1.1 한눈에 보는 흐름 [필수]

이 절은 페이지 하나가 뜨고 seek 한 번이 끝나기까지의 대표 흐름이다. 렌더와 프리뷰가 갈라지는 지점은 1.3.4에서 따로 다룬다.

1. 런타임 IIFE(`entry.ts`를 빌드한 스크립트)가 `<head>`에서 컴포지션 스크립트보다 먼저 평가된다. 이 시점에 `window.__timelines = {}`, `window.__hyperframes` helper, "첫 가시성 판정 전까지 timed clip 숨김" CSS가 준비된다(R-01). 렌더에서는 producer의 파일 서버가 이 IIFE와 렌더 전용 스크립트를 페이지에 끼운다(R-23).
2. `DOMContentLoaded`가 오면 `entry.ts`가 `after-fonts` 타입 스크립트(컴파일러가 작성자 컴포지션 스크립트의 type을 바꿔 둔 것)를 찾는다. 있으면 폰트를 최대 5초 기다리고, 그 스크립트들을 제자리에서 다시 만들어 실행하고, 그 뒤에 `initSandboxRuntimeModular()`를 한 번 호출한다. 없으면 바로 호출한다(R-02). 그래서 컴파일된 페이지에서는 `__timelines` 등록이 init보다 먼저 끝난다.
3. init이 fps를 정하고(R-03), `__timelines`를 정규화하고(R-04), `TransportClock`을 만들고, 서브 컴포지션 호스트 마운트를 시작하고(R-10), `window.__player`와 `window.__playerReady`를 설치한다(R-05). 이어서 어댑터 13개를 만들어 `discover`를 부른다(R-09).
4. 호스트 마운트·어댑터 준비·`window.__hf.buildReady` promise가 모두 끝나면 루트 timeline을 바인딩하고(R-06, R-07) `window.__renderReady = true`를 세운 뒤 첫 `timeline`·`state` 메시지를 보낸다(R-08, R-16, R-17). `assets-ready`는 그 뒤 한 번 온다(R-18).
5. control bridge가 마지막에 설치되고 `ready` 메시지를 보낸다(R-15). 부모는 이 신호를 받아 mute·volume·rate를 다시 보낸다.
6. seek(t)가 오면 경로가 둘로 갈린다. 프리뷰의 control `seek`·`__player.seek`는 t를 프레임 격자로 내림하고 clock을 옮긴 뒤 미디어·가시성·timeline·어댑터를 맞춘다. 렌더의 `__player.renderSeek`(producer가 `__hf.seek`로 감싼 것)는 순서가 조금 다르고 캐시를 쓰지 않는다(R-20, R-21, R-22). 둘 다 끝에서 `state`를 강제로 한 번 보낸다.
7. 재생 중에는 `requestAnimationFrame` 루프(`transportTick`)가 clock을 읽어 같은 seek 경로를 매 프레임 돌리고, clock이 끝에 닿으면 멈추고 `ended: true`인 `state`를 보낸다(R-31). 반복 재생은 부모가 맡는다.

### 1.2 범위·통합 지점 [필수]

- 제공: 페이지 전역(`__player`, `__playerReady`, `__renderReady`, `__timelines`, `__clipManifest` 등), `postMessage` 프로토콜(parent→runtime control, runtime→parent 이벤트), seek 한 번에 바뀌는 상태와 순서, 시간 모델(fps, 프레임↔초, 컴포지션 길이, 끝 처리), 어댑터가 런타임에 등록되고 불리는 계약, 실패 처리.
- 제외(이유):
  - 렌더러가 페이지를 열고 프레임을 캡처·인코딩하는 부분은 행 4다. 이 스펙은 렌더러가 부르는 입구(`__hf.seek`, `__hf.duration`, ready 폴링 조건)까지만 쓴다.
  - 방식별 어댑터 내부(GSAP·CSS·WAAPI·Lottie·Three.js 등)는 행 3이다. 이 스펙은 등록 순서, `discover`/`seek`/`pause`/`play`/`revert`/`getReadyPromise`/길이 추정 hook이 불리는 시점까지만 쓴다.
  - 컴파일(속성 해석, 서브 컴포지션 인라인)은 행 1이다. `data-start` 참조 해석은 [composition-contract.md](./composition-contract.md)의 R-04·R-05, `data-track-index`를 렌더가 읽지 않는 것은 같은 문서의 R-11을 따른다. 이 스펙은 런타임이 그 규칙에 더하는 부분만 R-25에 적는다.
  - 편집 UI용 코드(`editing*.ts`, `picker*.ts`, `manualEditGestureWatch.ts`, `positionEdits.ts`, `inspection.ts`)는 행 10 몫이라 읽지 않았다. control의 `enable-pick-mode`, `disable-pick-mode`, `flash-elements`와 outbound의 `element-*`, `pick-mode-cancelled`도 여기 포함된다.
  - 색보정·VFX(`colorGrading.ts` 4.3천 줄, `vfx.ts` 1.4천 줄, `captureMotionBlur`)는 행 12 몫이다. seek 순서 안에서 불리는 위치(`colorGrading.redraw`, `paintVfx`, `paintCaptureMotionBlur`)만 R-20, R-21에 적는다.
  - Studio 미리보기 전용 최적화(`previewSeek.ts`는 R-20에서 읽음, `pausedVideoFrames.ts`, `sceneWindow.ts`·`farScenes.ts`의 scene 파킹, `mediaProxy.ts`의 가벼운 복사본, `previewRasterHints.ts`)는 본문을 읽지 않았다. 렌더에는 쓰이지 않거나(R-23의 `isRenderMode`) 별도 메시지 계열(`preview-copies`, `preview-health`, `preview-facts`)이라 학습 목적상 뺐다. `previewSeek`가 시각 t의 최종 상태를 바꾸는지는 R-20에서 확인했다(commit이 `applySeek(t)`를 부른다).
  - 오디오 믹싱·WebAudio 스케줄링(`webAudioTransport.ts` 1.3천 줄, `audioFx.ts`)은 행 6 몫이다. R-27은 미디어 sync의 구조만 쓴다.
  - 부모 쪽 구현(`packages/player`의 `<hyperframes-player>`, `packages/studio`)은 행 9·11이다. 이 스펙은 부모가 보내야 하는 메시지의 모양과 받는 쪽(런타임) 동작만 쓴다.
- 외부 의존·선행 계약: 선행 스펙은 [composition-contract.md](./composition-contract.md)(컴포지션 속성 계약). 호출자가 제공해야 하는 것은 (a) 런타임 IIFE를 페이지에 싣는 일(렌더는 producer 파일 서버가 manifest의 sha256을 확인하고 싣는다, R-23), (b) 부모 창의 `postMessage` 송수신, (c) 렌더에서는 seek를 프레임마다 부르는 드라이버(`__hf.seek`)다. 컴포지션 작성자는 `window.__timelines[<루트 data-composition-id>]`에 seek 가능한 timeline을 등록하거나(R-06), 어댑터가 읽는 방식(CSS·WAAPI·Lottie 등)을 쓴다.
- 소유 상태·부작용: 런타임 인스턴스 하나가 `RuntimeState`(`capturedTimeline`, `currentTime`, `canonicalFps`, `playbackRate` 등)와 `TransportClock`을 소유한다. 페이지에는 위 전역과 DOM 변경을 남긴다. DOM 변경은 clip 요소의 inline `visibility`/`display`와 `data-hf-clip-hidden` 속성(R-26), 루트 요소의 크기·`position`·`overflow` inline style, 비루트 컴포지션 호스트의 `data-duration`·`data-end` 제거(R-28), 루트의 `data-start="0"` 기본 주입(R-04), 미디어 요소의 `currentTime`·`volume`·`muted`·재생 상태(R-27)다. 같은 창에 런타임이 다시 init되면 이전 인스턴스를 `window.__hfRuntimeTeardown()`으로 먼저 정리한다(R-38).

### 1.3 인터페이스와 데이터 의미 [필수]

#### 1.3.1 페이지 전역

| 이름 | 타입·값 | 의미·수명 |
|---|---|---|
| `window.__timelines` | map<string, timeline-like> | 작성자 스크립트가 `__timelines[<composition id>] = tl`로 등록한다. 런타임은 스크립트 평가 시점에 `{}`를 보장한다. 배열이면 init이 map으로 바꾼다(R-04). 키가 루트 컴포지션 id와 같은 항목이 루트 timeline이다(R-06). timeline-like는 `play`·`pause`·`seek`·`time`·`duration` 등을 가진 객체(GSAP timeline)이고 `totalTime`·`getChildren`·`timeScale`은 있으면 쓴다 |
| `window.__player` | 객체 | init 중간에 설치된다. 실제로 동작하는 멤버는 `play`, `pause`, `seek`, `renderSeek`, `getTime`, `getDuration`, `isPlaying`이고, `getRenderState`는 `time`·`duration`·`isPlaying`만 실제 값이다(`renderMode: false`·`timelineDirty: false`는 상수) 나머지(`setElementPosition` 등 약 35개)는 빈 함수이거나 `false`·빈 값을 돌려주는 stub이다. `setPlaybackRate`·`getPlaybackRate`는 `__player`에 없고 control 메시지로만 바꾼다(R-05) |
| `window.__playerReady` | bool | init이 `__player` 설치 직후 `true`로 둔다. 루트 timeline 바인딩 전이다. 렌더용 body 스크립트(`waitForPlayer`)도 `__player.renderSeek`가 함수가 되면 `true`로 둔다(R-05) |
| `window.__renderReady` | bool | 마운트·어댑터·`buildReady`가 모두 끝나고 루트 timeline 바인딩을 시도한 뒤에 `true`다. `maybePublishRenderReady`가 다시 불려 조건에 걸릴 때만 `false`로 돌아간다(주기 폴링은 없음, R-08) |
| `window.__clipManifest` | `timeline` 메시지 페이로드 | 마지막으로 만든 manifest. `assetsReady`는 들어 있지 않다. 재생 중에는 갱신이 보류된다(R-17) |
| `window.__clipTree` | Studio용 clip 트리 | timed 요소(`[data-start]`)의 부모·자식 관계. 재생 중에는 삭제되고 멈추면 다시 만든다(R-17) |
| `window.__hf` | 객체 | 런타임이 `lengthSource`, `durationSource`, `animationEnd()`, `clipWindow(el)`, `audioMeter`를 채운다. 작성자는 `buildReady`(key→promise map)에 promise를 등록할 수 있다(R-08). `__hf.seek(t, options)`와 `__hf.duration`은 런타임 코드가 만들지 않는다. `__hf.duration`의 호스트 폴백(`getDeclaredDuration`, `fileServer.ts:633-647`)이 합산하는 `data-composition-src` 호스트의 `data-duration`은 R-28의 `postTimeline`이 비루트 컴포지션의 `data-duration`을 지우므로 `__renderReady` 뒤에는 사실상 쓰이지 않을 수 있다(추론). 렌더에서는 producer의 `HF_BRIDGE_SCRIPT`가 `__player.renderSeek`·`getDuration`을 감싸 만든다(R-23) |
| `window.__hfStartupError` | string | 부트 실패 때만 있다. 렌더러가 이 값을 보면 즉시 실패로 처리한다(R-35) |
| `window.__hfRuntimeTeardown` | function | 인스턴스 정리 함수. 다음 init이 먼저 부른다(R-38) |
| 엔진용 hook | function | `__hfWaitForSeekCompletion(options)`(seek가 남긴 비동기 작업이 끝나길 기다림, R-22), `__hfReseekGpu(t)`, `__hfForceTimelineRebind()` |
| 렌더 모드 플래그 | 아래 R-23 | `__HF_EXPORT_RENDER_SEEK_CONFIG`, `__HF_RENDER_CAPTURE_MODE`, `__HF_REPLAY_SKIPPED_FRAMES`, `<meta name="hyperframes-studio-preview">` |

#### 1.3.2 parent → runtime: control 메시지

모든 control은 `{ source: "hf-parent", type: "control", action, ...필드 }` 모양이다. `protocolVersion`이 있으면 `capabilities`·`fps`와 함께 프로토콜 검사를 받는다(R-11). `protocolVersion` 없이 `fps`만 오면 검사 없이 `seek`의 `frame` 계산에만 쓰인다. 아래 표는 이 스펙 범위의 액션이고, 같은 `CONTROL_HANDLERS`에 있는 나머지는 1.2 제외 항목이다(`set-color-grading`, `set-color-grading-compare`, 선택 모드, `flash-elements`, `set-runtime-data`, `clear-runtime-data`, 미리보기 품질·복사본·facts 계열 5개).

| action | 필드 | 효과 |
|---|---|---|
| `play` | 없음 | `player.play()`. clock이 끝에 있으면 `getPlayStart()`(재생 범위 시작, 기본 0)에서 다시 시작한다(R-31) |
| `pause` | 없음 | `player.pause()`. 재생 중이면 clock을 멈추고 현재 시각에 정지시킨다 |
| `seek` | `timeSeconds` 또는 `frame`(+ 선택 `fps`), 선택 `seekMode` | R-13. 프리뷰 seek 경로(R-20). `seekMode`는 init에서 읽지 않는다 |
| `tick` | 없음 | 재생 중일 때만 clock을 한 번 읽고 timeline·어댑터를 맞춘다. 끝에 닿으면 멈춘다. 숨겨진 탭처럼 rAF가 멈춘 호스트가 대신 구동할 때 쓴다 |
| `stop-media` | 없음 | 진행 중인 미리보기 seek·버퍼링을 취소하고 모든 `video`/`audio`를 `pause()`한다 |
| `set-muted` | `muted` | `muted === true`일 때만 mute. 사용자 mute 선호(`bridgeMuted`)다 |
| `set-volume` | `volume` | 없으면 1, 유한한 수면 0~1로 자른다. 유한하지 않으면 메시지를 버린다 |
| `set-media-output-muted` | `muted` | 부모가 오디오를 대신 재생할 때 런타임 미디어 출력을 끈다(`mediaOutputMuted`). 사용자 mute와 별개로 기록한다 |
| `set-native-media-sync-disabled`, `set-web-audio-media-disabled` | `disabled` | 슬라이드쇼 발표 모드용 스위치. 켜면 런타임이 native 미디어 요소를 건드리지 않는다 |
| `set-playback-rate` | `playbackRate` | 없으면 1, 유한하지 않으면 버림. 적용 시 0 이하·NaN은 1, 나머지는 0.1~5로 자른다. timeline `timeScale`과 clock rate를 함께 바꾼다 |
| `set-idle-heartbeat` | `slow` | transport가 정지·idle로 멈춰 있는 동안 `state`를 다시 알리는 타이머 간격을 80ms에서 1초로 늘린다(루트 timeline과 자식 바인딩이 끝난 뒤에만) |
| `set-display-scale` | `scale` | 0보다 큰 유한한 수일 때만. 프리뷰 해상도 힌트라 seek 결과에 영향이 없다 |
| `set-root-duration` | `durationSeconds` | 루트 길이를 늘린다. 현재 길이(clock·루트 `data-duration`·이전 override 중 최댓값) 이하면 무시한다. 늘릴 때 루트 `data-duration`을 쓰고 clock 길이를 바꾸고 `timeline`·`state`를 다시 보낸다 |
| `set-play-range` | `startSeconds`(없으면 0), `endSeconds`(없으면 열린 구간) | clock의 재생 범위를 바꾼다. 재생 중이고 현재 시각이 start 앞이거나 끝에 닿아 있으면 start로 `seek(keepPlaying)`한다. 아니면 `state`만 다시 보낸다 |

#### 1.3.3 runtime → parent: 이벤트

모든 메시지는 `window.parent.postMessage(payload, "*")`로 나가고, `source: "hf-preview"`, `type`, 그리고 프로토콜 메타데이터 `protocolVersion: 1`, `capabilities`(문자열 6개: `seconds-time`, `rational-fps`, `seek-keep-playing`, `composition-manifest-v1`, `runtime-data`, `play-range`), `fps: { numerator, denominator }`가 붙는다(R-14). 페이지가 최상위 창이면 `window.parent`가 자기 자신이라 같은 창으로 보낸다.

| type | 필드 | 의미·발생 시점 |
|---|---|---|
| `ready` | 없음 | control bridge 리스너를 설치한 직후 한 번. iframe가 새로 로드될 때마다 새 런타임이 다시 보낸다. 첫 `timeline`·`state`보다 늦을 수 있다(R-15) |
| `state` | `frame`(int, `round(currentTime × fps)`), `currentTime`(초), `ended`(bool), `isPlaying`, `buffering`, `muted`, `playbackRate` | 재생 상태 스냅샷. 모든 상태 변경(play·pause·seek·renderSeek·control)은 강제 전송으로 끝난다. 재생 중에는 프레임·재생 여부·mute가 바뀌거나 마지막 전송 후 80ms가 지나면 보낸다(R-16) |
| `timeline` | `durationSeconds`, `durationInFrames`, `clips[]`, `scenes[]`, `compositionWidth`, `compositionHeight`, `compositionContractVersion: 1`, `assetsReady`(bool, 있을 때만) | 컴포지션의 clip 목록과 길이(R-17). `compositionWidth`·`compositionHeight`는 루트 `data-width`·`data-height`가 없거나 양의 정수가 아니면 1920×1080이다 |
| `stage-size` | `width`, `height` | 루트의 `data-width`·`data-height`가 둘 다 양의 정수(`parseInt`)로 읽힐 때 `timeline` 직전에 보낸다 |
| `assets-ready` | `timedOut`(bool) | 첫 `timeline` 이후 한 번. 첫 프레임에 필요한 미디어·이미지·폰트가 정착했거나 8초가 지났을 때(R-18) |
| `diagnostic` | `code`, `details` | 런타임이 감지한 문제나 상태 기록(R-19) |
| `media-autoplay-blocked` | 없음 | `play()`가 `NotAllowedError`로 거부된 첫 한 번. 부모가 오디오 재생을 넘겨받는 신호다 |

그 밖의 outbound(`analytics`, `perf`, `group-levels`, `preview-*`, `element-*`, `runtime-data-*`)는 1.2 제외다.

#### 1.3.4 seek 한 번에 바뀌는 것, 렌더와 프리뷰의 차이

공통 단계는 `seekTimelineAndAdapters(t)`(R-22)이고, 앞뒤에 붙는 단계가 두 경로에서 다르다. 아래 표는 같은 t에 대해 각 경로가 상태를 바꾸는 순서다(R-20, R-21).

| 순서 | 프리뷰 `seek` (control `seek`, `__player.seek`) | 렌더 `renderSeek` (`__player.renderSeek`, `__hf.seek`) |
|---|---|---|
| 0 | t를 `quantizeTimeToFrame`으로 프레임 격자에 내림. 이미지가 막 보이게 되는데 아직 decode가 안 됐으면 최대 1초 이전 화면을 붙잡는다 | 진행 중인 미리보기 seek·held seek를 취소하고 `renderCaptureSeekStarted`를 켠다. t는 `resolveRenderSeekTime`(내림, `exact`면 그대로, `subFrameDivisions`면 세분 격자 반올림) |
| 1 | `seekWhenReady`(`init.ts:5170-5202`)가 경로를 고른다. `mediaDeferred`(Studio 미리보기 meta가 있거나, WebKit이고 `<hyperframes-player>`가 만든 iframe 안)가 아니거나, `nativeMediaSyncDisabled`(부모가 `set-native-media-sync-disabled`로 켠 상태)이거나, `isExportRenderDrivingFrames()`이거나, `__HF_EXPORT_RENDER_SEEK_CONFIG`가 있거나, `keepPlaying`이면서 재생 중이면 진행 중인 `previewSeek`를 취소하고 곧바로 `applySeek`로 간다. 나머지(지연 미디어 미리보기)는 `previewSeek` 경로다(R-20) | 항상 아래 순서 |
| 2 | WebAudio 정지, clock의 오디오 소스 해제, clock 정지, `clock.seek(t)`(길이로 clamp), `state.currentTime = clock.now()`, `isPlaying = false`, 미디어 강제 sync 플래그 켬 | 같음 |
| 3 | `syncMediaForCurrentState()`: 미디어 요소의 `currentTime` 맞춤과 clip 가시성 pass. 페이지 그리기보다 먼저 해서 디코딩이 겹치게 한다 | (아직 안 함) |
| 4 | root timeline `pause` | (3의 위치) |
| 5 | `seekTimelineAndAdapters(t)`: scene timeline → 루트 timeline → 비GSAP 어댑터(R-22) | 같음. 단 `suppressEvents` 옵션이 timeline seek에 전달된다 |
| 6 | `decideClipsUnderScriptHidden(t)`: 스크립트가 숨긴 clip 아래 clip의 가시성을 다시 판정 | (없음) |
| 7 | `runAdapters("pause")`: 모든 어댑터 `pause()` | 같음 |
| 8 | (3에서 이미 함) | `syncMediaForCurrentState()`: 미디어 sync와 clip 가시성 pass. 이 pass는 인덱스·캐시 없이 모든 요소를 방문한다(R-23) |
| 9 | `colorGrading.redraw()`, `paintVfx(t)`, `paintCaptureMotionBlur(t)` | 같은 세 호출. VFX·블러는 `engineMode: true`로 부른다 |
| 10 | `postState(true)` | 같음 |

`keepPlaying` 옵션이 있고 직전에 재생 중(또는 buffering)이었다면 프리뷰 `applySeek`는 2의 정지·seek, 4(timeline pause), `pausedFrames.notify()`, 5, 7은 그대로 하고 3(`syncMediaForCurrentState`), 6, 9(`colorGrading.redraw`·`paintVfx`·블러)를 건너뛴다. 끝의 `postState(true)` 대신 `transport.play()`를 불러 재생을 이어 가고 상태 전송은 그 안에서 한다.

#### 1.3.5 시간 모델

| 항목 | 규칙 |
|---|---|
| fps | `canonicalFps`는 init에서 한 번 정한다. 우선순위는 렌더 설정의 `__HF_EXPORT_RENDER_SEEK_CONFIG.fps`(유효할 때), 루트 `data-fps`(`parseFps`가 받아들일 때), 30이다(R-03) |
| 프레임 ↔ 초 | 초 = 프레임 / fps. control의 `frame`은 메시지 `fps`(분수), 없으면 `canonicalFps`로 나눈다(R-13). `state.frame`은 `round(currentTime × fps)`다(R-16) |
| 시각 양자화 | 프리뷰·렌더 모두 기본은 `floor(t × fps + 1e-9) / fps`. 렌더는 `exact`·`subFrameDivisions` 옵션이 있다(R-24) |
| 컴포지션 길이 | 루트 `data-duration`이 유한한 양수면 그 값이다. 없으면 timeline 길이, 미디어 창·authored 서브 컴포지션·어댑터 추정 길이의 최댓값(floors), 호출자 fallback 중 가장 긴 값이고, 모두 없으면 clip들의 끝에서 유도한 값이다(R-29) |
| 끝 | clock은 `min(길이, 재생 범위 끝)`에서 멈춘다. `state.ended`는 `clock.reachedEnd()`다(R-31) |
| `timeline.durationSeconds` | clock 길이와 별도로 계산한다. manifest의 clip들과 루트 창으로 정하며 값이 다를 수 있다(R-32) |

#### 1.3.6 어댑터 계약

`RuntimeDeterministicAdapter`(`types.ts:412-477`)가 런타임이 어댑터에 요구하는 인터페이스다. 전체가 C-09에 있고, 여기서는 불리는 시점만 적는다(R-09).

| 멤버 | 불리는 시점 |
|---|---|
| `name` | 식별자. `"gsap"`이면 루트 timeline이 바인딩된 동안 seek 패스(R-22)의 순회에서만 빠진다. `discover` 직후의 부트스트랩 seek와 `pause`에서는 빠지지 않는다(R-09) |
| `discover()` | init 중 한 번(`init.ts:5486`), `maybePublishRenderReady`가 마운트·timeline 빌드 대기 검사를 통과할 때마다 `getReadyPromise` 평가 앞에서(`5580`), 루트 timeline 바인딩 직후 한 번 더(`5493`), 그리고 scene 교체·마운트 경로 `settleChangedScenes` 안에서(`4572`, 프리뷰 전용으로 추정, R-08). 매번 모든 어댑터에 `seek({time, suppressEvents: true})`가 이어서 불린다. 여러 번 불려도 안전해야 하고, `getReadyPromise`는 항상 discover 뒤에 평가된다 |
| `seek({time, suppressEvents, pageAnimations})` | 모든 seek 패스, 재생 중 매 tick. 등록 순서대로 부르고 예외는 삼킨다 |
| `pause({pageAnimations})` | 모든 seek 끝, 재생 정지·끝 처리 때 |
| `play?()` | `transport.play()`에서만 |
| `revert?()` | 런타임 teardown 때 |
| `getReadyPromise?()` | `__renderReady` 게이트가 평가될 때마다(R-08). promise가 settle될 때까지 `__renderReady`는 `false`다. 같은 promise를 반복해서 돌려주는 것이 계약이고, throw·reject는 삼키고 진행한다 |
| `getInferredDurationSeconds?()`, `getAnimationCycleEndSeconds?()` | 컴포지션 길이 floors 계산(R-29)과 `__hf.animationEnd()`에서. 캐시하지 않고 매번 부른다 |

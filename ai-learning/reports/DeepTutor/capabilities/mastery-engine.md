# 마스터리 엔진: 학습 상태·게이트·다음 목표·증거 기록

> 학습 경로(모듈 → 지식점)와 시도·평가 증거를 입력받아, 지식점별 숙달 여부(게이트)와 "지금 무엇을 할지"(다음 목표)를 계산하고, 답을 채점·기록할 때 상태가 어떻게 바뀌는지를 정한다.

## 1부. 동작 설명

### 1.1 한눈에 보는 흐름 [필수]
1. 경로가 만들어지면 `LearningProgress`(경로 하나의 상태 전체)에 모듈과 지식점이 들어가고, `knowledge_types[kp_id]`가 지식점 유형(memory/concept/procedure/design)을 기억한다(R-02, R-19).
2. 튜터가 문제를 내면 `PendingQuestion`(정답 키 포함)이 서버 쪽에 저장되고 학습자 답이 올 때까지 대기한다(R-22, R-17).
3. 답이 오면 **결정론적 채점**(`grade_answer`) 또는 의미 채점 판정(verdict)으로 정오를 정하고, 시도(`QuizAttempt`)를 쌓고, 오류 기록을 만들거나 졸업시키고, 증거(`LearningEvidence`)를 쌓고, 숙달도를 다시 계산하고, 복습 일정을 갱신한다(R-09~R-13, 복습 일정 자체는 `review-scheduler.md`).
4. 개념·설계형(concept/design)은 숫자 채점 대신 튜터가 학습자의 설명을 판정하고(`record_qualitative`) 그 결과가 게이트가 된다(R-14).
5. 다음 목표는 상태에서 **매번 계산**한다: 대기 중인 질문 → 기한 지난 복습 → 첫 미숙달 지식점 → 완료(R-07). 단계 포인터를 따로 저장하지 않는다.
6. 학습자는 "이미 안다"(override)고 선언하거나 "나중에"(defer)로 미룰 수 있다. 둘 다 증거를 바꾸지 않는다(R-15).

### 1.2 범위·통합 지점 [필수]
- 제공: 상태 데이터의 의미, 게이트 판정, 숙달도 계산, 다음 목표 선택, 채점·기록 파이프라인, 질적 판정 기록, override·defer, 모듈 교체 시 상태 정리.
- 제외(이유):
  - **복습 일정 계산**: `review-scheduler.md`가 맡는다. 이 스펙은 스케줄러를 호출하는 지점과 입력 증거만 정의한다.
  - **문항 그룹**(`question_type="group"`, 2~4문항), **시각 과제**(`visual_context`), **출처 노출로 인한 독립성 판정**(`_apply_source_assistance`), **레슨 증거 검증**(`lesson_evidence`), **문제 수리**(`repair_question`): 제품의 UI·출처 연동을 전제로 한 층이라 이 스펙의 목적(상태 + 순수 함수) 밖이다. `independent` 플래그와 `hints_used`가 숙달도 계산에 미치는 효과만 정의한다.
  - **LLM 호출 자체**(문제 출제, 의미 채점, 질적 판정): 입력·출력 계약(verdict, 판정 boolean)만 정의한다.
  - **이벤트 발행·경로 리스(동시 턴 방지)·복구**: 제품 런타임 층. 이 스펙은 저장소를 "호출자가 제공하는 원자적 읽기-수정-쓰기"로만 본다.
  - **선택지 라벨 해석·옛 형식 복구**: `choice` 답을 한 선택지로 읽는 규칙(`resolve_choice_submission`·`is_readable_choice_answer`·`parse_options`), 옛 문자열 선택지 목록(`["A: body", ...]`)의 분해, `pending_question`만 있고 상호작용 행이 없는 옛 집계의 복구(`_interaction_from_legacy_pending`). 입력 정규화·마이그레이션 층이다. 이 스펙은 새 문항을 `{label, body}` 선택지로 받고 `choice` 답을 `grade_answer`가 비교할 수 있는 문자열로 이미 정규화해 넘긴다고 본다. 범위 안 연산만 쓰면 `pending_question`이 있을 때와 활성 상호작용이 있을 때가 같다(추론).
  - **출처 목록 검증**: `validate_objective_relations`의 `topic_source_ids` 검사(출처 모델 `TopicSource`)는 제품의 출처 연동을 전제로 해서 제외한다. 이 스펙의 입력은 모든 지식점이 `topic_source_ids=[]`라고 본다(R-21).
- 외부 의존:
  - **저장소**: 경로 id로 `LearningProgress` 하나를 읽고, 함수로 수정하고, 원자적으로 쓴다. 원본은 SQLite 트랜잭션 + 리비전 + 상호작용 테이블이다. 이 스펙이 쓰는 **최소 인터페이스**(C-30): `store.mutate(book_id, fn)` → `(progress, fn의 반환값)`. 경로를 잠그고 상태를 읽어 트랜잭션 객체 `tx`를 만들어 `fn(tx)`를 부른다. `tx`에 필요한 것: `tx.progress`(수정 가능한 `LearningProgress`), `tx.active_interaction()`(활성 상호작용 또는 None, 정의는 R-22), `tx.get_interaction(id)`(이 경로의 그 id 상호작용, 상태 무관, 없으면 None), `tx.put_interaction(i)`(저장·갱신, R-17의 허용 전이만), `tx.abandon_active_interactions()`(활성 전부를 abandoned로, 바뀐 개수 반환), `tx.touch()`(변경 표시)·`tx.emit(...)`(이벤트, 제품 층이라 구현은 변경 표시만 해도 된다). 실패·원자성은 R-24. 예외 이름은 1.3, 실패 전달은 R-17.
  - **스케줄러**: `scheduler` 인자가 `None`이면 복습 갱신을 건너뛴다(R-13).
  - **시계**: 시각은 모두 epoch **초**(`time.time()`). `now` 인자가 없으면 호출 시점의 현재 시각.
- 소유 상태·부작용: `LearningProgress`의 필드들(1.3). 이 스펙의 함수는 상태를 제자리에서 바꾸고, 저장은 호출자(또는 `save`/`mutate`)가 한다.

### 1.3 인터페이스와 데이터 의미 [필수]

**지식 유형과 오류 유형** (C-01): `KnowledgeType` ∈ {memory, concept, procedure, design}, `ErrorType` ∈ {structural, deviation, application, metacognitive}. 중국어 옛 값은 입력 시 영어 값으로 바뀐다(C-01 매핑표).

**경로 상태** `LearningProgress`(C-08, 지식점 id를 키로 쓰는 맵이 핵심):

| 필드 | 타입 | 의미·제약 |
|---|---|---|
| `modules` | list of `LearningModule`(id, name, `order`, `pass_threshold` 기본 0.7, `objective`, `knowledge_points`) | 지식점 목록의 순서가 곧 학습 순서(R-07). `pass_threshold`는 이 스펙의 게이트 계산에서 쓰이지 않는다(추론: 읽은 코드에서 참조 없음) |
| `KnowledgePoint` | id, name, `type`, `module_id`, `prerequisite_ids`, `topic_source_ids`, `required_visual_tasks` | `prerequisite_ids`는 모듈 구성 때 검증(자기참조·순환 거부, `objective_relations.py`)되고 `next_objective`는 읽지 않는다(R-07) |
| `knowledge_types` | map kp_id → KnowledgeType | 스케줄러가 유형을 찾는 곳. 모듈 교체 때 다시 채워진다(R-19) |
| `mastery_levels` | map kp_id → float 0..1 | 정량 게이트의 입력이자 화면 표시값. 기록 때마다 재계산(R-09) |
| `qualitative_mastery` | map kp_id → bool | 질적 게이트의 기록. **키가 있으면** "시도했음"으로 본다(False 포함, R-06) |
| `quiz_attempts` | list of `QuizAttempt` | 추가 전용 시도 기록(순서 = 추가 순서). `voided=True`는 감사용으로 남지만 숙달도·오류·복습에서 제외 |
| `error_records` | list of `ErrorRecord` | 오답 기록과 재시도 이력. 상태 `active` → `retrying` → `graduated`(R-12) |
| `learning_evidence` | list of `LearningEvidence` | 복습 일정 재계산용 사건 기록(추가 순서가 기준) |
| `repetition_states`, `review_queue` | map / list | `review-scheduler.md`가 정의 |
| `desired_retention` | float 0.7..0.99, 기본 0.9 | 경로당 하나. 새 반복 상태에 복사됨. 범위(0.7..0.99, NaN 불가)는 모델 생성·적재 때만 검증되고 대입은 검증하지 않는다(`validate_assignment` 없음. `set_desired_retention`은 스스로 검증) |
| `learner_mastery_overrides`, `deferred_objectives` | map kp_id → 객체(note ≤ 500자) | R-15 |
| `pending_question` | `PendingQuestion` 또는 null | 동시에 하나. 정답 키·해설은 서버에만 있다. 학습자·튜터에게 보이는 투영(C-31, C-32)은 `question_id`, `prompt`, `question_type`, `options`(`choice`일 때만 `{id, label, body}` 목록, 아니면 빈 목록)이고 문항 그룹일 때만 `questions`가 더해진다. `knowledge_point_id`·`module_id`·`expected_answer`·`explanation`·`accepted_answers`·출처는 들어가지 않는다. `prompt`·`label`·`body`는 연속 3개 이상의 `\uXXXX` 이스케이프가 비ASCII 문자로 풀릴 때만 풀어서 보인다 |
| `learner_profile.teaching_strategy` | "probe_first"(기본) \| "teach_first" | 새 지식점의 첫 행동을 정한다(R-07) |

**시도·증거**(C-03): `QuizAttempt`(question_id, knowledge_point_id, `is_correct`, `result` ∈ correct/partial/incorrect — 비어 있으면 `is_correct`에서 채움, `error_type`, `independent` 기본 true, `voided`, `timestamp` 초). `LearningEvidence`(knowledge_point_id, `assessment_type` ∈ quiz/qualitative/review, `result`, `quality` 0..1 또는 null, `hints_used`, `attempt_count`, `confidence`, `timestamp`, `evidence_id`(기본 ""), `source`(기본 `"mastery_path"`), `learner_answer`·`feedback`(기본 ""), `session_id`·`turn_id`(기본 ""), `visual_context`(map, 기본 비어 있음)). 증거에는 `independent` 필드가 없다. `quality`는 "정답 정도"이며 학습자 자기평가가 아니다.

**상호작용**(C-33): `MasteryInteraction`(`interaction_id` = 문항의 `question_id`, `path_id`, `question`(PendingQuestion), `status` ∈ registered/awaiting_input/answered/graded/abandoned, `session_id`, `turn_id`, `user_answer`, `result`(map), `created_at`, `updated_at` 초). 선택지 `PendingOption`(`label`, `body`). 문항의 `assistance_used`(기본 false)·`visual_context`(기본 비어 있음)는 이 스펙에서 기본값으로 본다(출처 노출 판정 제외). **영수증**(의미 채점 판정)은 R-16.

### 1.4 행동 규칙과 남은 질문 [필수]

| ID | 조건·입력 | 반드시 관찰될 결과·사후 상태 | 검증 수준 |
|---|---|---|---|
| R-01 | 지식 유형·오류 유형 enum | 값 4종씩(C-01). 중국어 옛 값은 영어 값으로 읽힌다 | 코드 확인 |

- 같은 목적의 다른 레포 분석: [learnharness 스펙](../../learnharness/overview.md#스킬화-관점-지도-2026-10-27-추가). learnharness에는 복습 일정·숙달 게이트가 없다(overview 지도 7번).
- 코드를 복사한 적 없음.

## Purpose & Scope

This document provides technical instructions for setting up a local development environment for the Langfuse monorepo. It covers prerequisites, dependency management with `pnpm`, infrastructure orchestration via Docker, and the initialization of the dual-database architecture (PostgreSQL and ClickHouse).

## System Requirements

### Node.js Runtime
Langfuse requires **Node.js version 24**. This is enforced across the monorepo configuration to ensure compatibility with Next.js and modern OpenTelemetry instrumentations used in the services.

| Component | Requirement | Source |
| :--- | :--- | :--- |
| Node Version | `24` | [package.json:8-8](), [web/package.json:7-7](), [worker/package.json:12-12]() |
| Web Engine | `node: 24` | [web/package.json:7-7]() |
| Worker Engine | `node: 24` | [worker/package.json:12-12]() |

### Package Manager
The project uses **pnpm version 11.1.3**. Usage of `pnpm` is strictly enforced via the `preinstall` script to maintain lockfile integrity and efficient workspace linking.

```bash
# Corepack is used to manage the pinned version
corepack enable
corepack prepare pnpm@11.1.3 --activate
```

**Sources:** [package.json:14-14](), [package.json:100-100](), [CONTRIBUTING.md:114-114]()

### Core Technology Stack
The development environment relies on the following core tools:
*   **Turbo**: Orchestrates tasks (build, lint, test) across the monorepo [package.json:51-51]().
*   **Docker**: Required for running the local infrastructure stack defined in `docker-compose.dev.yml` [package.json:15-17]().
*   **ClickHouse Client**: Necessary for manual database inspections and running migration scripts [CONTRIBUTING.md:116-116]().
*   **golang-migrate**: Used for managing ClickHouse database migrations via a custom-built CLI [web/Dockerfile:23-35]().

### Installation Command
To install all dependencies and link internal workspace packages, run:
```bash
pnpm install
```
The repository uses a `postinstall` script to execute a helper bash script for repository-specific setup tasks [package.json:13-13]().

## Infrastructure Setup

### Local Services
Langfuse requires four primary infrastructure components. These are managed via `docker-compose.dev.yml`.

| Service | Technology | Usage |
| :--- | :--- | :--- |
| **Database** | PostgreSQL | Transactional data (Users, Projects, API Keys) [CONTRIBUTING.md:70-70]() |
| **Analytics** | ClickHouse | OLAP data (Traces, Observations, Scores) [CONTRIBUTING.md:72-72]() |
| **Cache/Queue** | Redis | BullMQ job coordination and caching [CONTRIBUTING.md:71-71]() |
| **Storage** | S3 / Blob | Raw event storage and multi-modal attachments [CONTRIBUTING.md:73-73]() |

**Sources:** [CONTRIBUTING.md:64-89](), [package.json:15-17]()

### Management Commands
Infrastructure is controlled via root-level scripts:
*   `pnpm run infra:dev:up`: Starts the local Docker stack and waits for health checks [package.json:15-15]().
*   `pnpm run infra:dev:down`: Stops the local Docker stack [package.json:16-16]().
*   `pnpm run infra:dev:prune`: Stops the stack and removes all volumes (data reset) [package.json:17-17]().

## Database Initialization

### PostgreSQL & Prisma
PostgreSQL initialization involves generating the Prisma client and applying migrations. These tasks are orchestrated via `turbo`.

```bash
# Generate Prisma Client
pnpm run db:generate

# Apply migrations to local Postgres
pnpm run db:migrate

# Seed initial development data
pnpm run db:seed
```

**Sources:** [package.json:18-20](), [packages/shared/package.json:67-73]()

### ClickHouse Migrations
ClickHouse schema management is handled using a combination of shell scripts and a dedicated seeder.

*   `ch:up`: Starts ClickHouse containers using `clickhouse/scripts/up.sh` [packages/shared/package.json:76-76]().
*   `ch:dev-tables`: Runs `dev-tables.sh` to initialize development-specific table structures [packages/shared/package.json:79-79]().
*   `ch:seed`: Executes `seed-clickhouse.ts` to populate the OLAP database [packages/shared/package.json:81-81]().

## Streamlined Onboarding: The `dx` Command

For a "one-command" setup, Langfuse provides the `dx` script. This is the recommended path for new contributors to get a fully working environment including example data.

```bash
pnpm run dx
```

**Sequence of operations performed by `dx`:**
1.  **Install**: Runs `pnpm i` to install dependencies [package.json:23-23]().
2.  **Reset Infrastructure**: Runs `infra:dev:prune` to clear old state [package.json:23-23]().
3.  **Start Services**: Runs `infra:dev:up --pull always` to fetch and start fresh containers [package.json:23-23]().
4.  **Postgres Reset**: Resets transactional databases via `db:reset:test` and `db:reset` [package.json:23-23]().
5.  **ClickHouse Reset**: Resets OLAP database via `ch:reset` which handles `ch:down`, `ch:up`, `ch:seed`, and `ch:dev-tables` [package.json:23-23](), [packages/shared/package.json:80-80]().
6.  **Seed Examples**: Populates the environment with example data via `db:seed:examples` [package.json:23-23]().
7.  **Launch**: Starts development servers for `web` and `worker` via `pnpm run dev` [package.json:23-23]().

**Sources:** [package.json:23-25](), [CONTRIBUTING.md:154-155](), [packages/shared/package.json:80-80]()

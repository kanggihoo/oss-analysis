The MinerU project utilizes a robust CI/CD infrastructure powered by GitHub Actions to manage versioning, automated testing, package distribution to PyPI, and documentation deployment. The pipeline ensures that every release is validated across multiple Python environments and that documentation remains synchronized with the `master` and `dev` branches.

## Release Workflow Orchestration

The primary release process is defined in `.github/workflows/python-package.yml`. This workflow is triggered by the creation of a git tag matching the pattern `*released` or via manual `workflow_dispatch` [[.github/workflows/python-package.yml:6-10]](). It consists of four sequential jobs: `update-version`, `check-install`, `build`, and `release`.

### 1. Version Management (`update-version`)
This job synchronizes the internal Python package version with the Git tag. It uses a specialized script, `update_version.py`, to extract the version string and write it to the codebase.

*   **Logic**: The `get_version()` function executes `git describe --tags` to find the latest tag [[update_version.py:7-9]]().
*   **Validation**: It expects a format like `mineru-<version>-released`. If valid, it extracts the `<version>` component using `version_parts[1]` [[update_version.py:10-12]]().
*   **Injection**: The `write_version_to_commons(version)` function writes the string into `mineru/version.py` as the `__version__` variable [[update_version.py:20-23]]().
*   **Persistence**: The workflow commits this change back to the `master` branch using a dedicated `RELEASE_TOKEN` [[.github/workflows/python-package.yml:38-56]]().

### 2. Installation Verification (`check-install`)
To ensure cross-version compatibility, the pipeline attempts to install the package on a matrix of Python versions: 3.10, 3.11, 3.12, and 3.13 [[.github/workflows/python-package.yml:60-63]](). It performs a development-mode installation using `pip install -e .[core]` to verify that all core dependencies resolve correctly [[.github/workflows/python-package.yml:82-85]]().

### 3. Build and Artifact Generation (`build`)
Once installation is verified, the pipeline builds the distribution files:
*   Installs the `build` and `wheel` packages [[.github/workflows/python-package.yml:103-106]]().
*   Executes `python -m build --wheel` to generate the `.whl` file [[.github/workflows/python-package.yml:108-110]]().
*   Uploads the resulting wheel as a GitHub artifact named `wheel-file` for the final release job [[.github/workflows/python-package.yml:112-117]]().

### 4. Publishing (`release`)
The final stage handles external distribution:
*   **GitHub Release**: Uses `softprops/action-gh-release` to create a formal release on GitHub and attach the wheel file [[.github/workflows/python-package.yml:132-139]]().
*   **PyPI Distribution**: Uses `twine` to upload the package to PyPI. It performs a `twine check dist/*` before using a PyPI token (`__token__`) for the upload [[.github/workflows/python-package.yml:140-144]]().

## Documentation Deployment

Documentation is managed via MkDocs and deployed automatically to GitHub Pages. The configuration is stored in `mkdocs.yml` [[mkdocs.yml:1-161]]().

*   **Workflow**: The `Publish docs via GitHub Pages` workflow triggers on pushes to `master` and `dev` branches [[.github/workflows/mkdocs.yml:2-6]]().
*   **Source**: It checks out the repository and specifically uses the `dev` branch for the build source [[.github/workflows/mkdocs.yml:13-16]]().
*   **Requirements**: It installs dependencies via the environment configuration pointing to `/docs/requirements.txt` [[.github/workflows/mkdocs.yml:22]]().
*   **Deployment**: The `mhausenblas/mkdocs-deploy-gh-pages` action handles the build and push to the `gh-pages` branch using the `RELEASE_TOKEN` [[.github/workflows/mkdocs.yml:17-21]]().
*   **Features**: The documentation supports multi-language (English and Chinese) via the `i18n` plugin [[mkdocs.yml:120-132]]() and uses the Material theme [[mkdocs.yml:9]]().
*   **Assets**: Uses `docs/images/logo.png` and `docs/images/logo.svg` for site branding [[mkdocs.yml:34-35]](), [[docs/images/logo.svg:1-22]]().
*   **Customization**: Custom CSS in `docs/stylesheets/extra.css` handles the layout for the Gradio demo page, specifically hiding the secondary sidebar and expanding content width for elements with the `.mineru-demo-page` class [[docs/stylesheets/extra.css:1-22]](). This is used in the Gradio demo index pages to ensure the iframe is rendered correctly [[docs/en/demo/index.md:6-8]](), [[docs/zh/demo/index.md:6-8]]().

**Sources:** [[.github/workflows/mkdocs.yml:1-23]](), [[mkdocs.yml:1-161]](), [[docs/images/logo.svg:1-22]](), [[docs/stylesheets/extra.css:1-41]](), [[docs/en/demo/index.md:1-9]](), [[docs/zh/demo/index.md:1-9]]()

## Contributor License Agreement (CLA)

MinerU enforces a CLA check for all pull requests to ensure legal compliance.

*   **Workflow**: `.github/workflows/cla.yml` is triggered by `issue_comment` (created) and `pull_request_target` (opened, closed, synchronize) [[.github/workflows/cla.yml:1-6]]().
*   **Activation**: The check runs if a user comments "I have read the CLA Document and I hereby sign the CLA" or "recheck" [[.github/workflows/cla.yml:20]]().
*   **Storage**: Signatures are stored in a JSON file at `signatures/version1/cla.json` on a dedicated `cla` branch [[.github/workflows/cla.yml:28-31]]().
*   **Allowlist**: Specific maintainers (e.g., `myhloli`, `dt-yy`, `Focusshang`, `renpengli01`, `icecraft`, `drunkpig`, `wangbinDL`, `qiangqiang199`, `GDDGCZ518`, `papayalove`, `conghui`, `quyuan`, `LollipopsAndWine`, `Sidney233`) are exempt from the CLA check [[.github/workflows/cla.yml:32]]().
*   **Document**: The CLA document is hosted at `https://github.com/opendatalab/MinerU/blob/master/MinerU_CLA.md` [[.github/workflows/cla.yml:29]]().

**Sources:** [[.github/workflows/cla.yml:1-44]]()

## Additional CI/CD Workflows

### CLI Integration Tests
The `mineru-cli-test` workflow validates the CLI functionality on every push to `master` or `dev` [[.github/workflows/cli.yml:4-9]]().
*   **Environment**: Uses `astral-sh/setup-uv` for high-speed dependency management and virtual environment setup [[.github/workflows/cli.yml:28-34]]().
*   **Installation**: Installs the package with test extras using `uv pip install .[test]` [[.github/workflows/cli.yml:36]]().
*   **Coverage**: Runs `tests/clean_coverage.py` to reset metrics before executing `coverage run` and `tests/get_coverage.py` to generate reports [[.github/workflows/cli.yml:37-39]]().

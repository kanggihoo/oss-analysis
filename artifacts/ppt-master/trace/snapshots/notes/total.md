# 01_표지

안녕하세요, 4년 차 백엔드 개발자 김도윤입니다. 저는 느린 API를 측정으로 찾아 수치로 개선하는 개발자이고, 그 대표 결과가 주문 조회 API의 p95 응답 시간을 1.8초에서 0.4초로 줄인 일입니다. 이 자료의 내용은 검증용 가상 샘플입니다.

# 02_소개

저는 Python 중심의 백엔드 개발자이고, 주로 FastAPI, PostgreSQL, Redis, AWS를 씁니다. 관심 분야는 성능 개선, 관측성, 배포 자동화입니다. 다음 두 프로젝트에서 이 가운데 성능 개선과 배포 자동화를 다뤘습니다.

---

# 03_주문api_문제원인

첫 번째 프로젝트는 2025년의 주문 API 응답 속도 개선입니다. 피크 시간대에 주문 조회 API의 p95 응답 시간이 1.8초까지 느려졌고, 원인은 세 가지였습니다. N+1 쿼리, 인덱스 누락, 그리고 동일한 상품 정보를 반복해서 조회하는 문제입니다. 3인 팀에서 저는 원인 분석, 쿼리와 인덱스 수정, cache 설계를 맡았습니다.

---

# 04_주문api_조치결과

그 결과 p95 응답 시간은 1.8초에서 0.4초로 줄었고, DB CPU 사용률도 70%에서 35%로 내려갔습니다. 조치는 세 가지였습니다. selectinload로 쿼리 수를 줄였고, 복합 인덱스를 추가했고, 상품 정보에 Redis cache를 도입했습니다.

---

# 05_배포자동화

두 번째는 2024년의 배포 파이프라인 자동화입니다. 수동 배포에 40분이 걸렸고, 배포가 실패했을 때의 원복 절차는 문서에만 있었습니다. 저는 GitHub Actions로 test, build, deploy를 구성하고 blue/green 전환과 실패 시 자동 rollback을 넣었습니다. 그 결과 배포 시간은 40분에서 8분으로 줄었고, 월 평균 배포 횟수는 4회에서 22회로 늘었습니다. 이 프로젝트는 설계부터 구현까지 혼자 맡았습니다.

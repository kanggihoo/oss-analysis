This page documents the end-to-end demo scripts provided in the `toolbox/mdcode/demo/` directory. These demos illustrate how to use the `kcmd` tool to manage metadata as code for different Google Cloud resources, specifically BigQuery datasets and Dataplex-based Knowledge Bases.

## Overview of Demo Scenarios

The demos are categorized into three primary workflows:
1.  **BigQuery Dataset**: Managing metadata for structured data assets using the `StandardLayout` (YAML-based).
2.  **Knowledge Base**: Managing a set of document-like entries in a Dataplex Entry Group using the `DocumentsLayout` (Markdown-based).
3.  **OKF Wiki**: Demonstrating the synchronization of an [Open Knowledge Format](https://github.com/GoogleCloudPlatform/knowledge-catalog/tree/main/okf) bundle into Knowledge Catalog.

### Prerequisites and Configuration
All demos require a GCP project with BigQuery and Dataplex APIs enabled [toolbox/mdcode/demo/README.md:3-9](). Users must authenticate via `gcloud` and set the default project and region [toolbox/mdcode/demo/README.md:13-17]().

## BigQuery Dataset Demo

This scenario demonstrates the synchronization of BigQuery resource metadata (datasets and tables) to local YAML files.

### Workflow Execution
1.  **Setup**: The `setup.ts` script uses the `bq` CLI to create a dataset named `demo_ecommerce` and a table `events` populated from public GA4 sample data [toolbox/mdcode/demo/bq/setup.ts:7-31](). It also generates a `catalog.yaml` manifest with a `bq-dataset` scope [toolbox/mdcode/demo/bq/setup.ts:36-58]().
2.  **Pull**: Executing `kcmd pull` downloads the metadata. Because it is a BigQuery scope, it uses the `StandardLayout` where each entry is a `.yaml` file [toolbox/mdcode/demo/README.md:39-42]().
3.  **Update**: The `update.ts` script modifies the local YAML file to add or change a `dataplex-types.global.overview` aspect [toolbox/mdcode/demo/bq/update.ts:4-15]().
4.  **Push**: Executing `kcmd push` synchronizes the local YAML changes back to the Dataplex Knowledge Catalog [toolbox/mdcode/demo/README.md:59-60]().
5.  **Cleanup**: The `cleanup.ts` script drops the BigQuery schema [toolbox/mdcode/demo/bq/cleanup.ts:4-15]().

## Knowledge Base Demo

This scenario demonstrates managing a "Knowledge Base" (a collection of markdown documents) within a Dataplex Entry Group.

### Technical Implementation
The Knowledge Base demo utilizes the `DocumentsLayout`. In this layout, the local representation consists of `.md` files where the Markdown body maps to the `overview` aspect, and metadata (like titles or tags) is stored in YAML frontmatter.

1.  **Setup**: `setup.ts` creates a Dataplex Entry Group named `demo_kb` and populates it with several entries (e.g., `index`, `topic1`, `dir/topic1`) using `gcloud dataplex entries create` [toolbox/mdcode/demo/kb/setup.ts:12-51]().
2.  **Manifest Generation**: It creates a `catalog.yaml` with a `kb` scope pointing to the `demo_kb` entry group [toolbox/mdcode/demo/kb/setup.ts:60-78]().
3.  **Library Usage**: Unlike the BigQuery demo, the KB `update.ts` script demonstrates using the `kcmd` library programmatically. It initializes a `CatalogSnapshot` via `CatalogSnapshot.fromPath` [toolbox/mdcode/demo/kb/update.ts:4-4](), looks up an entry via `lookupEntry` [toolbox/mdcode/demo/kb/update.ts:6-6](), and calls `updateEntry` to modify the `dataplex-types.global.overview` aspect [toolbox/mdcode/demo/kb/update.ts:10-14]().

## OKF Wiki Demo

The OKF (Open Knowledge Format) demo showcases the integration between standardized documentation bundles and Knowledge Catalog.

### Features
*   **Documents Layout**: Maps a directory structure of 17 markdown files (GA4 sample) to entries in an `okf_ga4` Entry Group [toolbox/mdcode/demo/README.md:123-130]().
*   **Path-to-Entry Mapping**: File paths like `references/metrics/event_count.md` are automatically converted to entry names like `references/metrics/event_count` [toolbox/mdcode/demo/README.md:145-147]().
*   **Aspect Mapping**: The markdown body is stored in `dataplex-types.global.overview`, while frontmatter fields (`title`, `description`, `tags`) map to specific entry fields or aspects [toolbox/mdcode/demo/README.md:127-129]().

### Execution Summary
| Step | Action | Description |
| :--- | :--- | :--- |
| **Setup** | `bun setup.ts` | Creates the `okf_ga4` Entry Group and `catalog.yaml` [toolbox/mdcode/demo/README.md:131-141](). |
| **Publish** | `kcmd push` | Synchronizes the local `catalog/` directory (pre-populated with OKF GA4 bundle) to the cloud [toolbox/mdcode/demo/README.md:143-153](). |
| **Modify** | Edit `.md` files | Users can edit the markdown or frontmatter directly in the filesystem [toolbox/mdcode/demo/README.md:155-159](). |
| **Cleanup** | `bun cleanup.ts` | Deletes the Entry Group [toolbox/mdcode/demo/README.md:165-171](). |

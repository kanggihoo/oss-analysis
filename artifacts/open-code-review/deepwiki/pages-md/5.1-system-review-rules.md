The **System Review Rules** subsystem provides a flexible, pattern-based mechanism for defining language-specific and path-specific review checklists. By mapping file glob patterns to specific natural language instructions, OpenCodeReview ensures that the LLM applies relevant scrutiny to different parts of a codebase—such as checking for memory leaks in C/C++ code, identifying SQL injection in MyBatis XML mappers, or enforcing null-safety in Kotlin.

## Core Logic and Data Structures

The system is centered around the `SystemRule` struct, which maintains an ordered list of patterns and a default fallback rule.

### Data Model
- **`SystemRule`**: The root configuration object. It contains a `DefaultRule` string and an ordered slice of `PathRules` [internal/config/rules/system_rules.go:27-30]().
- **`PathRule`**: A single pattern-to-rule entry that preserves declaration order [internal/config/rules/system_rules.go:21-24]().
- **`Resolver` Interface**: Defines the contract for resolving a review rule for a file path [internal/config/rules/system_rules.go:16-18]().

### Ordered Pattern Matching
The system preserves the order of rules defined in the JSON configuration. This is critical because the **first match wins** [internal/config/rules/system_rules.go:127-135](). If a file path matches multiple patterns, the rule appearing earlier in the `path_rule_map` is selected.

### JSON Deserialization
Standard Go JSON unmarshaling into maps does not guarantee key order. To solve this, `SystemRule` implements a custom `UnmarshalJSON` method [internal/config/rules/system_rules.go:33-81](). It uses a `json.Decoder` with a streaming approach to capture the keys from the `path_rule_map` object in the exact order they appear in the source JSON [internal/config/rules/system_rules.go:53-79]().

## Pattern Matching and Brace Expansion

The system supports advanced globbing via the `doublestar` library, including recursive directory matching with `**`. Additionally, it implements a custom `expandBraces` function to support comma-separated lists within patterns [internal/config/rules/system_rules.go:154-175]().

- **Recursive Matching**: `**/*.java` matches any Java file in any subdirectory [internal/config/rules/system_rules.json:11]().
- **Brace Expansion**: Patterns like `**/*.{yaml,yml}` are expanded into two distinct patterns: `**/*.yaml` and `**/*.yml` [internal/config/rules/system_rules.go:151-153]().

**Brace Expansion Logic**
The `expandBraces` function identifies the first occurrence of `{` and `}`, splits the content by commas, and generates a list of strings by applying the prefix and suffix to each option [internal/config/rules/system_rules.go:154-175]().

Sources: [internal/config/rules/system_rules.go:127-175](), [internal/config/rules/system_rules_test.go:10-41]()

## Loading Rules

Rules are loaded from embedded defaults or project-specific files. The system uses a `NewResolver` to prioritize rules from the repository level before falling back to system defaults.

| Method | Source | Description |
| :--- | :--- | :--- |
| `LoadDefault()` | Embedded Binary | Parses `system_rules.json` and associated docs from the embedded `rulesFS` [internal/config/rules/system_rules.go:87-109](). |
| `NewResolver(repoDir, customPath)` | Filesystem | Merges project-level rules from `<repoDir>/.opencodereview/rule.json` with system defaults [internal/config/rules/system_rules_test.go:182-237](). |

The embedded rules are defined using the `//go:embed` directive, which includes both the mapping JSON and the markdown documentation files in `rule_docs/` [internal/config/rules/system_rules.go:83-84]().

Sources: [internal/config/rules/system_rules.go:83-109](), [internal/config/rules/system_rules_test.go:206-237]()

## Built-in Review Checklists

The default `system_rules.json` contains specialized checklists for various languages and configuration formats.

### Key Language Rules
- **Java (`**/*.java`)**: Focuses on logical errors (NPEs, loop conditions), performance (N+1 queries, DB in loops), and thread safety (race conditions, atomic operations) [internal/config/rules/rule_docs/java.md:1-42]().
- **C/C++ (`**/*.{cpp,cc,hpp,c}`)**: Targets memory management (`malloc/free` pairing), RAII principles, buffer overflow protection, and smart pointer usage [internal/config/rules/rule_docs/c.md:5-50](), [internal/config/rules/rule_docs/cpp.md:10-33]().
- **Kotlin (`**/*.kt`)**: Emphasizes null safety (avoiding `!!`), coroutine management, and idiomatic collection operations (e.g., `asSequence`) [internal/config/rules/rule_docs/kotlin.md:1-82]().
- **SQL/MyBatis (`**/*{mapper,dao}*.xml`)**: Specifically flags SQL injection risks (misuse of `${}`), full table scan risks, and JOIN condition logic [internal/config/rules/rule_docs/mapper_dao_xml.md:6-34]().

### Configuration Rules
- **Dependency Managers**: 
    - **`pom.xml`**: Flags `SNAPSHOT` versions for production environments [internal/config/rules/rule_docs/pom_xml.md:1]().
    - **`build.gradle`**: Recommends specific version numbers over snapshots [internal/config/rules/rule_docs/build_gradle.md:1]().
    - **`package.json`**: Flags `latest` or `*` version ranges [internal/config/rules/rule_docs/package_json.md:1]().
- **Data Formats**:
    - **JSON/YAML**: Checks for key spelling errors and configuration best practices [internal/config/rules/rule_docs/json.md:1](), [internal/config/rules/rule_docs/yaml.md:1]().

## Usage in the Review Agent

The `Agent` utilizes these rules during the review process to augment the prompt for each file. When the agent prepares a subtask for a specific file, it calls `Resolve(path)` to retrieve the specific checklist. This checklist is then injected into the LLM's context.

Additionally, the `FileFilter` struct uses the same `expandBraces` and `doublestar` logic to determine if a file should be included or excluded based on user configuration in `rule.json` [internal/config/rules/system_rules.go:192-232]().

Sources: [internal/config/rules/system_rules.go:127-137](), [internal/config/rules/system_rules.go:203-232]()

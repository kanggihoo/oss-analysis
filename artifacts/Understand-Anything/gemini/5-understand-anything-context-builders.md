# Understand Anything 스킬 컨텍스트 빌더 상세 가이드

`understand-anything-plugin/src/` 디렉토리 아래의 TypeScript 모듈들은 `/understand`가 빌드해 놓은 지식 그래프(`.understand-anything/knowledge-graph.json`)를 활용하여 대화, 변경 영향도 분석, 심층 코드 설명, 온보딩 가이드 생성 등의 세부 스킬에 필요한 구체적 데이터 컨텍스트를 설계하고 조립하는 역할을 수행합니다.

---

## 1. 개요 및 설계 사상

스킬 컨텍스트 빌더들은 직접 소스 코드를 새로 구문 분석하는 대신, 이미 빌드된 그래프의 노드와 엣지망을 메모리에 적재하여 타겟 쿼리나 Git diff 지점 주변의 서브그래프를 추출합니다.
* **1-hop 확장(1-hop Expansion)**: 특정 노드(수정된 파일, 질문에 부합하는 함수 등)가 감지되면 해당 노드와 직접 선(Edge)으로 연결된 주변 노드 목록(1-hop neighbors)까지 함께 컨테이너 패키징하여 LLM 프롬프트에 제공함으로써 관계적 맥락을 상실하지 않게 돕습니다.
* **의미적 정제 및 정렬**: 수집된 서브그래프를 사람이 읽을 수 있는 마크다운 보고서로 가공하거나, LLM이 오답(Hallucination) 없이 Grounded 답변을 하도록 돕는 고밀도 프롬프트 데이터셋으로 구조화합니다.

---

## 2. 챗 컨텍스트 빌더 (`context-builder.ts`)

자연어 질문과 지식 그래프의 중간 가교 역할을 수행하는 **`ChatContext`** 클래스가 핵심 모듈입니다.

### 세부 동작 및 흐름
* 사용자의 자연어 쿼리 질문을 수신하면 `@understand-anything/core`에 설계된 Fuzzy Search(Fuse.js) 및 Semantic Search(Embedding 기반 Cosine 유사도 분석) 엔진을 기동시켜 질문과 관련도가 높은 핵심 노드(GraphNode) 목록을 1차 선별합니다.
* 1차 매칭된 노드들을 기준으로 이들과 직접 연결(imports, calls, depends_on 등)을 가진 인접 엣지 및 1-hop 노드들을 순회 수집하여 서브그래프 맥락을 확장합니다.
* 완성된 컨텍스트 스냅샷(Context Graph Snapshot)을 Q&A LLM 프롬프트의 Context 영역에 주입하여, 플러그인이 사용자의 질문에 대해 정확한 파일 경로와 함수 호출 관계를 근거로 답변할 수 있게 지원합니다.

## 3. 변경 영향도 분석기 (`diff-analyzer.ts`)

Git의 변경 사항(diff)이나 PR을 조회하여 프로젝트 전반의 폭발 반경(Blast Radius)과 리스크 수준을 평가하는 **`DiffContext`**를 구축합니다.

### 감출 및 식별 정보
* **changedNodeIds**: 직접 수정이 일어난 소스 파일 노드 및 해당 파일 내부에 정의된 함수, 클래스 노드들의 고유 ID 세트입니다.
* **affectedNodeIds**: 수정된 노드들과 직접적인 연결고리(Imports, Calls 등)를 가져 영향을 주고받는 1-hop 주변 노드들의 고유 ID 세트입니다.
* **affectedLayers**: 변경 사항 또는 영향 범위에 속한 파일들이 귀속되어 있는 아키텍처 레이어 목록입니다.
* **impactedEdges**: 수정 지점과 영향을 받는 구성 요소 사이를 흐르는 의존성 엣지들의 리스트입니다.
* **unmappedFiles**: Git 수정 목록에는 존재하나 정적 분석ignore 규칙 등으로 인해 지식 그래프 노드에 수록되지 않은 예외 파일 목록입니다.

### 마크다운 요약본 생성 (`formatDiffAnalysis`)
위 수치들을 종합하여 사람이 파악하기 좋은 마크다운 형식 보고서를 동적 빌드합니다.
* 수정 요소 및 파급 요소의 등급별 노출.
* 수정 범위 내에 복잡도가 높은 컴포넌트(`complexity: "complex"`)가 포함되었거나, 레이어 경계를 뛰어넘어 아키텍처 규정을 해치는 불법 참조 관계가 엮였는지 여부를 대조하여 최종 위험도 등급(Risk Assessment)을 종합 판정하여 리포트합니다.

## 4. 설명 빌더 (`explain-builder.ts`)

특정 파일이나 개별 모듈, 혹은 특정 함수 명칭이 주어졌을 때 이에 대해 막힘없이 해설할 수 있도록 컨텍스트를 조립하는 **`ExplainContext`** 모듈입니다.
* 사용자가 지정한 타겟 검색어(예: `src/auth/login.ts` 또는 특정 클래스의 `verify` 메서드)로 그래프 노드를 스캔합니다.
* 해당 대상 노드와 사슬처럼 얽힌 인접 에지 목록(호출하는 함수들, 호출되는 함수들, 의존 파일들)을 찾아내어 주변 환경을 정밀하게 복사합니다.
* 소속 아키텍처 레이어의 이름과 아키텍처 레이어의 명세 요약을 함께 로드하여 고수준 설계 의도를 확보합니다.
* 로컬 파일 시스템에서 대상 노드가 나타내는 실제 소스 파일의 raw code 본문을 직접 발췌하여 취합합니다.
* 수집된 소스 코드 본문, 소속 레이어의 아키텍처 가이드라인, 인접 호출 관계망 정보가 하나로 결합하여 설명 생성용 LLM 프롬프트를 구성합니다.

## 5. 온보딩 가이드 빌더 (`onboard-builder.ts`)

신규 프로젝트 참가자를 위해 코드 아키텍처 가이드를 표준 마크다운 형식으로 자동 구성해 내는 **`buildOnboardingGuide`** API를 구현하고 있습니다.

### 온보딩 문서 조립 레이아웃
1. **프로젝트 개요 (Overview)**: 프로젝트 메타데이터에서 이름, 소개 설명, 사용 언어 비율, 탐색된 프레임워크 기술셋, 분석 완료 날짜 및 노드/엣지 통계를 추출해 요약 표로 렌더링합니다.
2. **아키텍처 계층 설명 (Architecture Layers)**: 아키텍처 레이어 정의를 순회하며 계층별 책임 설명 및 계층에 귀속되는 대표 핵심 컴포넌트 파일들의 목록을 나열합니다.
3. **핵심 설계 개념 (Key Concepts)**: 그래프 노드 중 `"concept"` 타입에 해당하는 주요 패턴(예: 이벤트 아키텍처, 인증 로직 개념 등)의 개요와 요약을 제공합니다.
4. **학습 투어 가이드 (Guided Tour)**: 아키텍처 투어(`tour`) 리스트를 차례대로 순회하며, 추천 학습 단계 이름, 세부 가이드 문장 및 단계별로 먼저 열어서 읽어보아야 할 추천 소스 파일 링크들을 연결해 줍니다.
5. **파일 맵 (File Map)**: 전체 코드 노드를 테이블화하여 파일명, 담당 기능 요약, 소스 복잡도 정보를 직관적으로 펼쳐 보여줍니다.
6. **복잡도 핫스팟 (Complexity Hotspots)**: 복잡도가 `"complex"`로 등재된 핵심 고난도 소스 파일 목록을 별도로 격리 표시하여 분석 시 주의를 집중하도록 안내합니다.

## 6. 대화형 인터페이스 연결 (`understand-chat.ts`)

대화형 질의응답 스킬인 `/understand-chat` 명령어의 백엔드 컨트롤러 스크립트 역할을 수행합니다.
* 사용자가 채팅창에 입력한 의도를 파악하고, `ChatContext` 인스턴스를 기동해 질문의 타겟 키워드와 주변 1-hop 의존 노드를 실시간으로 긁어옵니다.
* 추출한 서브그래프를 텍스트 프롬프트 형태로 안전하게 직렬화(Serialize)하여 Q&A LLM 모델에 전달합니다.
* 이를 통해 대화 모델이 단순히 사전에 축적된 가중치 지식에 의존해 그럴듯한 답변을 하는 대신, 제공된 최신 로컬 의존 그래프 스냅샷을 팩트로 삼아 실제 파일 명칭과 호출선 정보를 명시하며 대답하도록 Grounding 구조를 조율합니다.

This page documents the core state management implementation of the Understand Anything dashboard located in the `@understand-anything/dashboard` package. The dashboard leverages Zustand to define a centralized reactive store encapsulating the UI state, graph data, navigation logic, filtering preferences, and search functionality. This page covers the key features of the `useDashboardStore` Zustand store, including:

- Graph loading and indexing (`setGraph`)
- Navigation, node selection, and layered drill-down (`selectNode`, `drillIntoLayer`, `nodeHistory`)
- Persona filtering (user expertise levels)
- Detail level toggling for graph views (file-level vs. class-level)
- Focus mode to isolate code neighborhoods
- Integration of diff overlay state
- Search integration via the `SearchEngine` and `SemanticSearchEngine` subsystems.

---

## 1. Purpose and Scope

The `useDashboardStore` Zustand store acts as the single source of truth for the dashboard's state. It manages the loaded knowledge graph data, indexes it for efficient lookups, tracks the current node selection and navigation context, controls UI panels and modes (e.g., focus mode, detail level), and manages filtering and search modes. It also integrates with the embedded search engines to provide both fuzzy and semantic search capabilities.

This page explains the key functions, state fields, and mechanisms by which the dashboard maintains and updates this state, supporting the interactive graph exploration and filtering features exposed in the UI.

## 2. Store Structure and Core Data

### 2.1 Graph Data and Indexing

- `graph` holds the current `KnowledgeGraph` object or null if none loaded.
- Indexed caches rebuilt on every `setGraph` call:
  - `nodesById`: `Map<string, GraphNode>` for efficient node lookup by ID.
  - `nodeIdToLayerId`: `Map<string, string>` mapping node IDs to a single primary layer ID (first matching layer).
  - `nodeIdToLayerIds`: `Map<string, Set<string>>` mapping node IDs to all layers they appear in.

Building these indexes supports rapid node retrieval and layer membership queries for filtering and navigation.

```ts
function buildGraphIndexes(graph: KnowledgeGraph): {
  nodesById: Map<string, GraphNode>;
  nodeIdToLayerId: Map<string, string>;
  nodeIdToLayerIds: Map<string, Set<string>>;
} {
  const nodesById = new Map<string, GraphNode>();
  for (const node of graph.nodes) nodesById.set(node.id, node);
  const nodeIdToLayerId = new Map<string, string>();
  const nodeIdToLayerIds = new Map<string, Set<string>>();
  for (const layer of graph.layers) {
    for (const nid of layer.nodeIds) {
      if (!nodeIdToLayerId.has(nid)) nodeIdToLayerId.set(nid, layer.id);
      let set = nodeIdToLayerIds.get(nid);
      if (!set) {
        set = new Set<string>();
        nodeIdToLayerIds.set(nid, set);
      }
      set.add(layer.id);
    }
  }
  return { nodesById, nodeIdToLayerId, nodeIdToLayerIds };
}
```

### 2.2 Core State Fields

- `selectedNodeId`: currently selected graph node or null.
- `nodeHistory`: array of visited node IDs, capped at 50 entries.
- `navigationLevel`: `"overview"` or `"layer-detail"`, controlling dashboard lens depth.
- `activeLayerId`: the layer currently drilled into.
- `persona`: user filtering preference among `"non-technical"`, `"junior"`, `"experienced"`.
- `detailLevel`: display detail level with `"file"` or `"class"`.
- `focusNodeId`: optionally isolate a node's 1-hop neighborhood when set.
- `diffMode`, `changedNodeIds`, `affectedNodeIds`: manages diff overlay highlighting.

### 2.3 Filter State and Node Category Toggling

The store maintains a rich filter state including:

- Node types, complexities, layers, and edge categories represented as sets.
- Category-based toggles for node types to simplify filtering UI:
  
```ts
nodeTypeFilters: Record<NodeCategory, boolean>;
toggleNodeTypeFilter: (category: NodeCategory) => void;
```

## 3. Key Actions and Functions

### 3.1 Loading and Setting Graph Data: `setGraph`

The `setGraph` action replaces the entire knowledge graph, rebuilding all internal indexes:

- Calls `buildGraphIndexes` to update caches: `nodesById`, `nodeIdToLayerId`, and `nodeIdToLayerIds`.
- Resets selection, history, active layer, filters, diffs, and search engine instances.
- Properly initializes the fuzzy and semantic `SearchEngine` instances with the new graph.

This permits clean reinitialization on new graph loads or refreshes.

### 3.2 Navigation, Selection, and History

- `selectNode(nodeId: string | null)`: sets the current node selection.
- `navigateToNode(nodeId: string)`: navigates to the given node. Internally calls `navigateToNodeInLayer`.
- `navigateToNodeInLayer(nodeId: string)`: determines which layer the node belongs to via `nodeIdToLayerId`, sets `activeLayerId` accordingly, sets `navigationLevel` to `"layer-detail"`, and selects the node.

The store maintains `nodeHistory` as a stack of previous visited nodes with methods to backtrack history (`goBackNode`) and directly navigate history items (`navigateToHistoryIndex`).

### 3.3 Drilling Into and Navigating Layers

Drilling into a layer zooms the graph view to that layer's details:

- `drillIntoLayer(layerId: string)`: sets `activeLayerId` and navigation level to `"layer-detail"`.
- `navigateToOverview()`: resets navigation level to `"overview"` and `activeLayerId` to null.

### 3.4 Persona Filtering

The store tracks the `persona` state:

- Three levels: `"non-technical"`, `"junior"`, `"experienced"`.
- Components use this to filter displayed content or tune UI explanations.
- Action `setPersona` updates the persona state.

### 3.5 Detail Level: File vs. Class

Dashboard offers two detail levels for representing code:

- `"file"`: default architecture-level view showing only file nodes.
- `"class"`: code-structure-level view showing classes and optionally functions.

State fields:

- `detailLevel`: current level.
- `showFunctionsInClassView`: boolean toggle for function expansion within classes.
- Actions `setDetailLevel` and `toggleShowFunctionsInClassView` control these settings.

### 3.6 Focus Mode

- `focusNodeId` holds the ID of a node for isolating a 1-hop neighborhood view.
- Enabling focus mode helps isolate the selected node's immediate code context.
- `setFocusNode` clears or sets this state.

### 3.7 Diff Overlay State

Supports visualization of code changes overlay:

- `diffMode`: toggle overlay on/off.
- `changedNodeIds` and `affectedNodeIds`: sets of node IDs that changed or are affected transitively.
- Related actions for toggling and clearing diffs.

### 3.8 Search Integration

- `searchQuery`: current search string.
- `searchResults`: current results (typed as `SearchResult[]`).
- `searchMode`: `"fuzzy"` or `"semantic"`.
- `searchEngine`: an instance of either `SearchEngine` or `SemanticSearchEngine`.
- `setSearchMode` swaps between search modes, reinitializing the engine.
- Search updates update `searchResults` based on query and mode.

The store wires the semantic search backend and manages fallback between fuzzy and semantic results in the UI.

## 5. Detailed Function Descriptions

### 5.1 `setGraph(graph: KnowledgeGraph)`

- Resets the entire graph state used throughout the dashboard.
- Calls `buildGraphIndexes(graph)` to generate efficient lookups.
- Initializes the search engines with the new graph data.
- Resets filters, selections, navigation, and diff states.
- Enables UI to react to the new graph data immediately.

### 5.2 `drillIntoLayer(layerId: string)`

- Changes the lens focus to a specific code layer.
- Sets `activeLayerId` to the target and `navigationLevel` to `"layer-detail"`.
- Allows users to drill down from overview into detailed layer contents.

### 5.3 `selectNode(nodeId: string | null)`

- Updates `selectedNodeId` to reflect current user selection.
- Also appends to `nodeHistory`, bounded by `MAX_HISTORY = 50` entries.
- Clears focus if selecting null.

### 5.4 `nodeHistory` and Navigation Backwards

- `nodeHistory` records a history stack of visited nodes (IDs).
- `goBackNode()` pops the most recent node and re-selects the previous.
- `navigateToHistoryIndex(index: number)` jumps to a specific entry.

### 5.5 `setPersona(persona: Persona)`

- Filters displayed nodes or content according to user expertise.
- Used to toggle visibility or complexity of node renderings.

### 5.6 `setDetailLevel(level: DetailLevel)` and `toggleShowFunctionsInClassView()`

- Allows toggling between "file" overview and more detailed "class" view.
- Optionally shows functions under classes when detail level is class.

### 5.7 Focus Mode State Management

- `focusNodeId` isolates the graph visualization to a single node and immediate neighbors.
- Used for in-depth exploration of particular code regions.

### 5.8 Search Integration and Wiring

- Initially sets `searchEngine` to an instance of `SearchEngine` (for fuzzy).
- Can switch to `SemanticSearchEngine` for cosine similarity on embeddings.
- `searchQuery` updates initiate searches, populating `searchResults`.
- Results update triggers UI highlights and selection logic.

## 7. Summary

The dashboard's Zustand store (`useDashboardStore`) provides a comprehensive and performant state management backbone:

- Efficient graph indexing and caching for fast node lookup and layer determination.
- Rich navigation and history management to support drill-down and focus.
- Persona-based user filtering to tailor complexity and explanations.
- Detail level toggling for coarse or fine code views.
- Diff overlay state to visualize code changes clearly.
- Dual-mode search integration wired for both fuzzy and semantic embeddings.
- Centralized UI state for code viewer and panel toggles.

This design enables the dashboard components (graph view, search bar, filters, file explorer, persona selector, etc.) to reactively and synchronously reflect user actions and backend data, seamlessly guiding exploration of large knowledge graphs.

This page provides a concise reference for all user-facing slash commands (skills) available in the Understand Anything plugin. Each skill's purpose, arguments, flags, and expected outputs are detailed. Technical implementation notes, data flow, and key functions/classes are included to provide a comprehensive understanding for developers.

## `/understand`

Analyzes a codebase to produce an interactive knowledge graph for understanding architecture, components, and relationships. This is the core skill that generates the primary data structure for many other skills.

### Arguments and Flags

*   `[path]` (optional): A directory path (e.g., `/path/to/repo` or `../other-project`) to analyze instead of the current working directory.
*   `--full`: Forces a full rebuild, ignoring any existing graph.
*   `--auto-update`: Enables automatic graph updates on commit (writes `autoUpdate: true` to `.understand-anything/config.json`).
*   `--no-auto-update`: Disables automatic graph updates (writes `autoUpdate: false` to `.understand-anything/config.json`).
*   `--review`: Runs a full LLM graph-reviewer instead of inline deterministic validation.
*   `--language <lang>`: Generates all textual content (summaries, descriptions, tags, titles, languageNotes, languageLesson) in the specified language. Accepts ISO 639-1 codes (e.g., `zh`, `ja`, `ko`, `en`, `es`, `fr`, `de`) or friendly names (e.g., `chinese`, `japanese`, `korean`, `english`, `spanish`). Locale variants like `zh-TW`, `zh-HK` are supported. Defaults to `en` (English). This preference is stored in `.understand-anything/config.json`.

### Expected Output

The primary output is a `knowledge-graph.json` file located in the `.understand-anything/` directory within the project root. This file contains nodes, edges, layers, and tour steps representing the codebase's structure and relationships.

### Implementation Details

The `/understand` skill is a multi-phase process orchestrated by a shell script [understand-anything-plugin/skills/understand/SKILL.md]().

#### Phase 0: Pre-flight

This phase determines the `PROJECT_ROOT` and ensures the plugin is built.
1.  **Resolve `PROJECT_ROOT`**:
    *   If a path argument is provided, it's resolved to an absolute path.
    *   If no path is provided, the current working directory is used.
    *   **Worktree Redirect**: The script checks if `PROJECT_ROOT` is inside a Git worktree by comparing `git rev-parse --git-dir` and `git rev-parse --git-common-dir`. If it's a worktree, the `PROJECT_ROOT` is redirected to the main repository root to prevent ephemeral graph data [understand-anything-plugin/skills/understand/SKILL.md:53-70](). This behavior can be overridden by setting `UNDERSTAND_NO_WORKTREE_REDIRECT=1`.
2.  **Ensure Plugin Build**: The script verifies that `packages/core/dist/index.js` exists. If not, it runs `pnpm install` and `pnpm --filter @understand-anything/core build` to compile the core library [understand-anything-plugin/skills/understand/SKILL.md:116-117](). The `PLUGIN_ROOT` is resolved through a series of candidate paths to handle various installation scenarios [understand-anything-plugin/skills/understand/SKILL.md:88-99]().

#### Phase 1: Project Scanning & File Discovery

This phase identifies all relevant files in the project.
1.  **File Enumeration**: The `scan-project.mjs` script is executed to discover files, apply `.understandignore` rules, and detect languages [understand-anything-plugin/skills/understand/SKILL.md:129-130]().
2.  **Import Map Generation**: `extract-import-map.mjs` uses Tree-sitter to generate an import map for each file, which is crucial for resolving cross-file dependencies [understand-anything-plugin/skills/understand/SKILL.md:131-132]().

#### Phase 2: File Analysis & Batch Processing

This phase processes files in batches to extract structural and semantic information.
1.  **Batch Computation**: `compute-batches.mjs` divides the discovered files into batches, considering token limits and file categories [understand-anything-plugin/skills/understand/SKILL.md:140-141]().
2.  **Parallel Analysis**: Each batch is dispatched to a `file-analyzer` agent. The agent's task is to read source files and produce structured knowledge graph data (nodes and edges) [understand-anything-plugin/agents/file-analyzer.md:9-11]().
    *   **Structural Extraction**: The `file-analyzer` executes a bundled `extract-structure.mjs` script. This script uses Tree-sitter for code files and specialized parsers for non-code files to deterministically extract structural data [understand-anything-plugin/agents/file-analyzer.md:28-30, 67-74](). The output is a JSON object containing functions, classes, exports, call graphs, and metrics [understand-anything-plugin/agents/file-analyzer.md:83-117](). For non-code files, it extracts definitions, services, endpoints, steps, and resources [understand-anything-plugin/agents/file-analyzer.md:121-128]().
    *   **LLM Semantic Analysis**: After structural extraction, the `file-analyzer` applies expert judgment to generate summaries, tags, complexity ratings, and semantic edges. It uses `neighborMap` for cross-batch context to improve confidence in cross-batch edges [understand-anything-plugin/agents/file-analyzer.md:55-62]().
3.  **Batch Merging**: `merge-batch-graphs.py` combines the results from all batches into a single `assembled-graph.json` file. This script normalizes IDs, complexity values, and cleans edges [understand-anything-plugin/skills/understand/merge-batch-graphs.py:3-8](). It handles ID canonicalization (e.g., `func:` to `function:`) and deduplicates nodes and edges [understand-anything-plugin/skills/understand/merge-batch-graphs.py:178-199, 202-210]().

#### Phase 3: Graph Assembly & Validation

This phase refines and validates the assembled graph.
1.  **Semantic Recovery**: The `assemble-reviewer` agent reviews the `assembled-graph.json` for semantic issues that the deterministic scripts cannot catch [understand-anything-plugin/skills/understand/SKILL.md:159-160]().
2.  **Referential Integrity**: `graph-reviewer` performs checks to ensure the graph's consistency.

#### Phase 4: Architecture Analysis & Tour Building

This phase adds architectural layers and guided tours to the graph.
1.  **Layer Assignment**: The `architecture-analyzer` agent assigns nodes to architectural layers based on heuristics like `intraGroupDensity` and `interGroupImports` [understand-anything-plugin/skills/understand/SKILL.md:167-168]().
2.  **Tour Generation**: The `tour-builder` agent generates a guided learning path (tour) using BFS and fan-in ranking [understand-anything-plugin/skills/understand/SKILL.md:169-170]().

#### Phase 5: Finalization

This phase merges subdomain graphs and saves the final knowledge graph.
1.  **Subdomain Merging**: `merge-subdomain-graphs.py` merges any subdomain knowledge graphs (e.g., from `/understand-domain` or `/understand-knowledge`) into the main `knowledge-graph.json` [understand-anything-plugin/skills/understand/merge-subdomain-graphs.py:3-8](). It deduplicates nodes and edges, merges layers by ID, and concatenates tour steps [understand-anything-plugin/skills/understand/merge-subdomain-graphs.py:64-157]().
2.  **Save Graph**: The final `knowledge-graph.json` is saved.

#### Progress Reporting

The skill provides detailed progress updates to the user, including phase transitions and batch processing status [understand-anything-plugin/skills/understand/SKILL.md:23-37]().

#### GraphBuilder Class

The `GraphBuilder` class [understand-anything-plugin/packages/core/src/analyzer/graph-builder.ts:60-60]() is central to constructing the knowledge graph. It provides methods to add various types of nodes and edges:
*   `addFile(filePath: string, meta: FileMeta)`: Adds a file node [understand-anything-plugin/packages/core/src/analyzer/graph-builder.ts:84-102]().
*   `addFileWithAnalysis(filePath: string, analysis: StructuralAnalysis, meta: FileAnalysisMeta)`: Adds a file node along with its contained functions and classes, creating `contains` edges [understand-anything-plugin/packages/core/src/analyzer/graph-builder.ts:105-177]().
*   `addImportEdge(fromFile: string, toFile: string)`: Adds an `imports` edge between files [understand-anything-plugin/packages/core/src/analyzer/graph-builder.ts:179-190]().
*   `addCallEdge(callerFile: string, callerFunc: string, calleeFile: string, calleeFunc: string)`: Adds a `calls` edge between functions [understand-anything-plugin/packages/core/src/analyzer/graph-builder.ts:192-208]().
*   `addNonCodeFile(filePath: string, meta: NonCodeFileMeta)`: Adds a non-code file node [understand-anything-plugin/packages/core/src/analyzer/graph-builder.ts:210-225]().
*   `addNonCodeFileWithAnalysis(filePath: string, meta: NonCodeFileAnalysisMeta)`: Adds a non-code file node and its child nodes (definitions, services, endpoints, steps, resources), creating `contains` edges [understand-anything-plugin/packages/core/src/analyzer/graph-builder.ts:228-270]().

The `GraphBuilder` also handles language detection [understand-anything-plugin/packages/core/src/analyzer/graph-builder.ts:77-79]() and ensures unique node and edge IDs [understand-anything-plugin/packages/core/src/analyzer/graph-builder.ts:64-66]().

## `/understand-dashboard`

Launches an interactive visualization dashboard for exploring the project's knowledge graph.

### Arguments and Flags

None explicitly documented in the provided `SKILL.md` for `/understand-dashboard`. It is typically invoked after `/understand` has generated a `knowledge-graph.json`.

### Expected Output

Opens a web-based dashboard in the user's browser, displaying the knowledge graph.

### Implementation Details

The dashboard is a React-based application that reads the `knowledge-graph.json` file. It uses a Vite dev server with a data API middleware to serve the graph data.

## `/understand-chat`

Answers questions about a codebase using the generated knowledge graph.

### Arguments and Flags

*   `[query]`: The natural language question about the codebase.

### Expected Output

A natural language answer to the user's query, referencing specific files, functions, relationships, and architectural layers from the knowledge graph.

### Implementation Details

The `/understand-chat` skill operates by querying the `knowledge-graph.json` file.
1.  **Prerequisite Check**: Verifies the existence of `.understand-anything/knowledge-graph.json`. If not found, it instructs the user to run `/understand` first [understand-anything-plugin/skills/understand-chat/SKILL.md:34-35]().
2.  **Project Metadata**: Extracts the `project` section (name, description, languages, frameworks) from the graph for context [understand-anything-plugin/skills/understand-chat/SKILL.md:37-38]().
3.  **Node Search**: Uses `grep` to search the knowledge graph for keywords from the user's query within node `name`, `summary`, and `tags` fields [understand-anything-plugin/skills/understand-chat/SKILL.md:41-43]().
4.  **Edge Traversal (1-hop)**: For each matching node ID, it searches the `edges` section to find connected nodes (both upstream and downstream dependencies), forming a 1-hop subgraph [understand-anything-plugin/skills/understand-chat/SKILL.md:45-48]().
5.  **Layer Context**: Identifies which architectural layers the matched nodes belong to by searching the `layers` section [understand-anything-plugin/skills/understand-chat/SKILL.md:50-51]().
6.  **Answer Generation**: Constructs an answer using the relevant subgraph, explaining relationships, architectural context, and linking concepts to code locations. If no matches are found, it informs the user and suggests related terms [understand-anything-plugin/skills/understand-chat/SKILL.md:53-56]().

## `/understand-diff`

Analyzes Git diffs or pull requests to understand changes, affected components, and risks.

### Arguments and Flags

None explicitly documented in the provided `SKILL.md`. The skill implicitly uses the current Git state.

### Expected Output

A structured analysis of changes, including:
*   **Changed Components**: Directly modified components with summaries.
*   **Affected Components**: Components impacted by the changes (1-hop dependencies).
*   **Affected Layers**: Architectural layers touched by the changes.
*   **Risk Assessment**: Based on complexity, cross-layer edges, and blast radius.
*   A `diff-overlay.json` file in `.understand-anything/` for dashboard visualization.

### Implementation Details

The `/understand-diff` skill leverages the existing `knowledge-graph.json` and Git information.
1.  **Prerequisite Check**: Ensures `knowledge-graph.json` exists, prompting the user to run `/understand` if not [understand-anything-plugin/skills/understand-diff/SKILL.md:33-34]().
2.  **Changed Files List**: Determines changed files using Git commands:
    *   `git diff --name-only` for uncommitted changes.
    *   `git diff main...HEAD --name-only` for feature branches.
    *   Retrieves diff from a specified PR number [understand-anything-plugin/skills/understand-diff/SKILL.md:36-38]().
3.  **Project Metadata**: Extracts the `project` section from the graph for context [understand-anything-plugin/skills/understand-diff/SKILL.md:40-41]().
4.  **Changed Nodes**: For each changed file path, it searches the knowledge graph for nodes with matching `filePath` values (file-level, function, and class nodes). The `id` values of these nodes are collected as `changedNodeIds` [understand-anything-plugin/skills/understand-diff/SKILL.md:43-47]().
5.  **Affected Edges (1-hop)**: For each `changedNodeId`, it searches the `edges` section to find incoming and outgoing connections. This identifies upstream callers and downstream dependencies, which are considered "affected components" [understand-anything-plugin/skills/understand-diff/SKILL.md:49-52]().
6.  **Affected Layers**: It searches the `layers` section for the `changedNodeIds` to determine which architectural layers are impacted [understand-anything-plugin/skills/understand-diff/SKILL.md:54-55]().
7.  **Structured Analysis**: Generates a detailed analysis report covering changed components, affected components, affected layers, and a risk assessment based on node `complexity`, cross-layer edges, and the number of affected components [understand-anything-plugin/skills/understand-diff/SKILL.md:57-60]().
8.  **Diff Overlay Output**: Writes a `diff-overlay.json` file containing `changedFiles`, `changedNodeIds`, and `affectedNodeIds`. This file is used by the dashboard for visual representation of the diff [understand-anything-plugin/skills/understand-diff/SKILL.md:62-71](). The user is then informed that they can use `/understand-anything:understand-dashboard` to visualize the diff.

## `/understand-explain`

Provides a deep-dive explanation of a specific file, function, or module in the codebase.

### Arguments and Flags

*   `[file-path]`: The path to the file, or a file path with a function/class name (e.g., `src/auth/login.ts:verifyToken`).

### Expected Output

A thorough, in-depth explanation of the specified code component, including its role, internal structure, external connections, data flow, and any notable patterns or complexities.

### Implementation Details

The `/understand-explain` skill relies on the `knowledge-graph.json` and direct file content.
1.  **Prerequisite Check**: Verifies the existence of `.understand-anything/knowledge-graph.json`, prompting the user to run `/understand` if not [understand-anything-plugin/skills/understand-explain/SKILL.md:34-35]().
2.  **Target Node Identification**: Uses `grep` to find the target node in the knowledge graph based on the provided argument. This involves searching `filePath` for file paths or `name` fields (filtered by file path) for functions/classes. The node's `id`, `type`, `summary`, `tags`, and `complexity` are noted [understand-anything-plugin/skills/understand-explain/SKILL.md:37-40]().
3.  **Connected Edges**: Searches the `edges` section for the target node's ID to find all incoming and outgoing connections (e.g., `calls`, `imports`, `depends_on`) [understand-anything-plugin/skills/understand-explain/SKILL.md:42-44]().
4.  **Connected Nodes**: For each connected node ID, it retrieves its `name`, `summary`, and `type` from the `nodes` section to build the component's neighborhood context [understand-anything-plugin/skills/understand-explain/SKILL.md:46-47]().
5.  **Layer Context**: Identifies the architectural layer the target node belongs to and its description by searching the `layers` section [understand-anything-plugin/skills/understand-explain/SKILL.md:49-50]().
6.  **Source File Content**: Reads the actual source file content at the node's `filePath` for detailed analysis [understand-anything-plugin/skills/understand-explain/SKILL.md:52-53]().
7.  **Explanation Generation**: Combines all gathered information to explain the component's role, internal structure, external connections, data flow, and highlights any significant patterns or complexities [understand-anything-plugin/skills/understand-explain/SKILL.md:55-59]().

## `/understand-domain`

Extracts business domain knowledge from a codebase and generates an interactive domain flow graph.

### Arguments and Flags

*   `--full`: Forces a fresh scan even if a `knowledge-graph.json` already exists.

### Expected Output

A `domain-graph.json` file in `.understand-anything/` containing domains, business flows, and process steps, which can be visualized in the dashboard.

### Implementation Details

The `/understand-domain` skill can operate in two modes: deriving from an existing knowledge graph or performing a lightweight scan.
1.  **Phase 0: Resolve `PROJECT_ROOT`**: Similar to `/understand`, it resolves `PROJECT_ROOT` and performs worktree redirection if necessary [understand-anything-plugin/skills/understand-domain/SKILL.md:19-40](). It also resolves the `PLUGIN_ROOT` [understand-anything-plugin/skills/understand-domain/SKILL.md:46-85]().
2.  **Phase 1: Detect Existing Graph**: Checks for `$PROJECT_ROOT/.understand-anything/knowledge-graph.json`.
    *   If it exists AND `--full` is NOT passed, it proceeds to Phase 3 (derive from graph).
    *   Otherwise, it proceeds to Phase 2 (lightweight scan) [understand-anything-plugin/skills/understand-domain/SKILL.md:89-93]().
3.  **Phase 2: Lightweight Scan (Path 1)**:
    *   Executes `extract-domain-context.py` with `PROJECT_ROOT`. This script performs a lightweight scan, generating `domain-context.json` with a file tree, detected entry points, file signatures, code snippets, and project metadata [understand-anything-anything-plugin/skills/understand-domain/extract-domain-context.py:3-8, 99-108]().
    *   The `extract-domain-context.py` script uses `MAX_FILE_TREE_DEPTH`, `MAX_FILES_PER_DIR`, `MAX_FILES_TOTAL`, `MAX_SAMPLED_FILES`, `MAX_LINES_PER_FILE`, `MAX_ENTRY_POINTS`, and `MAX_OUTPUT_BYTES` to control the scope and size of the extracted context [understand-anything-plugin/skills/understand-domain/extract-domain-context.py:26-30](). It also parses `.gitignore` to exclude irrelevant files [understand-anything-plugin/skills/understand-domain/extract-domain-context.py:118-146]().
    *   It then proceeds to Phase 4 [understand-anything-plugin/skills/understand-domain/SKILL.md:109-110]().
4.  **Phase 3: Derive from Existing Graph (Path 2)**:
    *   Reads `$PROJECT_ROOT/.understand-anything/knowledge-graph.json`.
    *   Formats the graph data (nodes, edges, layers, tour steps) as structured context for the domain analyzer [understand-anything-plugin/skills/understand-domain/SKILL.md:114-120]().
    *   It then proceeds to Phase 4 [understand-anything-plugin/skills/understand-domain/SKILL.md:121-122]().
5.  **Phase 4: Domain Analysis**:
    *   Dispatches a `domain-analyzer` subagent with its prompt (`$PLUGIN_ROOT/agents/domain-analyzer.md`) and the context from Phase 2 or 3 [understand-anything-plugin/skills/understand-domain/SKILL.md:125-127]().
    *   The agent writes its output to `$PROJECT_ROOT/.understand-anything/intermediate/domain-analysis.json` [understand-anything-plugin/skills/understand-domain/SKILL.md:128-128]().
6.  **Phase 5: Validate and Save**:
    *   Reads the `domain-analysis.json` output.
    *   Validates it using the standard graph validation pipeline (which supports `domain`, `flow`, `step` node types).
    *   Saves the validated graph to `$PROJECT_ROOT/.understand-anything/domain-graph.json` [understand-anything-plugin/skills/understand-domain/SKILL.md:130-134]().
    *   Cleans up intermediate files [understand-anything-plugin/skills/understand-domain/SKILL.md:135-135]().

## `/understand-knowledge`

This skill is not detailed in the provided `SKILL.md` files, but based on the `merge-subdomain-graphs.py` script, it likely generates a knowledge graph specific to a subdomain or a particular knowledge base (e.g., a wiki).

### Arguments and Flags

Not explicitly documented.

### Expected Output

## `/understand-onboard`

Generates a comprehensive onboarding guide for new team members joining a project.

### Arguments and Flags

None explicitly documented.

### Expected Output

A markdown-formatted onboarding guide, potentially saved to `docs/ONBOARDING.md`.

### Implementation Details

The `/understand-onboard` skill constructs an onboarding guide by extracting information from the `knowledge-graph.json`.
1.  **Prerequisite Check**: Ensures `knowledge-graph.json` exists, prompting the user to run `/understand` if not [understand-anything-plugin/skills/understand-onboard/SKILL.md:32-33]().
2.  **Project Metadata**: Extracts the `project` section (name, description, languages, frameworks) for the overview [understand-anything-plugin/skills/understand-onboard/SKILL.md:35-36]().
3.  **Layers**: Retrieves the `layers` array to define the architectural structure of the guide [understand-anything-plugin/skills/understand-onboard/SKILL.md:38-39]().
4.  **Tour**: Extracts the `tour` section for the guided walkthrough steps [understand-anything-plugin/skills/understand-onboard/SKILL.md:41-42]().
5.  **File-level Nodes**: Uses `grep` to find only file-level nodes (`file`, `config`, `document`, `service`, `pipeline`, `table`, `schema`, `resource`, `endpoint`) to keep the guide high-level. It extracts `name`, `filePath`, `summary`, and `complexity` for these nodes [understand-anything-plugin/skills/understand-onboard/SKILL.md:44-46]().
6.  **Complexity Hotspots**: Identifies nodes with high `complexity` values from the file-level nodes to highlight areas requiring careful attention [understand-anything-plugin/skills/understand-onboard/SKILL.md:48-49]().
7.  **Guide Generation**: Assembles the onboarding guide with sections for Project Overview, Architecture Layers, Key Concepts, Guided Tour, File Map, and Complexity Hotspots, formatted as clean markdown [understand-anything-plugin/skills/understand-onboard/SKILL.md:51-52]().
8.  **Saving and Suggestion**: Offers to save the guide to `docs/ONBOARDING.md` and suggests committing it to the repository [understand-anything-plugin/skills/understand-onboard/SKILL.md:53-54]().

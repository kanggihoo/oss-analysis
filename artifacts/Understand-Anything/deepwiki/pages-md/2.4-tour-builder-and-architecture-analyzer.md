This page details Phases 4 and 5 of the Understand Anything analysis pipeline: Architecture Analysis and Tour Building. The `architecture-analyzer` agent is responsible for assigning nodes to logical architectural layers using heuristics based on intra-group density and inter-group imports. Following this, the `tour-builder` agent generates a guided learning path through the codebase, leveraging Breadth-First Search (BFS) and fan-in ranking to prioritize important nodes.

## Architecture Analyzer (Phase 4)

The `architecture-analyzer` agent identifies logical architectural layers within a codebase and assigns every file to exactly one layer [understand-anything-plugin/agents/architecture-analyzer.md:9-10](). This process is split into two phases: a deterministic script for structural analysis and an LLM-driven phase for semantic interpretation.

### Phase 1: Structural Analysis Script

The first phase involves a script (preferably Node.js, falling back to Python) that analyzes file paths and import edges to compute structural patterns [understand-anything-plugin/agents/architecture-analyzer.md:23-25](). This script performs several deterministic graph analyses:

1.  **Directory Grouping**: Files are grouped by their top-level directory after a common path prefix is removed. If the structure is flat, grouping occurs by file type/extension pattern [understand-anything-plugin/agents/architecture-analyzer.md:54-63]().
2.  **Node Type Grouping**: File node IDs are grouped by their `type` (e.g., `file`, `config`, `document`, `service`) to reveal the distribution of code vs. non-code files [understand-anything-plugin/agents/architecture-analyzer.md:65-68]().
3.  **Import Adjacency Matrix**: An adjacency list is built to show which files import others. This includes calculating fan-out (how many files a node imports) and fan-in (how many files import a node) for each file, and inter-group import relationships for directory groups [understand-anything-plugin/agents/architecture-analyzer.md:70-74]().
4.  **Cross-Category Dependency Analysis**: This identifies relationships between different node type groups (e.g., `config` nodes configuring `file` nodes, `service` nodes deploying `file` nodes) [understand-anything-plugin/agents/architecture-analyzer.md:76-87]().
5.  **Inter-Group Import Frequency**: A matrix is generated showing the number of import edges between every pair of directory groups, indicating dependency direction [understand-anything-plugin/agents/architecture-analyzer.md:89-96]().
6.  **Intra-Group Import Density**: For each directory group, the script calculates the density of import edges within the group compared to total edges involving that group. High intra-group density suggests a cohesive group suitable for its own layer [understand-anything-plugin/agents/architecture-analyzer.md:98-102]().
7.  **Directory Pattern Matching**: Directory names are classified against known architectural patterns (e.g., `routes` -> `api`, `services` -> `service`) [understand-anything-plugin/agents/architecture-analyzer.md:104-150]().

The script outputs a JSON object containing these computed structural patterns [understand-anything-plugin/agents/architecture-analyzer.md:152-169]().

### Phase 2: Semantic Layer Assignment (LLM)

In the second phase, the `architecture-analyzer` LLM agent uses the structural insights from the script to make semantic layer assignments. It identifies 3-10 logical architectural layers and assigns every file node to exactly one layer [understand-anything-plugin/agents/architecture-analyzer.md:10-11](). The layer names and descriptions are translated if a language directive is provided [understand-anything-plugin/agents/architecture-analyzer.md:16-19]().

The agent considers the following factors for layer assignment:

*   **Directory Grouping**: Cohesive directory groups with high intra-group density are strong candidates for layers.
*   **Node Type Grouping**: Files of similar types (e.g., all `config` files) might form a layer.
*   **Inter-Group Import Frequency**: Groups with strong, unidirectional dependencies often form hierarchical layers.
*   **Cross-Category Dependency Analysis**: Non-code files that configure or deploy code files might be grouped into infrastructure or configuration layers.
*   **Directory Pattern Matching**: Known architectural patterns (e.g., `api`, `service`, `data`, `ui`) guide layer naming and assignment.

The output of this phase is a list of `Layer` objects, each containing an `id`, `name`, `description`, and an array of `nodeIds` belonging to that layer [understand-anything-plugin/skills/understand-diff/SKILL.md:21]().

## Tour Builder (Phase 5)

The `tour-builder` agent designs guided learning tours through codebases, creating 5-15 pedagogical steps that teach project architecture and key concepts in a logical order [understand-anything-plugin/agents/tour-builder.md:10-11](). Similar to the architecture analyzer, this phase also involves a deterministic script and an LLM-driven component.

### Phase 1: Graph Topology Script

The first phase involves a script (preferably Node.js, falling back to Python) that analyzes the graph's topology to surface structural signals useful for tour design [understand-anything-plugin/agents/tour-builder.md:25-26]().

The script computes the following:

1.  **Fan-In Ranking (Importance)**: For every node, it counts how many other nodes have edges pointing to it (fan-in). High fan-in indicates importance, suggesting early understanding [understand-anything-plugin/agents/tour-builder.md:55-57](). The top 20 nodes by fan-in are outputted [understand-anything-plugin/agents/tour-builder.md:57]().
2.  **Fan-Out Ranking (Scope)**: For every node, it counts how many other nodes it has edges pointing to (fan-out). High fan-out suggests a broad scope, useful for overview steps [understand-anything-plugin/agents/tour-builder.md:59-61](). The top 20 nodes by fan-out are outputted [understand-anything-plugin/agents/tour-builder.md:61]().
3.  **Entry Point Candidates**: Likely entry points are identified by scoring nodes based on filename patterns (e.g., `index.ts`, `main.py`), file location (project root or one level deep), high fan-out, and low fan-in [understand-anything-plugin/agents/tour-builder.md:63-72](). `README.md` at the project root receives the highest score for documentation files [understand-anything-plugin/agents/tour-builder.md:74](). The top 5 candidates are outputted [understand-anything-plugin/agents/tour-builder.md:77]().
4.  **Dependency Chains (BFS from Entry Points)**: Starting from the top code entry point candidate, a Breadth-First Search (BFS) traversal is performed following `imports` and `calls` edges. This reveals the natural "reading order" of the codebase [understand-anything-plugin/agents/tour-builder.md:79-83](). The BFS traversal order, node depths, and nodes grouped by depth level are outputted [understand-anything-plugin/agents/tour-builder.md:85-87]().
5.  **Non-Code File Inventory**: Non-code files are separated by category (documentation, infrastructure, data/schema, configuration) for potential tour inclusion [understand-anything-plugin/agents/tour-builder.md:89-94]().
6.  **Tightly Coupled Clusters**: Groups of 2-5 nodes with high mutual connectivity are identified, representing features or subsystems that should be explained together [understand-anything-plugin/agents/tour-builder.md:96-99]().
7.  **Layer List**: The provided layers (id, name, description) are recorded [understand-anything-plugin/agents/tour-builder.md:106-108]().
8.  **Node Summary Index**: A lookup of each node ID to its `summary`, `type`, and `name` is created for quick reference by the LLM phase [understand-anything-plugin/agents/tour-builder.md:110-112]().

The script outputs a JSON object containing these computed topological properties [understand-anything-plugin/agents/tour-builder.md:117-130]().

### Phase 2: Pedagogical Tour Design (LLM)

In the second phase, the `tour-builder` LLM agent uses the topological insights to design a pedagogical tour. It creates 5-15 steps, each with a `title`, `description`, and a list of `nodeIds` to highlight [understand-anything-plugin/skills/understand-diff/SKILL.md:22](). An optional `languageLesson` can be included for language-specific educational notes [understand-anything-plugin/skills/understand-diff/SKILL.md:22](). The tour title and descriptions are translated if a language directive is provided [understand-anything-plugin/agents/tour-builder.md:16-20]().

The agent leverages the following information:

*   **Entry Point Candidates**: The tour typically starts with the most important entry points, especially `README.md` [understand-anything-plugin/agents/tour-builder.md:74]().
*   **Fan-In Ranking**: Nodes with high fan-in are introduced early due to their importance.
*   **BFS Traversal**: The BFS order provides a natural progression through dependencies.
*   **Tightly Coupled Clusters**: These groups are presented together in a single step to explain related components.
*   **Non-Code File Inventory**: Relevant non-code files are integrated into the tour to provide a complete picture of the project.
*   **Layers**: The architectural layers provide a high-level structure for organizing tour steps.

The output of this phase is a list of `TourStep` objects, which are then included in the final `KnowledgeGraph` [understand-anything-plugin/skills/understand-diff/SKILL.md:22]().

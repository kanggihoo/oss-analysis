This page details the plugin architecture within the `@understand-anything/core` package, focusing on how `AnalyzerPlugin` implementations are registered, discovered, and invoked. It covers the `PluginRegistry` class, the configuration mechanism for plugins (`parsePluginConfig`, `serializePluginConfig`), and the `DEFAULT_PLUGIN_CONFIG`.

## AnalyzerPlugin Interface

The core of the plugin system is the `AnalyzerPlugin` interface, defined in [understand-anything-plugin/packages/core/src/types.ts](). This interface specifies the methods that any plugin must implement to provide structural analysis capabilities.

```typescript
// understand-anything-plugin/packages/core/src/types.ts
export interface AnalyzerPlugin {
  readonly name: string;
  readonly languages: string[]; // List of language IDs this plugin supports

  /**
   * Performs structural analysis on a file.
   * @param filePath The path to the file.
   * @param content The content of the file.
   * @returns StructuralAnalysis object or null if not applicable.
   */
  analyzeFile(filePath: string, content: string): StructuralAnalysis | null;

  /**
   * Resolves import statements within a file.
   * @param filePath The path to the file.
   * @param content The content of the file.
   * @returns Array of ImportResolution objects or null if not applicable.
   */
  resolveImports?(filePath: string, content: string): ImportResolution[] | null;

  /**
   * Extracts call graph entries from a file.
   * @param filePath The path to the file.
   * @param content The content of the file.
   * @returns Array of CallGraphEntry objects or null if not applicable.
   */
  extractCallGraph?(filePath: string, content: string): CallGraphEntry[] | null;
}
```

The `AnalyzerPlugin` interface requires a `name` and a list of `languages` it supports. It defines three primary methods:
*   `analyzeFile`: Performs a deep structural analysis, extracting functions, classes, imports, and exports.
*   `resolveImports`: Specifically handles the resolution of import statements. This method is optional, as some plugins (e.g., for non-code files) may not need to resolve imports.
*   `extractCallGraph`: Extracts call graph information, also an optional method.

## PluginRegistry

The `PluginRegistry` class ([understand-anything-plugin/packages/core/src/plugins/registry.ts:11-81]()) acts as a central hub for managing and dispatching `AnalyzerPlugin` instances. It maintains a collection of registered plugins and maps supported languages to their respective plugins.

### Constructor and Initialization

The `PluginRegistry` can be initialized with an optional `LanguageRegistry` instance. If not provided, it defaults to `LanguageRegistry.createDefault()` [understand-anything-plugin/packages/core/src/plugins/registry.ts:18](). This `LanguageRegistry` is crucial for mapping file extensions to language IDs, which in turn helps the `PluginRegistry` determine which plugin should handle a given file.

```typescript
// understand-anything-plugin/packages/core/src/plugins/registry.ts
export class PluginRegistry {
  private plugins: AnalyzerPlugin[] = [];
  private languageMap = new Map<string, AnalyzerPlugin>();
  private languageRegistry: LanguageRegistry;

  constructor(languageRegistry?: LanguageRegistry) {
    this.languageRegistry = languageRegistry ?? LanguageRegistry.createDefault();
  }
  // ...
}
```

### Plugin Management

*   **`register(plugin: AnalyzerPlugin): void`**: Adds a plugin to the registry. For each language the plugin supports, an entry is added to the internal `languageMap` [understand-anything-plugin/packages/core/src/plugins/registry.ts:20-24](). If multiple plugins support the same language, the last registered plugin for that language takes precedence [understand-anything-plugin/packages/core/src/__tests__/plugin-registry.test.ts:85-92]().
*   **`unregister(name: string): void`**: Removes a plugin by its `name`. This method rebuilds the `languageMap` to ensure that any languages previously handled by the unregistered plugin are correctly reassigned or removed [understand-anything-plugin/packages/core/src/plugins/registry.ts:26-37]().
*   **`getPlugins(): AnalyzerPlugin[]`**: Returns a list of all currently registered plugins [understand-anything-plugin/packages/core/src/plugins/registry.ts:74-76]().
*   **`getSupportedLanguages(): string[]`**: Returns a list of all unique language IDs supported by the registered plugins [understand-anything-plugin/packages/core/src/plugins/registry.ts:78-80]().

### Plugin Discovery and Invocation

The `PluginRegistry` provides methods to find and invoke plugins based on language or file path:

*   **`getPluginForLanguage(language: string): AnalyzerPlugin | null`**: Retrieves the plugin registered for a specific language ID [understand-anything-plugin/packages/core/src/plugins/registry.ts:39-41]().
*   **`getPluginForFile(filePath: string): AnalyzerPlugin | null`**: Determines the language of a given `filePath` using the `LanguageRegistry` and then returns the corresponding plugin [understand-anything-plugin/packages/core/src/plugins/registry.ts:43-47]().
*   **`getLanguageForFile(filePath: string): string | null`**: A helper method to get the language ID for a given file path [understand-anything-plugin/packages/core/src/plugins/registry.ts:51-53]().
*   **`analyzeFile(filePath: string, content: string): StructuralAnalysis | null`**: Finds the appropriate plugin for the `filePath` and delegates the `analyzeFile` call to it [understand-anything-plugin/packages/core/src/plugins/registry.ts:55-59]().
*   **`resolveImports(filePath: string, content: string): ImportResolution[] | null`**: Similar to `analyzeFile`, but delegates to the `resolveImports` method of the discovered plugin. It handles cases where a plugin might not implement `resolveImports` [understand-anything-plugin/packages/core/src/plugins/registry.ts:61-65]().
*   **`extractCallGraph(filePath: string, content: string): CallGraphEntry[] | null`**: Delegates to the `extractCallGraph` method of the discovered plugin, also handling optional implementations [understand-anything-plugin/packages/core/src/plugins/registry.ts:67-71]().

## Plugin Discovery and Configuration

The system supports dynamic plugin configuration through a JSON file, allowing users to enable/disable plugins, specify supported languages, and pass custom options.

### PluginConfig Interface

The structure for plugin configuration is defined by the `PluginConfig` and `PluginEntry` interfaces [understand-anything-plugin/packages/core/src/plugins/discovery.ts:3-12]():

```typescript
// understand-anything-plugin/packages/core/src/plugins/discovery.ts
export interface PluginEntry {
  name: string;
  enabled: boolean;
  languages: string[];
  options?: Record<string, unknown>;
}

export interface PluginConfig {
  plugins: PluginEntry[];
}
```

*   `PluginEntry`: Represents a single plugin's configuration, including its `name`, `enabled` status, a list of `languages` it should handle, and optional `options`.
*   `PluginConfig`: The top-level configuration object, containing an array of `PluginEntry` objects.

### DEFAULT_PLUGIN_CONFIG

A default configuration is provided, which enables the `tree-sitter` plugin for all languages that have a `treeSitter` configuration defined in `builtinLanguageConfigs` [understand-anything-plugin/packages/core/src/plugins/discovery.ts:14-24]().

```typescript
// understand-anything-plugin/packages/core/src/plugins/discovery.ts
export const DEFAULT_PLUGIN_CONFIG: PluginConfig = {
  plugins: [
    {
      name: "tree-sitter",
      enabled: true,
      languages: builtinLanguageConfigs
        .filter((c) => c.treeSitter)
        .map((c) => c.id),
    },
  ],
};
```
This ensures that out-of-the-box, the system leverages the powerful `TreeSitterPlugin` for structural analysis of common programming languages.

### `parsePluginConfig`

The `parsePluginConfig` function ([understand-anything-plugin/packages/core/src/plugins/discovery.ts:30-61]()) is responsible for parsing a JSON string into a `PluginConfig` object.

*   It handles empty or invalid JSON strings by returning the `DEFAULT_PLUGIN_CONFIG` [understand-anything-plugin/packages/core/src/plugins/discovery.ts:31-32, 58-60]().
*   It validates the structure of the parsed JSON, specifically checking if `plugins` is an array and if each `PluginEntry` has the required `name` and `languages` fields [understand-anything-plugin/packages/core/src/plugins/discovery.ts:34-48](). Entries missing these fields are filtered out [understand-anything-plugin/packages/core/src/__tests__/plugin-discovery.test.ts:36-43]().
*   The `enabled` field defaults to `true` if omitted in the JSON [understand-anything-plugin/packages/core/src/plugins/discovery.ts:52]().

### `serializePluginConfig`

The `serializePluginConfig` function ([understand-anything-plugin/packages/core/src/plugins/discovery.ts:66-68]()) converts a `PluginConfig` object back into a human-readable JSON string, formatted with 2-space indentation.

```typescript
// understand-anything-plugin/packages/core/src/plugins/discovery.ts
export function serializePluginConfig(config: PluginConfig): string {
  return JSON.stringify(config, null, 2);
}
```

## Example: TreeSitterPlugin

The `TreeSitterPlugin` ([understand-anything-plugin/packages/core/src/plugins/tree-sitter-plugin.ts:31-97]()) is a prime example of an `AnalyzerPlugin` implementation. It leverages `web-tree-sitter` to provide highly accurate structural analysis for various programming languages.

*   **Constructor**: It takes `LanguageConfig` objects to determine which languages to support and how to load their WASM grammars. It also registers `LanguageExtractor` instances for each supported language [understand-anything-plugin/packages/core/src/plugins/tree-sitter-plugin.ts:56-97]().
*   **`init()`**: This asynchronous method loads the `web-tree-sitter` WASM module and all required language grammars. It must be called before any analysis can occur [understand-anything-plugin/packages/core/src/plugins/tree-sitter-plugin.ts:124-197]().
*   **`analyzeFile()`**: This method uses the loaded Tree-sitter grammars and language-specific `LanguageExtractor`s to parse the file content and extract structural information like functions, classes, imports, and exports [understand-anything-plugin/packages/core/src/plugins/tree-sitter-plugin.ts:203-220]().
*   **`resolveImports()`**: Delegates to the language-specific extractor to resolve import paths [understand-anything-plugin/packages/core/src/plugins/tree-sitter-plugin.ts:222-226]().
*   **`extractCallGraph()`**: Delegates to the language-specific extractor to build a call graph [understand-anything-plugin/packages/core/src/plugins/tree-sitter-plugin.ts:228-232]().

The `TreeSitterPlugin` is a powerful, language-agnostic way to perform static analysis, with language-specific details handled by `LanguageExtractor` implementations.

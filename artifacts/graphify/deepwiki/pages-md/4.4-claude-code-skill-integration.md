The Claude Code Skill Integration allows `graphify` to operate as a native extension within the Claude Code CLI and other agentic environments. By registering specialized skill manifests, `graphify` provides agents with a structured protocol to transform directories into knowledge graphs, perform semantic queries, and maintain a persistent mental model of a codebase across chat sessions.

## Skill Manifest and Trigger

The integration is defined by a primary skill manifest located at `graphify/skill.md`. This manifest acts as the "system prompt" for the agent when the `/graphify` trigger is used [graphify/skill.md:1-5]().

### Key Manifest Components
*   **Trigger**: The `/graphify` prefix tells the agent to invoke the skill logic [graphify/skill.md:4]().
*   **Capabilities**: Informs the agent that it can handle code, docs, papers, images, and video to produce clustered communities and interactive reports [graphify/skill.md:3, 9]().
*   **Persistence**: Explicitly instructs the agent that relationships are stored in `graphify-out/graph.json`, allowing the graph to survive across different chat sessions [graphify/skill.md:45-46]().
*   **Interpreter Persistence**: The skill writes the path of the correct Python interpreter to `graphify-out/.graphify_python` to ensure consistency across multiple bash block invocations [graphify/skill.md:95-97]().
*   **GitHub Integration**: Step 0 of the manifest allows agents to clone remote repositories and merge them into cross-repo graphs [graphify/skill.md:60-63]().

## Progressive Disclosure and Build System

As of version 0.8.29, `graphify` uses a **progressive-disclosure** architecture for skill files. Instead of a single monolithic prompt, the system employs a lean core (~615 lines) supplemented by on-demand sidecar files in the `references/` directory.

### Skill Fragments and `skillgen`
Platform-specific skills are generated from shared fragments using the `tools/skillgen/` build system.
*   **`gen.py`**: The core generator script that assembles skill files [tools/skillgen/gen.py:1]().
*   **`platforms.toml`**: Defines the configuration and target paths for all supported platforms [tools/skillgen/platforms.toml:1]().
*   **`fragments/`**: Contains reusable markdown blocks (e.g., `core/`, `always_on/`) that are combined to create the final `SKILL.md` for each platform.
*   **CI Guards**: The build system includes `--check`, `--bless`, and `--audit-coverage` flags to ensure skill files remain synchronized and meet coverage requirements during development.

### Sidecar Reference Files
The core skill file refers the agent to specific reference files for complex tasks:
*   `extraction-spec.md`: Detailed schema for graph extraction.
*   `query.md`: BFS/DFS query logic.
*   `update.md`: Incremental update procedures.
*   `exports.md`: Visualization and export formats.
*   `transcribe.md`: Whisper-based transcription workflows.
*   `github-and-merge.md`: Remote repository handling.

Sources: [graphify/skill.md:62, 147-150](), [tools/skillgen/gen.py:1](), [tools/skillgen/platforms.toml:1]()

## Execution Pipeline and Interpreter Detection

When triggered, the agent follows a strictly defined execution pipeline. A critical component of this is **uv-aware interpreter detection**.

### Interpreter Resolution Logic
To handle `uv tool`, `pipx`, and virtual environments, the skill manifest uses a multi-step detection block:
1.  **uv tool**: Checks if `uv tool run graphifyy` can resolve a Python path [graphify/skill.md:71-74]().
2.  **Shebang**: Reads the shebang from the `graphify` binary [graphify/skill.md:76-82]().
3.  **Fallback**: Defaults to `python3` and attempts a quiet install if the package is missing [graphify/skill.md:84-94]().

## Agent Instructions and Token Optimization

The `graphify install` command injects rules into project-local files like `CLAUDE.md` to guide agent behavior.

### Query-First Policy (Issue #580)
To prevent excessive token usage, `graphify` enforces a "query-first" policy. Instructions explicitly tell the agent to use `graphify query` as the first action for codebase questions, rather than reading the full `GRAPH_REPORT.md` [tests/test_install_strings.py:49-54]().

*   **`CLAUDE.md` Section**: Registers the skill and points the agent to the `graphify-out/` directory [tests/test_install_strings.py:36]().
*   **Dirty File Handling**: Rules in `AGENTS.md` clarify that "dirty" files in `graphify-out/` are expected and should not prevent the agent from using the tool [tests/test_install_strings.py:125-128]().

Sources: [tests/test_install_strings.py:9-10, 49-54, 125-128]()

This page provides a step-by-step guide to installing `graphify`, registering AI assistant skills, and verifying the setup. `graphify` transforms directories containing code, documents, papers, images, or videos into a queryable knowledge graph.

## Installation

`graphify` is distributed as the Python package `graphifyy` (double-y) [README.md:80-80](). It requires **Python 3.10 or higher** [pyproject.toml:12-12]().

### Recommended Installation (uv)
The recommended way to install `graphify` is using `uv`, which handles tool isolation and dependency resolution efficiently. `uv` ensures that the `graphify` command is placed on your `PATH` automatically [README.md:85-86]().

```bash
# Install as a global tool
uv tool install graphifyy

# Run once without installing
uvx graphifyy install
```
The project uses `uv` for its own development and CI, ensuring a consistent environment via `uv.lock` [uv.lock:1-12]() and `.github/workflows/ci.yml` [.github/workflows/ci.yml:27-30]().

### Fallback Installation (pip)
The base installation includes core graph assembly (`networkx`), entity deduplication (`datasketch`, `rapidfuzz`), and structural extraction for 20+ languages via `tree-sitter` [pyproject.toml:13-43]().

```bash
pip install graphifyy
```

## Registering the AI Assistant Skill

After installation, you must register `graphify` as a "skill" to enable the `/graphify` command in AI coding assistants.

### The `graphify install` Command
The `graphify install` command (mapped to `graphify.__main__:main` [pyproject.toml:76-76]()) automates registration. As of version 0.8.33, running this command in a TTY terminal displays an amber "knowledge-graph brain" banner [CHANGELOG.md:7-7]().

1.  **Skill Deployment**: It copies platform-specific manifests (e.g., `skill-codex.md`, `skill-trae.md`) to the assistant's local config directory [pyproject.toml:113-113]().
2.  **Progressive Disclosure**: Modern installs use a lean `SKILL.md` core (~615 lines) and a `references/` sidecar for on-demand tool documentation [CHANGELOG.md:35-35]().
3.  **Instruction Injection**: It updates project-level files like `CLAUDE.md` to teach the assistant how to trigger the `/graphify` command [README.md:93-97]().

## Verifying the Setup

### 1. CLI Verification
Verify the entry point and version:
```bash
graphify --version
graphify --help
```

### 2. Skill Verification
Check if the skill was successfully deployed. You can use `graphify install --project` to install skills into the current repository (e.g., `.claude/skills/`) instead of the global home path [README.md:101-105]().

### 3. CI and Testing
The project uses a `uv`-based CI workflow [.github/workflows/ci.yml:63-71](). You can verify your local environment by running the test suite:
```bash
uv run pytest tests/ -q --tb=short
```

## CI Workflow

`graphify` maintains a robust CI pipeline via GitHub Actions [.github/workflows/ci.yml:1-10]().

*   **Triggers**: Runs on pushes and PRs to `main` and versioned branches (`v1`-`v8`) [.github/workflows/ci.yml:4-7]().
*   **Environment**: Matrix testing on Python 3.10 and 3.12 [.github/workflows/ci.yml:51-53]().
*   **Workflow Steps**:
    1.  **Skillgen Check**: Validates that generated skill artifacts are up to date with fragments in `tools/skillgen/` [.github/workflows/ci.yml:11-48]().
    2.  **Install uv**: Uses `astral-sh/setup-uv` [.github/workflows/ci.yml:63-66]().
    3.  **Sync**: Runs `uv sync --all-extras --frozen` to ensure a reproducible environment [.github/workflows/ci.yml:70-71]().
    4.  **Test**: Executes `pytest` [.github/workflows/ci.yml:73-74]().
    5.  **E2E Check**: Verifies `graphify install` succeeds in the CI environment [.github/workflows/ci.yml:76-80]().

**Sources:** [.github/workflows/ci.yml:1-80](), [pyproject.toml:98-101]()

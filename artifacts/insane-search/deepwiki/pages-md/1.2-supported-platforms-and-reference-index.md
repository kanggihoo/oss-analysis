## Core Retrieval Logic by Platform

### X/Twitter: The Multi-Route Strategy
X/Twitter is heavily protected against standard scraping (returning 402/403). `insane-search` bypasses this by prioritizing structured JSON endpoints that do not require authentication.

1.  **Individual Tweets**: The system uses `cdn.syndication.twimg.com/tweet-result?id={id}&token=a`. This is the most stable route and provides full text, engagement counts, and author metadata [skills/insane-search/references/twitter.md:89-115]().
2.  **Timelines**: The Syndication API (`/srv/timeline-profile/screen-name/{handle}`) is used to fetch the last ~100 tweets including likes and retweets [skills/insane-search/references/twitter.md:13-22]().
3.  **Discovery**: When a keyword search is requested, the system routes through `WebSearch(query="site:x.com {keyword}")` to obtain tweet IDs, then escalates to `tweet-result` for full content [skills/insane-search/references/twitter.md:116-121]().

**Sources:** [skills/insane-search/references/twitter.md:89-121](), [PLATFORMS.md:15-15]()

### Reddit: RSS over JSON
As of June 2026, Reddit's unauthenticated `.json` endpoints are blocked by WAF (403). `insane-search` implements a fallback to the **Atom/RSS feed (`.rss`)**, which remains an exception to WAF rules [skills/insane-search/references/json-api.md:8-12]().

*   **Endpoint Pattern**: `https://www.reddit.com/r/{subreddit}/hot.rss?limit=25`
*   **Data Trade-off**: RSS provides full body HTML but lacks `score` (upvotes) and `num_comments`. For these fields, the system provides a reference for **Application-Only OAuth** [skills/insane-search/references/json-api.md:28-64]().

**Sources:** [skills/insane-search/references/json-api.md:6-64]()

### Naver (Korea): Identity Spoofing & URL Mutation
Naver requires specific headers and URL structures to bypass "Access Denied" blocks.

*   **Naver Blog**: The system transforms `blog.naver.com` URLs into `m.blog.naver.com` and applies an iPhone User-Agent with a `Referer: https://m.naver.com/` header [skills/insane-search/references/naver.md:7-16]().
*   **Naver Search**: Uses `curl_cffi` for session "cookie warming" by first visiting the homepage before hitting the search endpoint [skills/insane-search/references/naver.md:57-71]().
*   **Finance**: Direct access to `api.finance.naver.com/siseJson.naver` for real-time stock time-series data without authentication [skills/insane-search/references/naver.md:43-56]().

**Sources:** [skills/insane-search/references/naver.md:1-95]()

## The Generic Scheduler (Adaptive Escalation)

For any platform not explicitly indexed (e.g., LinkedIn, Coupang, Medium, local forums), the system utilizes the `fetch_chain.py` scheduler. This handles the **No-Site-Name Rule** by treating every URL as a generic challenge unless it matches a Phase 0 exception.

### Generic Handling Capabilities
The scheduler automatically applies the following techniques based on the site's behavior:
*   **Identity Spoofing**: Rotating TLS fingerprints (Safari, Chrome, Firefox) via `curl_cffi` [PLATFORMS.md:64-64]().
*   **Metadata Recovery**: Extracting `OGP` and `JSON-LD` if full body content is obscured [PLATFORMS.md:67-67]().
*   **Cookie Bridging**: Transferring cookies from a successful `Phase 3` (Playwright) session back to the `Phase 2` (curl_cffi) pool for future requests [skills/insane-search/references/playwright.md:65-65]().

**Sources:** [PLATFORMS.md:48-70](), [skills/insane-search/references/fallback.md:56-56]()

The GNOME extension utilizes a specialized data client to bridge the GNOME Shell JavaScript environment (GJS) with the CodeBurn CLI. This page documents the `DataClient` implementation, the GSettings schema configuration, and the installation lifecycle for Linux environments.

## DataClient Implementation

The `DataClient` class is responsible for executing the `codeburn` CLI as a subprocess, parsing its JSON output, and managing an in-memory cache of results. It leverages the `Gio` and `GLib` libraries for asynchronous process management.

### Key Features
*   **Subprocess Management**: Uses `Gio.SubprocessLauncher` to execute CLI commands with a custom `PATH` [gnome/dataClient.js:111-115]().
*   **Request Cancellation**: Supports cancelling in-flight requests via `Gio.Cancellable` to prevent race conditions during rapid period switching [gnome/dataClient.js:37-42]().
*   **Argument Validation**: Validates the `codeburn-path` against `SAFE_ARG_RE` (`/^[A-Za-z0-9 ._/\-]+$/`) to prevent shell injection [gnome/dataClient.js:5-6, 68]().
*   **Path Augmentation**: Automatically scans common package manager directories (NPM, Volta, Bun, Cargo, ASDF, FNM, PNPM) to locate the `codeburn` binary if it is not in the standard system `PATH` [gnome/dataClient.js:7-20, 88-96]().

### Timeout and Error Handling
The client enforces a `TIMEOUT_SECONDS` limit of 15 seconds [gnome/dataClient.js:4](). If the CLI fails to return within this window, `GLib.timeout_add_seconds` triggers a `proc.force_exit()` and rejects the promise [gnome/dataClient.js:121-126]().

## Configuration and GSettings

The extension's state and user preferences are persisted using the GNOME GSettings system, defined in `org.gnome.shell.extensions.codeburn.gschema.xml`.

### Schema Keys
| Key | Type | Default | Description |
|:---|:---|:---|:---|
| `refresh-interval` | uint | 30 | Seconds between data refreshes (Range: 5-300) [gnome/schemas/org.gnome.shell.extensions.codeburn.gschema.xml:6-11]() |
| `default-period` | string | 'today' | Initial view (today, week, 30days, month, all) [gnome/schemas/org.gnome.shell.extensions.codeburn.gschema.xml:13-17]() |
| `budget-threshold` | double | 0.0 | Daily spending limit in USD [gnome/schemas/org.gnome.shell.extensions.codeburn.gschema.xml:19-23]() |
| `budget-alert-enabled` | boolean | false | Toggle for daily budget warnings [gnome/schemas/org.gnome.shell.extensions.codeburn.gschema.xml:25-29]() |
| `compact-mode` | boolean | false | Hides the cost label in the top panel [gnome/schemas/org.gnome.shell.extensions.codeburn.gschema.xml:31-35]() |
| `codeburn-path` | string | '' | Manual override for the `codeburn` binary location [gnome/schemas/org.gnome.shell.extensions.codeburn.gschema.xml:49-53]() |
| `disabled-providers` | as (array) | [] | List of provider IDs to exclude from calculations [gnome/schemas/org.gnome.shell.extensions.codeburn.gschema.xml:61-65]() |

## Installation Lifecycle

The `install.sh` script automates the deployment of the extension to the local user directory.

### Installation Steps
1.  **Schema Compilation**: Runs `glib-compile-schemas` on the `schemas/` directory to generate the `gschemas.compiled` binary required by GNOME [gnome/install.sh:11-12]().
2.  **Directory Creation**: Ensures the target directory `~/.local/share/gnome-shell/extensions/codeburn@codeburn.dev` exists [gnome/install.sh:4-5, 15]().
3.  **File Migration**: Copies the logic (`extension.js`, `indicator.js`, `dataClient.js`), metadata, stylesheets, and compiled schemas into the extension folder [gnome/install.sh:18-31]().

### Post-Installation
Users must restart the GNOME Shell (or log out/in on Wayland) and then enable the extension using:
`gnome-extensions enable codeburn@codeburn.dev` [gnome/install.sh:37]().

Sources: [gnome/install.sh:1-39](), [gnome/README.md:11-27]()

This page documents the automated governance and contribution management system used in the `pi` monorepo. The project employs a "closed-by-default" strategy for new contributors to manage maintainer load and ensure high-quality signal in the issue tracker.

## Overview of the Contribution Gate

The contribution gate is a security and quality-control mechanism implemented via GitHub Actions. It restricts who can maintain open issues and Pull Requests (PRs) based on a flat-file permission system and maintainer commands.

### Key Components
- **`APPROVED_CONTRIBUTORS`**: A flat-file database of GitHub handles and their granted capabilities [`.github/APPROVED_CONTRIBUTORS:1-5`]().
- **Issue/PR Gates**: Automated workflows that intercept new issues and PRs to enforce gating [`.github/workflows/issue-gate.yml:3-5`](), [`.github/workflows/pr-gate.yml:3-5`]().
- **Maintainer Commands**: Comment keywords `lgtm` and `lgtmi` used by maintainers to promote contributors [`.github/workflows/approve-contributor.yml:34-37`]().

## Permission System: APPROVED_CONTRIBUTORS

The project uses a flat text file `.github/APPROVED_CONTRIBUTORS` to manage contributor rights. It acts as the definitive source for gating workflows.

### Capability Levels

| Capability | Description |
|------------|-------------|
| `issue` | Future issues from the user stay open; PRs still require approval [`.github/APPROVED_CONTRIBUTORS:4`](). |
| `pr` | Both future issues and PRs from the user stay open [`.github/APPROVED_CONTRIBUTORS:5`](). |

Each line in the file follows the format `<username> <capability>` [`.github/APPROVED_CONTRIBUTORS:2`](). Lines starting with `#` are comments and ignored [`.github/APPROVED_CONTRIBUTORS:1`]().

### Parsing Logic

The workflows share logic for loading and parsing the `APPROVED_CONTRIBUTORS` file. The function `parseApprovedUsers` processes the raw content into a Map:

```javascript
function parseApprovedUsers(content) {
  const users = new Map();
  for (const rawLine of content.split('\n')) {
    const line = rawLine.trim();
    if (!line || line.startsWith('#')) continue;
    const parts = line.split(/\s+/);
    if (parts.length !== 2) continue;
    const [username, capability] = parts;
    users.set(username.toLowerCase(), capability.toLowerCase());
  }
  return users;
}
```

## Automated Gate Workflows

The project enforces gate checks on new issues and PRs via specialized GitHub Actions workflows.

### Issue Gate (`issue-gate.yml`)

- **Trigger:** Fires on `issues: opened` [`.github/workflows/issue-gate.yml:4-5`]().
- **Bot Exclusion:** Automatically skips bot accounts like `dependabot[bot]` [`.github/workflows/issue-gate.yml:23-26`]().
- **Collaborator Check:** Uses `github.rest.repos.getCollaboratorPermissionLevel` to exempt users with `admin`, `maintain`, or `write` access [`.github/workflows/issue-gate.yml:82-86`]().
- **Approved File Check:** Validates the author against the `APPROVED_CONTRIBUTORS` list via `getTextFile` and `parseApprovedUsers` [`.github/workflows/issue-gate.yml:88-95`]().
- **Enforcement:** Unapproved issues are commented on and closed [`.github/workflows/issue-gate.yml:97-119`]().

### PR Gate (`pr-gate.yml`)

- **Trigger:** Fires on `pull_request_target: opened` [`.github/workflows/pr-gate.yml:4-5`]().
- **Strict Enforcement:** Unlike issues, PRs require the `pr` capability specifically. Users with only `issue` capability will still have PRs auto-closed [`.github/workflows/pr-gate.yml:107-112`]().
- **Action:** Closes the PR and posts a message directing the contributor to open an issue first [`.github/workflows/pr-gate.yml:116-126`]().

### OpenClaw Gate (`openclaw-gate.yml`)

- **Purpose:** Identifies potential automated or related traffic from the `openclaw/openclaw` repository.
- **Logic:** Uses `github.rest.search.issuesAndPullRequests` to check if the author has opened issues/PRs on `openclaw/openclaw` [`.github/workflows/openclaw-gate.yml:93-107`]().
- **Tagging:** If activity is found, it adds the `possibly-openclaw-clanker` label [`.github/workflows/openclaw-gate.yml:117-122`]().

Sources: [`.github/workflows/issue-gate.yml:1-120`](), [`.github/workflows/pr-gate.yml:1-127`](), [`.github/workflows/openclaw-gate.yml:1-123`]()

## Maintainer Workflow: The Promotion Loop

Maintainers control contributor permissions by commenting on issues with specific commands. These commands trigger the `approve-contributor.yml` workflow.

### Promotion Commands

| Command | Effect |
|---------|--------|
| `lgtmi` | Sets capability to `issue` [`.github/workflows/approve-contributor.yml:34-35`](). |
| `lgtm` | Sets capability to `pr` [`.github/workflows/approve-contributor.yml:36-37`](). |

### Promotion Logic (`approve-contributor.yml`)

1. **Verification:** Checks if the commenter has `admin`, `maintain`, or `write` access [`.github/workflows/approve-contributor.yml:51-55`]().
2. **File Update:** Uses `fs.readFileSync` and `fs.writeFileSync` to modify `.github/APPROVED_CONTRIBUTORS` [`.github/workflows/approve-contributor.yml:114-133`]().
3. **Commit:** The `github-actions[bot]` commits the change with message `chore: approve contributor <username>` [`.github/workflows/approve-contributor.yml:141-144`]().
4. **Push:** Pushes directly to the default branch [`.github/workflows/approve-contributor.yml:145`]().

Sources: [`.github/workflows/approve-contributor.yml:1-174`]()

## Quality Bar and Guidelines

The project maintains strict quality standards to ensure meaningful engagement and reduce maintenance overhead.

### The "One Rule"
**You must understand your code.** Submitting AI-generated "slop" without understanding the implementation or its interaction with the system is grounds for immediate closure [`CONTRIBUTING.md:7-9`]().

### Issue Quality
- **Templates:** Must use `bug.yml` or `contribution.yml` [`CONTRIBUTING.md:30`]().
- **Conciseness:** If an issue does not fit on one screen, it is too long [`CONTRIBUTING.md:34`]().
- **Weekend Policy:** Issues submitted Friday through Sunday are auto-closed and generally not reviewed until Monday [`CONTRIBUTING.md:17-19`](), [`CONTRIBUTING.md:79-81`]().

### PR Quality
- **Prerequisite:** Do not open a PR unless already approved with `lgtm` [`CONTRIBUTING.md:50`]().
- **Validation:** Must run `npm run check` and `./test.sh` before submission [`CONTRIBUTING.md:54-59`]().
- **Restrictions:** Do not edit `CHANGELOG.md` [`CONTRIBUTING.md:61`]().

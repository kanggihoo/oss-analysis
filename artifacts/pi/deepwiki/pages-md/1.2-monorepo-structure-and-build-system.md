The `pi` project is organized as an npm workspaces monorepo, designed to provide a modular ecosystem for AI-driven coding agents. It separates concerns into distinct packages for AI provider abstractions, agent logic, terminal rendering, and a primary CLI implementation.

## Package Architecture

The monorepo is managed via the root `package-lock.json` using the `workspaces` field [package-lock.json:10-17](). It contains four core packages and several auxiliary workspaces for examples and extensions [package-lock.json:12-16]().

### Core Packages

| Package | Name | Description |
| :--- | :--- | :--- |
| `packages/ai` | `@earendil-works/pi-ai` | Unified LLM API with automatic model discovery and provider configuration [packages/ai/package.json:2-4](). |
| `packages/agent` | `@earendil-works/pi-agent-core` | General-purpose agent with transport abstraction, state management, and attachment support [packages/agent/package.json:2-4](). |
| `packages/tui` | `@earendil-works/pi-tui` | Terminal User Interface library with differential rendering for efficient text-based applications [packages/tui/package.json:2-4](). |
| `packages/coding-agent` | `@earendil-works/pi-coding-agent` | Coding agent CLI with read, bash, edit, write tools and session management [packages/coding-agent/package.json:2-4](). |

## Build Pipeline

The build system utilizes `tsgo` for TypeScript compilation and `bun` for binary distribution.

### TypeScript Compilation (`tsgo`)
Most packages use `tsgo` to build their distribution files. 
- **Clean**: `shx rm -rf dist` [packages/coding-agent/package.json:29]().
- **Build**: Packages run `tsgo -p tsconfig.build.json` [packages/ai/package.json:65](), [packages/tui/package.json:9](), [packages/agent/package.json:25]().
- **Model Generation**: The `ai` package includes pre-build steps `generate-models` and `generate-image-models` to produce generated model metadata [packages/ai/package.json:63-65]().

### Binary Distribution (`bun compile`)
The standalone `pi` binary is created by compiling the `coding-agent` package using Bun.
- **Process**: The `build:binary` script ensures all dependencies (`tui`, `ai`, `agent`) are built first, then compiles the CLI and workers [packages/coding-agent/package.json:31]().
- **Command**: `bun build --compile ./dist/bun/cli.js ./src/utils/image-resize-worker.ts --outfile dist/pi` [packages/coding-agent/package.json:31]().

### Asset Management
Post-compilation, assets such as themes, PNGs, and HTML templates are copied into the `dist` directory. This includes the `photon_rs_bg.wasm` file required for image processing [packages/coding-agent/package.json:32-33]().

## Distribution and CI/CD

The project uses specialized scripts and GitHub Actions for release management.

### Versioning Policy
The monorepo follows a lockstep versioning policy. Versions are updated across all packages simultaneously using `scripts/sync-versions.js` [scripts/release.mjs:95]().

### Release Workflow
The `scripts/release.mjs` utility automates the release cycle:
1. Bumps versions across all packages [scripts/release.mjs:80-97]().
2. Updates `CHANGELOG.md` files [scripts/release.mjs:107-126]().
3. Regenerates release artifacts (models and shrinkwrap) [scripts/release.mjs:168-172]().
4. Commits and tags the release [scripts/release.mjs:180-184]().

## Scripting Utilities

The `scripts/` directory contains essential maintenance utilities:
- **`local-release.mjs`**: Builds and packs publishable packages into tarballs for local release testing outside the repository [scripts/local-release.mjs:15-28]().
- **`generate-coding-agent-shrinkwrap.mjs`**: Generates a specialized `npm-shrinkwrap.json` for the `coding-agent` package by resolving dependencies from the root lockfile [scripts/generate-coding-agent-shrinkwrap.mjs:7-12]().
- **`check-pinned-deps.mjs`**: Ensures all external dependencies use exact (pinned) versions [scripts/check-pinned-deps.mjs:4-5]().
- **`check-ts-relative-imports.mjs`**: Prevents the use of relative `.js` imports in `.ts` files to maintain build integrity [scripts/check-ts-relative-imports.mjs:70-74]().
- **`publish.mjs`**: Validates and publishes packages to npm, ensuring lockstep versioning is maintained [scripts/publish.mjs:85-90]().

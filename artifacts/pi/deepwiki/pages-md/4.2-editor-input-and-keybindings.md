The `pi-tui` package provides a robust text entry system consisting of a multi-line `Editor` and a single-line `Input` component. These components share a common core for grapheme-aware cursor movement, undo/redo history, and Emacs-style kill ring operations.

## Input Components

The TUI architecture separates single-line and multi-line input concerns into two primary classes, both implementing the `Focusable` interface [packages/tui/src/tui.ts:96-97]().

### Single-line Input
The `Input` class provides a standard single-line text field [packages/tui/src/components/input.ts:19](). It supports horizontal scrolling via `sliceByColumn` when the text exceeds the component width [packages/tui/src/components/input.ts:6](). It also includes support for bracketed paste mode, buffering input between `\x1b[200~` and `\x1b[201~` markers [packages/tui/src/components/input.ts:48-83]().

### Multi-line Editor
The `Editor` class handles complex multi-line text entry with support for word-wrapping, history navigation, and integrated autocomplete [packages/tui/src/components/editor.ts:188-210](). It maintains state including `lines`, `cursorLine`, and `cursorCol` [packages/tui/src/components/editor.ts:189-191](). It is extended by `CustomEditor` in the coding agent to handle application-level actions like interrupting or exiting via `AppKeybinding` handlers [packages/coding-agent/src/modes/interactive/components/custom-editor.ts:7-16]().

### Data Flow and Input Handling
Both components process raw terminal data through `handleInput(data: string)`.

| Feature | Input Class | Editor Class |
| :--- | :--- | :--- |
| **Undo Stack** | `UndoStack<InputState>` [packages/tui/src/components/input.ts:37]() | `UndoStack<EditorState>` [packages/tui/src/components/editor.ts:210]() |

## Grapheme and Marker Awareness

To ensure correct cursor movement and word-wrapping, the TUI uses `Intl.Segmenter` for grapheme-cluster awareness [packages/tui/src/utils.ts:4-10]().

### Paste Markers
The `Editor` supports a specialized `segmentWithMarkers` function. This merges "paste markers" (e.g., `[paste #1 +123 lines]`) into single atomic segments using `PASTE_MARKER_REGEX` [packages/tui/src/components/editor.ts:15-48](). This prevents the cursor from entering the middle of a marker and ensures the entire marker is treated as a single unit during deletion or wrapping [packages/tui/src/components/editor.ts:21-23]().

### Word-Wrap Implementation
The `wordWrapLine` function splits a single logical line into multiple `TextChunk` objects for visual rendering [packages/tui/src/components/editor.ts:107](). It attempts to wrap at whitespace but falls back to character-level wrapping if a single word exceeds the terminal width [packages/tui/src/components/editor.ts:136-152]().

## Keybindings and Semantic Actions

The `KeybindingsManager` maps physical key sequences to semantic action IDs (e.g., `tui.editor.cursorWordLeft`) [packages/tui/src/keybindings.ts:155]().

### Namespaced Actions
Actions are organized by namespace to allow for granular overrides:
- `tui.editor.*`: Navigation, deletion, and history [packages/tui/src/keybindings.ts:9-29]().
- `tui.input.*`: Submission and tab-completion [packages/tui/src/keybindings.ts:31-34]().
- `tui.select.*`: Selection list navigation [packages/tui/src/keybindings.ts:36-41]().

### Kitty Keyboard Protocol
The system supports the **Kitty Keyboard Protocol**, enabling disambiguation of keys like `Ctrl+Enter` vs `Enter` and reporting of "base" keys for non-Latin layouts [packages/tui/src/keys.ts:4-10](). The `matchesKey` function handles complex CSI-u sequences including shifted keys and alternate layouts [packages/tui/src/keys.ts:14-15](). For example, it can match `ctrl+c` even when pressing a Cyrillic character if the base layout key is 'c' [packages/tui/test/keys.test.ts:47-53]().

## Autocomplete Integration

The `Editor` integrates with an `AutocompleteProvider` to show suggestions in an overlay `SelectList` [packages/tui/src/components/editor.ts:1-9]().

### CombinedAutocompleteProvider
The default implementation `CombinedAutocompleteProvider` [packages/tui/src/autocomplete.ts:270]() handles:
1. **Slash Commands**: Registered via the `SlashCommand` interface [packages/tui/src/autocomplete.ts:227]().
2. **File Paths**: Uses the `fd` utility via `walkDirectoryWithFd` for high-performance, `.gitignore`-aware file discovery [packages/tui/src/autocomplete.ts:124-150](). It handles both relative and absolute paths and supports `@` or `"` prefixes [packages/tui/src/autocomplete.ts:94-105]().

### Trigger Mechanisms
- **Explicit**: Triggered by the `tui.input.tab` keybinding [packages/tui/src/keybindings.ts:120]().
- **Implicit**: Triggered by typing `@` (for files) or `/` (for commands) [packages/tui/src/autocomplete.ts:94-105]().

**Sources:** [packages/tui/src/autocomplete.ts:241-270](), [packages/tui/src/components/select-list.ts:40-58](), [packages/tui/test/autocomplete.test.ts:57-115]()

## Undo Stack and Kill Ring

### Undo/Redo
The `UndoStack` maintains a history of component states. Both `Editor` and `Input` use **undo coalescing**: consecutive character insertions are treated as a single `type-word` action to avoid excessive undo steps [packages/tui/src/components/input.ts:213-218]().

### Kill Ring (Emacs-style)
The `KillRing` allows for advanced text manipulation:
- **Kill**: Deleting text (e.g., `Ctrl+K` via `tui.editor.deleteToLineEnd`) pushes it onto the ring [packages/tui/src/components/input.ts:132-135]().
- **Yank**: Pasting the most recent item from the ring [packages/tui/src/components/input.ts:138-141]().
- **Yank-Pop**: Cycling through previous items in the ring immediately after a yank [packages/tui/src/components/input.ts:142-145]().

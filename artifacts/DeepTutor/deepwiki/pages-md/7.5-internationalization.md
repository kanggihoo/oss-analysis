DeepTutor provides a robust internationalization (i18n) framework designed to support multi-language interfaces and AI-driven content generation. The system leverages `i18next` for the frontend and maintains a structured locale directory for managing translations. To ensure parity across supported languages, the codebase includes an automated audit pipeline and linting rules to prevent hardcoded UI text.

## i18n Integration and Data Flow

The frontend utilizes `i18next` [web/package.json:30]() and `react-i18next` [web/package.json:38]() to provide dynamic translation capabilities. The integration allows components to reactively update when the user switches languages, such as through the sidebar or settings.

## Frontend Implementation

In React components, translations are accessed using the `useTranslation` hook from `react-i18next` [web/components/sidebar/SidebarShell.tsx:25](). The `SidebarShell.tsx` component demonstrates this pattern for rendering navigation labels and tooltips.

### Implementation Pattern

1.  **Hook Usage**: Components call `const { t } = useTranslation()` to access the translation function [web/components/sidebar/SidebarShell.tsx:117]().
2.  **Key Reference**: UI text is replaced with `t('Key Name')`. For example, the sidebar navigation uses `t(item.label)` to render localized menu items [web/components/sidebar/SidebarShell.tsx:190]().
3.  **Tooltips**: The `Tooltip` component is used in conjunction with i18n keys to provide localized descriptions for sidebar icons [web/components/sidebar/SidebarShell.tsx:188-193]().

### Dynamic Language Switching
In specialized pages like the Mastery Path dashboard, components may perform manual language checks via `i18n.language` to handle bilingual content or fallback logic [web/app/(workspace)/learning/page.tsx:38-40]().

## Theme and Global Styles Integration

The i18n system is also integrated with the theme system. Labels for themes are defined in the locale files to ensure the settings interface is fully localized.

- **Theme Labels**: "Snow", "Light", "Cream", "Dark", and "Glass" are localized [web/locales/en/app.json:153-157]().
- **CSS Variables**: While the values for variables like `--background` or `--primary` are defined in `globals.css` [web/app/globals.css:24-123](), the descriptive labels for these themes in the settings interface are retrieved via `t()`.

## i18n Audit and Maintenance Pipeline

To maintain translation parity and code quality, DeepTutor implements a multi-stage audit pipeline defined in the `package.json` scripts [web/package.json:14-17]().

### Audit Scripts
- `i18n:parity`: Checks for key synchronization between `en/app.json` and `zh/app.json` [web/package.json:14]().
- `i18n:audit`: Scans the codebase for missing translations or unused keys using `scripts/i18n_audit.mjs` [web/package.json:15]().
- `i18n:check`: A combined command to run both parity and audit checks [web/package.json:17]().

### Linting Rules
The project uses a custom ESLint configuration `eslint.config.mjs` which incorporates an `i18n-plugin.mjs` [web/eslint.config.mjs:2-9](). The rule `i18n/no-literal-ui-text` is configured as a warning to flag hardcoded string literals in UI components under the `app/` and `components/` directories [web/eslint.config.mjs:13]().

This page documents the automated code quality infrastructure used in DeepTutor. It covers pre-commit hooks, linting and formatting tools (Ruff, Prettier), security scanning (detect-secrets), and their integration with the development workflow.

## Overview

DeepTutor maintains high standards for code quality and security through a suite of automated tools configured in the repository root. These tools ensure consistency across both the Python backend and the Next.js frontend [.pre-commit-config.yaml:1-107]().

- **Ruff**: High-performance Python linting and formatting [.pre-commit-config.yaml:42-51]().
- **Prettier**: Consistent formatting for frontend assets and configuration files [.pre-commit-config.yaml:55-62]().
- **detect-secrets**: Scans for high-entropy strings and hardcoded secrets [.pre-commit-config.yaml:66-72]().
- **Bandit**: Analyzes Python code for common security vulnerabilities [.pre-commit-config.yaml:84-91]().
- **MyPy**: Static type checking to ensure code reliability [.pre-commit-config.yaml:97-106]().
- **Safety/Bandit**: Security analysis for dependencies and code [pyproject.toml:163-164]().

**Sources:** [.pre-commit-config.yaml:1-107](), [pyproject.toml:157-180]()

## Pre-commit Infrastructure

### Installation and Setup

DeepTutor uses the `pre-commit` framework to run checks automatically before every `git commit`. Developers are required to initialize this locally [.pre-commit-config.yaml:4-10]().

```bash
# Install pre-commit
pip install pre-commit

# Install Git hooks
pre-commit install

# Run on all files manually before PR
pre-commit run --all-files
```

**Sources:** [.pre-commit-config.yaml:1-11]()

## Python Code Quality

### Ruff (Linter & Formatter)

DeepTutor uses Ruff for unified Python tooling. It is configured to run with specific arguments to minimize friction during development.

| Hook ID | Arguments | Purpose |
|---------|-----------|---------|
| `ruff` | `--fix`, `--quiet`, `--exit-zero` | Lints code and applies automatic fixes for imports/style [.pre-commit-config.yaml:45-47](). |
| `ruff-format` | `--quiet` | Ensures consistent code indentation and quote usage [.pre-commit-config.yaml:49-51](). |

**Sources:** [.pre-commit-config.yaml:42-51]()

### Type Checking (Mypy)

DeepTutor uses Mypy for static type analysis. Currently, checks are relaxed to support gradual adoption across the codebase [.pre-commit-config.yaml:95-98]().

- **Exclusions**: Specific directories like `deeptutor/agents/`, `deeptutor/services/rag/`, and `deeptutor/api/routers/` are currently excluded from strict checking to avoid legacy noise [.pre-commit-config.yaml:102]().
- **Dependencies**: Includes type stubs for `PyYAML`, `requests`, and `croniter` [.pre-commit-config.yaml:104-106]().

**Sources:** [.pre-commit-config.yaml:97-107]()

## Frontend and Web Quality

### Prettier

Prettier handles formatting for the `web/` directory, covering TypeScript, CSS, and Markdown [.pre-commit-config.yaml:55-62]().

- **Target Files**: `web/**/*.{css,scss,json,jsonc,yaml,yml,md,graphql,html,ts,tsx,js,jsx}` [.pre-commit-config.yaml:60]().
- **Exclusions**: `node_modules`, `.next`, `out`, `dist`, `build` [.pre-commit-config.yaml:61]().

**Sources:** [.pre-commit-config.yaml:55-62]()

## Security Scanning

### detect-secrets

To prevent credential leakage, `detect-secrets` scans the codebase against a baseline file [.pre-commit-config.yaml:66-72]().

- **Baseline**: `.secrets.baseline` is used to track known false positives and allowed high-entropy strings [.pre-commit-config.yaml:70]().
- **Exclusions**: `package-lock.json` is excluded from secret detection [.pre-commit-config.yaml:71]().

**Sources:** [.pre-commit-config.yaml:66-72]()

### Bandit

Bandit performs security-oriented static analysis to find common security issues in Python code, such as insecure use of `subprocess` or `yaml.load` [.pre-commit-config.yaml:84-91]().

- **Configuration**: Uses `pyproject.toml` for rule settings [.pre-commit-config.yaml:88]().
- **Exclusions**: `tests/` directory is excluded from security linting [.pre-commit-config.yaml:89]().

**Sources:** [.pre-commit-config.yaml:84-91]()

## Integration and Testing

DeepTutor uses `pytest` for unit and integration testing. Testing infrastructure covers core services like `PromptManager` [tests/core/test_prompt_manager.py:11-152]() and RAG pipelines [tests/services/rag/test_rag_pipelines.py:1-166]().

### RAG Integration Tests
The `PipelineIntegrationTest` class in `tests/services/rag/test_pipeline_integration.py` validates the full lifecycle of a RAG knowledge base [tests/services/rag/test_pipeline_integration.py:68-84]():

1. **Setup**: Creates temporary directories for testing and initializes the `RAGService` [tests/services/rag/test_pipeline_integration.py:85-102]().
2. **Initialization**: Verifies KB directory creation and file indexing using `testfile.txt` [tests/services/rag/test_pipeline_integration.py:109-132]().
3. **Search**: Tests retrieval accuracy against known text ("Shandong province has a pancake") [tests/services/rag/test_pipeline_integration.py:144-197](), [tests/services/rag/testfile.txt:1-3]().
4. **Tool Verification**: Ensures `rag_tool.py` correctly interfaces with the `RAGService` [tests/services/rag/test_pipeline_integration.py:199-221]().

### Prompt Management Tests
The `TestPromptManager` class ensures the reliability of the system's prompt loading and caching logic [tests/core/test_prompt_manager.py:11-12]():

- **Singleton Pattern**: Confirms `PromptManager` maintains a single instance [tests/core/test_prompt_manager.py:19-23]().
- **Caching**: Verifies that prompts are cached after the first load to improve performance [tests/core/test_prompt_manager.py:71-81]().
- **Language Fallback**: Ensures the system falls back gracefully when a specific language prompt is missing [tests/core/test_prompt_manager.py:135-142]().

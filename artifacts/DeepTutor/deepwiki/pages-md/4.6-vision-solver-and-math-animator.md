The Vision Solver and Math Animator module provides a specialized pipeline for analyzing mathematical problems through visual inputs and generating high-quality mathematical animations or static diagrams using the Manim library. It also encompasses a vision-to-geometry system that converts images into interactive GeoGebra visualizations.

## 1. System Overview

The module operates as a multi-stage pipeline that transforms a user request (and optional visual attachments) into rendered video, image, or interactive code artifacts. It utilizes a "Plan-Design-Code-Render-Fix" cycle to ensure both mathematical accuracy and visual clarity.

### Key Components
- **`VisionSolverAgent`**: A specialized agent that processes math problem images, identifies geometric elements, and generates GeoGebra (GGB) commands [deeptutor/api/routers/vision_solver.py:13-13]().
- **`MathAnimatorPipeline`**: The central orchestrator that manages the flow between specialized agents and the rendering service.
- **`ManimRenderService`**: Handles the execution of generated Python code in a sandboxed environment to produce `.mp4` or `.png` files [deeptutor/agents/math_animator/renderer.py:35-50]().
- **`VisualizeCapability`**: The unified capability class that handles routing between standard text-based visualizations and the Manim subprocess path [deeptutor/capabilities/visualize.py:50-61]().
- **`VisualizePipeline`**: A separate pipeline for generating non-Manim visualizations like charts and diagrams using `AnalysisAgent`, `CodeGeneratorAgent`, and `ReviewAgent` [deeptutor/capabilities/visualize.py:97-103]().
- **`ReviewAgent`**: Optimized to skip LLM review for `html` render types to reduce latency and token costs [deeptutor/agents/visualize/agents/review_agent.py:38-46]().

## 2. Mathematical Animation Pipeline

The generation process is divided into discrete stages. The pipeline uses specialized prompts to ensure the output meets educational standards, such as maintaining a minimum duration (12-30 seconds) and specific "teaching beats" [deeptutor/agents/math_animator/prompts/en/code_generator_agent.yaml:29-30]().

## 4. General Visualization Agent

The `VisualizeCapability` handles non-animation requests such as data charts, flowcharts, and custom SVG illustrations through a three-stage pipeline [deeptutor/capabilities/visualize.py:35-45]().

### Supported Render Types
The pipeline determines the best `render_type` based on the request [web/lib/visualize-types.ts:4-9]():
- **`svg`**: Used for custom illustrations or free-form graphics.
- **`chartjs`**: Used for quantitative data.
- **`mermaid`**: Used for structured diagrams like flowcharts and mindmaps.
- **`html`**: Used for complex interactive visualizations; the `ReviewAgent` skips LLM review for this type to optimize performance [deeptutor/agents/visualize/agents/review_agent.py:38-46]().
- **`manim_video` / `manim_image`**: Specialized Manim-based outputs [web/lib/visualize-types.ts:11-18]().

## 5. Manim Rendering and Execution

The `ManimRenderService` manages the local filesystem and subprocesses required to run the Manim engine.

### Rendering Modes
The service supports two primary output modes [deeptutor/agents/math_animator/renderer.py:52-69]():
1.  **Video Mode**: Renders a full `Scene` subclass into an MP4 video [deeptutor/agents/math_animator/renderer.py:71-82]().
2.  **Image Mode**: Requires code blocks wrapped in `### YON_IMAGE_n_START ###` anchors [deeptutor/agents/math_animator/renderer.py:18-21](). Each block is rendered as a standalone static frame using the Manim `-s` flag [deeptutor/agents/math_animator/renderer.py:84-122]().

### Subprocess Interaction
The service uses `subprocess.Popen` combined with reader threads and an `asyncio.Queue` to preserve real-time streaming output while maintaining compatibility with systems where `SelectorEventLoop` might not support `asyncio` subprocesses [deeptutor/agents/math_animator/renderer.py:155-178]().

## 6. Error Recovery and Code Repair

The `MathAnimatorPipeline` facilitates a robust generation process by handling environment issues and code hallucinations.

### Repair Logic
When a rendering error occurs, the system triggers a repair cycle using the `retry_system` prompt [deeptutor/agents/math_animator/prompts/en/code_generator_agent.yaml:61-76]():
- **Environment Constraints**: The generator is instructed to avoid `Tex` or `MathTex` if local LaTeX is unavailable, preferring `Text` or geometric visualizations [deeptutor/agents/math_animator/prompts/en/code_generator_agent.yaml:35-36]().
- **Version Compatibility**: Specific parameters like `stroke_dash_pattern` (unsupported in Manim v0.20.1) or methods like `self.save_state()` (unsupported in `MovingCameraScene`) are explicitly forbidden and targeted during repair [deeptutor/agents/math_animator/prompts/en/code_generator_agent.yaml:37-38](), [deeptutor/agents/math_animator/prompts/en/code_generator_agent.yaml:70-72]().
- **Camera Logic**: If errors involve `self.camera.frame`, the repair logic either promotes the class to `MovingCameraScene` or removes the camera animation [deeptutor/agents/math_animator/prompts/en/code_generator_agent.yaml:72-75]().

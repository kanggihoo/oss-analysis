The API Layer serves as the central communication bridge between the Next.js frontend and the DeepTutor backend services. Built on **FastAPI**, this layer orchestrates HTTP REST endpoints for state management (settings, sessions, memory, knowledge bases) and a unified WebSocket interface for real-time, streaming agent interactions.

## Architecture Overview

The backend entry point is defined in `deeptutor/api/main.py`, which initializes the FastAPI application and manages the lifecycle of core services. It ensures that the `EventBus`, `TutorBotManager`, and LLM clients are started and stopped correctly during the application's lifespan [deeptutor/api/main.py:115-195]().

## Core Responsibilities

### 1. Lifecycle and Validation
Upon startup, the API layer performs critical consistency checks. The `validate_tool_consistency` function verifies that all tools referenced in capability manifests are actually registered in the `ToolRegistry` [deeptutor/api/main.py:56-82](). It also pre-initializes the `LLMClient` early to ensure environment variables like `OPENAI_API_KEY` are available for downstream provider integrations [deeptutor/api/main.py:129-136]().

### 2. Static Artifact Serving
The API includes a specialized `SafeOutputStaticFiles` mount. This component restricts access to files generated by agents (like Manim animations or code execution outputs) by whitelisting specific paths through the `PathService`, preventing unauthorized directory traversal [deeptutor/api/main.py:43-54]().

### 3. Authentication and Multi-User Scoping
The API layer implements a flexible authentication system via `deeptutor/api/routers/auth.py`. It supports both local SQLite/JSON auth and external **PocketBase** integration [deeptutor/api/routers/auth.py:29-44]().
* **Auth Guards:** Reusable dependencies like `require_auth` (HTTP) and `ws_require_auth` (WebSocket) enforce security [deeptutor/api/routers/auth.py:183-207]().
* **Context Propagation:** Authentication dependencies are declared as `async def` to ensure that `ContextVar` mutations (setting the `CurrentUser`) propagate correctly to the endpoint, avoiding issues where the system might silently fall back to the admin workspace [deeptutor/api/routers/auth.py:162-181](), [tests/api/test_auth_contextvar.py:1-19]().

## Child Pages

The API Layer is further divided into specialized modules:

### [Settings API](#12.1)
Manages the configuration for LLM providers, search engines, and system-wide preferences. It allows the frontend to retrieve and update runtime settings.
For details, see [Settings API](#12.1).

### [Unified WebSocket and Session API](#12.2)
The primary interface for real-time interaction. It covers the unified endpoint which handles bidirectional event streaming, including turn-based execution and session management (list, rename, delete).
For details, see [Unified WebSocket and Session API](#12.2).

## Logging and Middleware
* **Noise Suppression:** The API includes a `_SuppressWsNoise` filter to prevent uvicorn from flooding logs with WebSocket connection/disconnection messages [deeptutor/api/main.py:24-34]().
* **Access Logging:** A specialized middleware ensures that non-200 HTTP responses are logged with the correct number of arguments for uvicorn's `AccessFormatter`, preventing internal logging errors [tests/api/test_selective_access_log.py:1-6]().

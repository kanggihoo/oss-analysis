## Purpose and Scope

This document describes the continuous integration and continuous deployment (CI/CD) infrastructure for `agent-browser`. It covers the GitHub Actions workflows (`ci.yml`, `release.yml`), version synchronization mechanisms (`sync-version.js`, `check-version-sync.js`), testing strategies across platforms, and the release process managed via automated version detection and cross-platform binary distribution.

---

## Overview

The CI/CD pipeline uses GitHub Actions to automate testing, building, and releasing `agent-browser` across seven platform targets (Linux x64/ARM64, Linux musl x64/ARM64, macOS x64/ARM64, Windows x64). The pipeline enforces version consistency between `package.json`, `cli/Cargo.toml`, and the dashboard, runs tests on multiple OS environments, and validates cross-platform binary distribution.

### Pipeline Triggers

The main CI workflow [`.github/workflows/ci.yml:1-9`]() is triggered by:
- Pushes to the `main` branch.
- Pull requests targeting `main`.
- Manual workflow dispatch.

The Release workflow [`.github/workflows/release.yml:1-8`]() is triggered by:
- Pushes to the `main` branch.
- Manual workflow dispatch.

## Version Synchronization

### Strategy

Version synchronization ensures that all components of the monorepo reflect the same version number. The system treats the root `package.json` as the single source of truth [`scripts/sync-version.js:17-21`](). Changes are propagated to the Rust CLI and the Next.js dashboard via automated scripts.

### sync-version.js

The synchronization script [`scripts/sync-version.js`]() performs the following operations:

| Step | Action | Implementation |
|------|--------|---------|
| 1 | Read version from `package.json` | `JSON.parse(readFileSync(...))` [`scripts/sync-version.js:18-21`]() |
| 2 | Update `cli/Cargo.toml` | Regex replace: `/^version\s*=\s*"[^"]*"/m` [`scripts/sync-version.js:25-45`]() |
| 3 | Update `packages/dashboard/package.json` | JSON update [`scripts/sync-version.js:47-57`]() |
| 4 | Update `cli/Cargo.lock` | `cargo update -p agent-browser` [`scripts/sync-version.js:59-79`]() |

The script attempts `cargo update` with `--offline` first to avoid network requests, falling back to online mode if the package is not cached [`scripts/sync-version.js:62-75`]().

### Pre-commit Hook

The Husky pre-commit hook [`.husky/pre-commit:1-3`]() automatically runs version sync before every commit:

```bash
node scripts/sync-version.js
git add cli/Cargo.toml cli/Cargo.lock
```

### CI Version Check

The `version-sync` job [`.github/workflows/ci.yml:11-24`]() runs `node scripts/check-version-sync.js` to validate consistency. If versions differ, the CI fails to ensure no mismatched versions reach the `main` branch [`scripts/check-version-sync.js:42-49`]().

### Rust Testing

#### Primary Rust Testing
The `rust` job [`.github/workflows/ci.yml:26-51`]() runs on `ubuntu-latest`:
- Uses `dtolnay/rust-toolchain@stable` with `rustfmt` and `clippy` [`.github/workflows/ci.yml:33-36`]().
- Runs `cargo fmt` check [`.github/workflows/ci.yml:43-44`]().
- Runs `cargo clippy` to catch common mistakes and enforce style [`.github/workflows/ci.yml:46-47`]().
- Runs `cargo test --profile ci` [`.github/workflows/ci.yml:49-50`]().

#### Native E2E Tests
The `native-e2e` job [`.github/workflows/ci.yml:106-132`]() validates the actual browser interaction:
- Installs Chrome via the CLI: `cargo run -- install --with-deps` [`.github/workflows/ci.yml:123-125`]().
- Installs `ffmpeg` for recording capabilities [`.github/workflows/ci.yml:127-128`]().
- Runs E2E tests: `cargo test --profile ci e2e -- --ignored --test-threads=1` [`.github/workflows/ci.yml:130-131`]().

### Windows Integration Test

The `windows-integration` job [`.github/workflows/ci.yml:133-189`]() validates the full Windows lifecycle:
1. **Build**: Compiles the CLI for `x86_64-pc-windows-msvc` [`.github/workflows/ci.yml:153-154`]().
2. **Install**: Tests the `install` command with a 3-attempt retry loop to handle network instability [`.github/workflows/ci.yml:160-171`]().
3. **Lifecycle**: Executes `open`, `snapshot`, and `close` commands via the native binary [`.github/workflows/ci.yml:173-189`]().

## Release Process

Releases are triggered when the version in `package.json` differs from the current version on npm [`release.yml:34-46`]().

### Build Pipeline

The `build-binaries` job [`.github/workflows/release.yml:66-191`]() cross-compiles the CLI for 7 targets:
- **Linux**: `x86_64-unknown-linux-gnu`, `aarch64-unknown-linux-gnu` (uses `cargo-zigbuild` with glibc 2.28 floor check) [`.github/workflows/release.yml:75-86`](), [`.github/workflows/release.yml:192-201`]().
- **Linux Musl**: `x86_64-unknown-linux-musl`, `aarch64-unknown-linux-musl` (uses `cargo-zigbuild`) [`.github/workflows/release.yml:87-98`]().
- **Windows**: `x86_64-pc-windows-gnu` [`.github/workflows/release.yml:99-104`]().
- **macOS**: `x86_64-apple-darwin`, `aarch64-apple-darwin` [`.github/workflows/release.yml:105-117`]().

### Publishing

The `publish` job [`.github/workflows/release.yml:236-267`]() performs the following:
1. **Artifact Collection**: Downloads all platform binaries [`.github/workflows/release.yml:256-258`]().
2. **NPM Publish**: Publishes the package to the npm registry [`.github/workflows/release.yml:251-255`]().
3. **GitHub Release**: Creates a new release with the version tag and attaches all binaries [`.github/workflows/release.yml:260-267`]().

## Post-Installation Logic

The `postinstall.js` script (invoked via `npm install`) is responsible for fetching the correct binary for the user's environment.

### Platform Detection
The release workflow explicitly maps platform names to targets and binary names (e.g., `agent-browser-linux-x64`, `agent-browser-darwin-arm64`) [`.github/workflows/release.yml:75-117`](). This allows the installation logic to select the correct pre-built binary based on the local system's architecture and OS.

### Browser Installation
The `install` command in the CLI handles downloading "Chrome for Testing" [`docs/src/app/installation/page.mdx:9`](). In CI, this is used to provision the environment for e2e tests [`.github/workflows/ci.yml:123-125`]().

### Debugging and Maintenance
For platform-specific issues, especially on Windows, the repository contains debug scripts in `scripts/windows-debug/` to provision EC2 instances, sync code, and run remote builds [`scripts/windows-debug/provision.sh`](), [`scripts/windows-debug/sync.sh:23-27`]().

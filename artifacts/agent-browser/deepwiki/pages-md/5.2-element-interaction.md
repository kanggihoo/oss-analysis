This page documents commands for interacting with page elements: clicking, typing, filling forms, scrolling, hovering, dragging, and selecting. These commands accept element references (refs) from snapshots or CSS selectors. The system uses a specialized dispatch pipeline in `interaction.rs` for native CDP-based execution.

For navigation commands (open, back, forward, reload), see [Navigation and Browser Control](5.1). For retrieving element properties and content, see [Information Retrieval](5.3).

## Element Targeting

All interaction commands require an element selector, which can be:

1.  **Element references (refs)**: `@e1`, `@e2`, etc., generated during the `snapshot` command.
2.  **CSS selectors**: `#id`, `.class`, `button.primary`.

**Refs are strongly recommended** because they are validated at snapshot time and provide stable targeting for AI agents even when DOM attributes change. The CLI parses these refs in `parse_ref` which supports formats like `@e1`, `ref=e1`, or simply `e1`. [cli/src/native/element.rs:124-147]()

### Ref Resolution Pipeline (Native)

In the native Rust daemon, refs are resolved using a `RefMap` which stores metadata about elements discovered during the last snapshot. [cli/src/native/element.rs:18-21]()

The `resolve_element_center` function implements a "fast path" using the cached `backend_node_id`. If the node is stale (e.g., the page re-rendered), it falls back to a search based on the stored role, name, and index (`nth`) to find the element again. [cli/src/native/element.rs:9-16]()

### Ref Lifecycle

Refs are **invalidated** when the DOM changes significantly:
*   After navigation (clicking links, form submission).
*   After dynamic content loads (modals, dropdowns).
*   After any action that modifies the page structure.

**Always re-snapshot after page changes:**
```bash
agent-browser snapshot -i          # Get refs: @e1, @e2
agent-browser click @e2            # Navigate to new page
agent-browser snapshot -i          # MUST re-snapshot to get fresh @e refs
```
**Sources:** [skill-data/core/templates/form-automation.sh:24-54]()

## Mouse Interactions

### Click & Double Click
```bash
agent-browser click <selector> [--new-tab]
agent-browser dblclick <selector>
```
Native implementation resolves the element's center point and dispatches `Input.dispatchMouseEvent` via CDP. [cli/src/native/interaction.rs:28-58]() Double clicks are implemented as a `click` with `click_count: 2`. [cli/src/native/interaction.rs:60-77]()

### Hover
```bash
agent-browser hover <selector>
```
Moves the mouse to the element's center using `mouseMoved` event type via `Input.dispatchMouseEvent`. [cli/src/native/interaction.rs:79-112]()

## Keyboard Interactions

### Fill vs Type
The system provides two distinct ways to input text:

| Command | Implementation | Behavior |
| :--- | :--- | :--- |
| `fill` | `Runtime.callFunctionOn` + `Input.insertText` | Clears input via JS, focuses, then inserts text. Faster and more reliable for large inputs. [cli/src/native/interaction.rs:114-178]() |
| `type` | `Input.dispatchKeyEvent` (per char) | Simulates real key presses. Triggers `keydown`/`keyup` events for every character. [cli/src/native/interaction.rs:181-237]() |

**Sources:** [cli/src/native/interaction.rs:114-237]()

### Press
```bash
agent-browser press <key> [selector]
```
Dispatches a single key press (e.g., `Enter`, `Control+a`). If a selector is provided, it focuses the element first. [cli/src/native/interaction.rs:239-270]()

## Form & Content Control

### Select
```bash
agent-browser select <selector> <value...>
```
Used for `<select>` elements. Supports multiple values for multi-select inputs. [skill-data/core/templates/form-automation.sh:35]()

### Check / Uncheck
```bash
agent-browser check <selector>
agent-browser uncheck <selector>
```
Specifically for checkboxes and radio buttons. [skill-data/core/templates/form-automation.sh:36-37]()

### Upload
```bash
agent-browser upload <selector> <file_paths...>
```
Targets `<input type="file">` elements to upload one or more files. [skill-data/core/templates/form-automation.sh:39]()

## Scrolling

### Scroll Command
```bash
agent-browser scroll <direction> [amount] [--selector <sel>]
```
**Directions:** `up`, `down`, `left`, `right`.
If a selector is provided, the system scrolls that specific element. Otherwise, it scrolls the window.

### Scroll Into View
```bash
agent-browser scrollintoview <selector>
```
Forces the browser to scroll until the element is visible. This is critical before taking screenshots or clicking elements that are not currently in the viewport. [cli/src/native/element.rs:222-223]()

## Implementation: The interaction.rs Pipeline

The native Rust daemon handles interactions by communicating directly with the Chrome DevTools Protocol (CDP) via `CdpClient`. [cli/src/native/interaction.rs:5-8]()

**Title: Data Flow for Fill Command**
```mermaid
graph LR
    "Fill_Request"["Fill Command Request"] --> "resolve_id"["element::resolve_element_object_id()"]
    "resolve_id" --> "Focus_JS"["CDP: Runtime.callFunctionOn (focus)"]
    "Focus_JS" --> "Clear_JS"["CDP: Runtime.callFunctionOn (clear/input event)"]
    "Clear_JS" --> "Insert_CDP"["CDP: Input.insertText"]
    "Insert_CDP" --> "Interaction_Complete"["Success Response"]
```
**Sources:** [cli/src/native/interaction.rs:114-178]()

### Logic Flow for `interaction::fill`
1.  **Resolve ID**: Calls `resolve_element_object_id` to get a CDP `RemoteObjectId`. [cli/src/native/interaction.rs:122-129]()
2.  **Focus**: Executes `this.focus()` via `Runtime.callFunctionOn`. [cli/src/native/interaction.rs:132-144]()
3.  **Clear**: Executes a JS snippet to select all text, set `this.value = ''`, and dispatch an `input` event. [cli/src/native/interaction.rs:147-164]()
4.  **Insert**: Calls `Input.insertText` to place the new value. [cli/src/native/interaction.rs:167-175]()

### Logic Flow for `interaction::click`
1.  **Resolve Coordinates**: Calls `resolve_element_center` to get `(x, y)` coordinates and the effective `session_id`. [cli/src/native/interaction.rs:37-44]()
2.  **Dispatch**: Sends `mousePressed` and `mouseReleased` events to the browser at those coordinates using `dispatch_click`. [cli/src/native/interaction.rs:48-57]()

### Cross-Origin Iframes
Interaction commands automatically handle iframes. If a ref belongs to an element inside an iframe, the `RefEntry` stores the `frame_id`. [cli/src/native/element.rs:15-16]() The interaction logic resolves the dedicated CDP `session_id` for that iframe using `resolve_ax_session` (called within resolution helpers) before dispatching the command. [cli/src/native/element.rs:9](), [cli/src/native/snapshot.rs:222-223]()

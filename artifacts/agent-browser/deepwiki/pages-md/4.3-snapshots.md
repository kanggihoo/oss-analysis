## Purpose and Scope

This page documents the snapshot system in `agent-browser`, which generates accessibility tree representations of web pages with embedded element references (refs). Snapshots are the primary mechanism for AI agents to discover and interact with page elements via the `Accessibility` domain in the Chrome DevTools Protocol (CDP).

For information about how refs are used in commands, see [Element References (Refs)](/4.2). For the underlying communication layer, see [Communication Protocol](/3.5).

---

## Overview

Snapshots extract the accessibility tree from a web page and enhance it with element references (`@e1`, `@e2`, etc.). Unlike CSS selectors which can be fragile or obfuscated in modern web apps, refs are generated from semantic roles and accessible names, providing a deterministic way for AI to reference elements.

**Key characteristics:**
- **CDP-Native**: Uses the `Accessibility` domain protocol directly in the native daemon [cli/src/native/snapshot.rs:227-229]().
- **Deterministic**: Each ref points to a specific `backend_node_id` or a semantic role/name pair [cli/src/native/element.rs:9-16]().
- **AI-optimized**: Output is a compact text format designed to minimize token usage [docs/src/app/snapshots/page.mdx:33-42]().
- **Iframe Inlining**: Automatically traverses and flattens iframe trees into the main snapshot [cli/src/native/snapshot.rs:221-222](), [docs/src/app/snapshots/page.mdx:81-96]().

**Sources:** [cli/src/native/snapshot.rs:11-66](), [cli/src/native/element.rs:1-16](), [docs/src/app/snapshots/page.mdx:1-42]()

```mermaid
    ["RefMap::add_with_frame()"] --> ["RefEntry_Struct"]
    
    ["RefEntry_Struct"] --> ["OUTPUT: Compact_Text_Tree"]
```

**Generation Steps:**
1. **Enable Domains**: The daemon ensures `DOM` and `Accessibility` domains are enabled for the session [cli/src/native/snapshot.rs:224-229]().
2. **Fetch AXTree**: Scopes via `DOM.describeNode` if a selector is provided [cli/src/native/snapshot.rs:259-264]() or retrieves the tree of `AXNode` objects via `Accessibility.getFullAXTree` [cli/src/native/snapshot.rs:7-8]().
3. **Iframe Traversal**: If an `Iframe` node is encountered, the system resolves the dedicated CDP session for that iframe using `iframe_sessions` [cli/src/native/snapshot.rs:222]().
4. **Ref Assignment**: Elements matching `INTERACTIVE_ROLES` or `CONTENT_ROLES` are assigned a unique `@eN` reference [cli/src/native/snapshot.rs:11-43]().
5. **Caching**: The `backend_node_id`, `role`, `name`, and `frame_id` context for each ref are stored in the `RefMap` [cli/src/native/element.rs:42-62]().

**Sources:** [cli/src/native/snapshot.rs:216-270](), [cli/src/native/element.rs:42-62](), [cli/src/native/snapshot.rs:11-43]()

## Element Classification

The snapshot system categorizes elements to determine visibility and ref assignment based on ARIA roles.

### Interactive Roles
These elements always receive a ref and are preserved in `--interactive` mode [cli/src/native/snapshot.rs:11-30]().
- `button`, `link`, `textbox`, `checkbox`, `radio`
- `combobox`, `listbox`, `menuitem`, `searchbox`
- `slider`, `spinbutton`, `switch`, `tab`, `treeitem`, `Iframe`

### Content & Structural Roles
- **Content Roles**: `heading`, `cell`, `gridcell`, `article`, `main`, `navigation`. These receive refs if they contain meaningful text [cli/src/native/snapshot.rs:32-43]().
- **Structural Roles**: `generic`, `group`, `list`, `table`, `row`, `WebArea`, `RootWebArea`. These are typically omitted in `--compact` mode unless they are required for tree hierarchy [cli/src/native/snapshot.rs:45-66]().

**Sources:** [cli/src/native/snapshot.rs:11-66]()

## Filtering and Transformation

### Interactive-Only Mode (`-i`)
When `options.interactive` is true, the tree is pruned to only include elements defined in `INTERACTIVE_ROLES` [cli/src/native/snapshot.rs:80](), [docs/src/app/snapshots/page.mdx:11]().

### Compact Mode (`-c`)
Removes empty structural elements (e.g., `generic`, `group`) that do not have an accessible name or a reference assigned, flattening the tree for the AI [cli/src/native/snapshot.rs:81](), [docs/src/app/snapshots/page.mdx:25]().

### Iframe Inlining
The system flattens the browser's multi-process frame architecture into a single tree.
- **Cross-Origin Handling**: For out-of-process iframes, the system uses `iframe_sessions` to query the child frame's AXTree using its specific `session_id` [cli/src/native/snapshot.rs:222]().
- **Context Preservation**: Each ref in the `RefMap` stores the `frame_id` where it originated, allowing commands like `click @e5` to automatically target the correct CDP session [cli/src/native/element.rs:15-16](), [cli/src/native/element.rs:42-62]().

**Sources:** [cli/src/native/snapshot.rs:77-84](), [cli/src/native/element.rs:9-16](), [docs/src/app/snapshots/page.mdx:81-96]()

## The RefMap System

The `RefMap` is the source of truth for translating AI-provided refs back into browser actions.

### Ref Data Structure
| Field | Type | Description |
|-------|------|-------------|
| `backend_node_id` | `Option<i64>` | The stable CDP node identifier [cli/src/native/element.rs:10](). |
| `role` | `String` | The ARIA role (e.g., "button") [cli/src/native/element.rs:11](). |
| `name` | `String` | The accessible name (e.g., "Submit") [cli/src/native/element.rs:12](). |
| `frame_id` | `Option<String>` | The ID of the frame containing the element [cli/src/native/element.rs:15](). |

### Ref Resolution Space
This diagram shows how a ref string from the CLI is resolved to a physical location on the screen using internal functions and CDP types.

```mermaid
graph LR
    subgraph "Natural_Language_Space"
        ["REF_ID: @e1"]
    end
    
    subgraph "Code_Entity_Space"
        ["RefMap::get()"]
        ["RefEntry"]
        ["resolve_element_center()"]
        ["resolve_element_object_id()"]
    end
    
    subgraph "Browser_CDP_Space"
        ["CDP: DOM.getBoxModel"]
        ["CDP: DOM.resolveNode"]
        ["FUNC: find_node_id_by_role_name"]
    end
    
    ["REF_ID: @e1"] --> ["RefMap::get()"]
    ["RefMap::get()"] --> ["RefEntry"]
    ["RefEntry"] --> ["resolve_element_center()"]
    ["RefEntry"] --> ["resolve_element_object_id()"]
    
    ["resolve_element_center()"] --> ["CDP: DOM.getBoxModel"]
    ["resolve_element_object_id()"] --> ["CDP: DOM.resolveNode"]
    
    ["CDP: DOM.getBoxModel"] -- "Fallback" --> ["FUNC: find_node_id_by_role_name"]
    ["FUNC: find_node_id_by_role_name"] --> ["CDP: DOM.getBoxModel"]
```

**Resolution Logic:**
1. **Fast Path**: Attempt to use the cached `backend_node_id` with `DOM.getBoxModel` [cli/src/native/element.rs:165-181]().
2. **Fallback Path**: If the `backend_node_id` is stale (e.g., DOM mutation), the system performs a semantic lookup using `find_node_id_by_role_name` with the stored `role` and `name` [cli/src/native/element.rs:186-195]().

**Sources:** [cli/src/native/element.rs:9-21](), [cli/src/native/element.rs:149-209](), [cli/src/native/interaction.rs:37-44]()

## Annotated Screenshots

For visual context, `agent-browser` can overlay refs directly onto a screenshot using the `screenshot --annotate` flag [cli/src/native/screenshot.rs:61](), [docs/src/app/snapshots/page.mdx:66]().

1. **Collection**: The system retrieves all interactive elements and their bounding boxes via `collect_annotations` [cli/src/native/screenshot.rs:120-123](), [cli/src/native/screenshot.rs:231-235]().
2. **Injection**: A temporary overlay defined by `ANNOTATION_OVERLAY_ID` ("__agent_browser_annotations__") is injected into the page DOM using `inject_annotation_overlay` [cli/src/native/screenshot.rs:11](), [cli/src/native/screenshot.rs:126-131]().
3. **Capture**: `Page.captureScreenshot` is called while the overlay is visible [cli/src/native/screenshot.rs:224-226]().
4. **Cleanup**: The overlay is removed immediately after capture using `remove_annotation_overlay` [cli/src/native/screenshot.rs:136-138]().

**Sources:** [cli/src/native/screenshot.rs:100-169](), [cli/src/native/screenshot.rs:171-229](), [docs/src/app/snapshots/page.mdx:64-80]()

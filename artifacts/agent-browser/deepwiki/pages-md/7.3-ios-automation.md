This page documents iOS and Safari automation capabilities through Appium and WebDriver. iOS automation enables testing of real Mobile Safari behavior on iOS simulators and physical devices connected via USB.

For cloud browser providers (Browserbase, Kernel, Browser Use), see [7.2 Cloud Browser Providers](). For the experimental native daemon that also supports Safari via WebDriver, see [7.1 Native Daemon Mode]().

---

## Overview

iOS automation in `agent-browser` uses a different technical stack than desktop browser automation. Instead of Playwright or CDP, it uses the WebDriver protocol via Appium to control Safari running in the iOS Simulator or on real devices [docs/src/app/ios/page.mdx:1-5](). The system supports specialized mobile interactions like `tap` and `swipe` while maintaining parity for core commands like `snapshot` and `fill` [docs/src/app/ios/page.mdx:41-62]().

### Architecture Comparison

**Desktop:** CLI → Daemon → Playwright → Chrome (direct CDP).

**iOS:** CLI → Daemon → `AppiumManager` → `WebDriverClient` → Appium → XCUITest → Simulator → Safari.

## Setup Requirements

iOS automation requires macOS with Xcode and the Appium ecosystem installed [docs/src/app/ios/page.mdx:6-10]().

### Installation Steps

**1. Install Appium and XCUITest driver:**

```bash
npm install -g appium
appium driver install xcuitest
```

**2. Verify Xcode is installed:**

```bash
xcode-select --install  # If needed
xcrun simctl list devices available  # List available simulators
```

**3. Test with agent-browser:**

```bash
agent-browser device list
```

Sources: [docs/src/app/ios/page.mdx:12-20](), [docs/src/app/ios/page.mdx:27-39]()

## Device Selection and Management

### Listing Available Devices

The `device list` command queries available iOS simulators. On macOS, this typically interfaces with `xcrun simctl` to list UDIDs and device names [docs/src/app/ios/page.mdx:22-39]().

```bash
agent-browser device list
```

### Specifying a Device

Use the `--device` flag or `AGENT_BROWSER_IOS_DEVICE` environment variable. The `AppiumManager` uses these to build the required `XCUITest` capabilities [cli/src/native/webdriver/appium.rs:43-70]().

| Variable | Description |
|----------|-------------|
| `AGENT_BROWSER_PROVIDER` | Set to `ios` to enable iOS mode |
| `AGENT_BROWSER_IOS_DEVICE` | Device name (e.g., "iPhone 16 Pro") |
| `AGENT_BROWSER_IOS_UDID` | Device UDID (alternative to name) |

Sources: [docs/src/app/ios/page.mdx:80-103](), [cli/src/native/webdriver/appium.rs:43-70]()

## Technical Implementation

### AppiumManager and Capabilities

The `AppiumManager` class in the native Rust backend manages the lifecycle of the Appium process and the WebDriver session [cli/src/native/webdriver/appium.rs:10-14]().

### Session Initialization Flow

1. **Connection Check:** `AppiumManager::connect_or_launch` checks if an Appium server is already running on `APPIUM_DEFAULT_PORT` (4723) [cli/src/native/webdriver/appium.rs:17-28]().
2. **Launch:** If not running, `launch_appium` spawns the `appium` process using `npx` or direct command with `--relaxed-security` [cli/src/native/webdriver/appium.rs:166-190]().
3. **Capabilities:** `build_ios_capabilities` constructs a JSON payload with `platformName: "iOS"`, `appium:automationName: "XCUITest"`, and `browserName: "Safari"` [cli/src/native/webdriver/appium.rs:43-70]().
4. **Session Creation:** `create_ios_session` calls the `WebDriverClient` to POST to `/session` and stores the resulting `sessionId` [cli/src/native/webdriver/appium.rs:72-83]().

## Mobile-Specific Commands

### tap and swipe

iOS automation introduces native touch gestures that are mapped to WebDriver "actions".

*   **Tap:** `AppiumManager::tap` constructs a `pointer` action sequence of type `touch` involving `pointerMove`, `pointerDown`, a 100ms `pause`, and `pointerUp` [cli/src/native/webdriver/appium.rs:85-105]().
*   **Swipe:** `AppiumManager::swipe` moves from a start coordinate to an end coordinate over a specified duration using a `pointerMove` with the provided `duration_ms` [cli/src/native/webdriver/appium.rs:107-134]().

```bash
# Swipe gestures
agent-browser -p ios swipe up
agent-browser -p ios swipe down 500

# Tap (alias for click, semantically clearer for touch)
agent-browser -p ios tap @e1
```

## Real Device Support

Physical iOS devices connected via USB are supported. This requires the `WebDriverAgent` (WDA) to be signed and installed on the device [docs/src/app/ios/page.mdx:115-118]().

### Real Device Setup
1. **UDID:** Identify the device using `xcrun xctrace list devices` [docs/src/app/ios/page.mdx:120-128]().
2. **Signing:** Open `WebDriverAgent.xcodeproj` in Xcode and configure a development team for the `WebDriverAgentRunner` target [docs/src/app/ios/page.mdx:132-147]().
3. **Trust:** On the device, navigate to **Settings → General → VPN & Device Management** to trust the developer certificate [docs/src/app/ios/page.mdx:164]().

Sources: [docs/src/app/ios/page.mdx:115-165]()

## Limitations vs CDP

While iOS automation provides authentic mobile testing, it lacks some features available in the CDP-based desktop stack due to the abstraction layer of WebDriver [docs/src/app/ios/page.mdx:172-185]().

| Feature | Desktop (CDP) | iOS (WebDriver/Appium) |
|---------|---------------|-------------------------|
| **Browser** | Chrome, Lightpanda | Safari Only |
| **Tabs** | Supported | Single Tab Only |
| **PDF Export** | Supported | Not Supported |
| **Screencast** | Supported | Not Supported |
| **Gestures** | Simulated | Native (Tap/Swipe) |

Sources: [docs/src/app/ios/page.mdx:172-185]()

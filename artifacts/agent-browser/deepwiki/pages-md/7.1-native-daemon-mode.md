## Purpose and Scope

The native daemon mode (invoked via `run_daemon`) is a high-performance, low-overhead alternative to traditional Node.js-based browser automation. Implemented entirely in Rust, it communicates directly with browsers via the Chrome DevTools Protocol (CDP). This mode eliminates the need for Node.js and Playwright runtimes, reducing memory consumption from approximately 140MB down to ~7MB RAM [docs/src/app/native-mode/page.mdx:3-5](). It is now the default architecture for `agent-browser` [docs/src/app/native-mode/page.mdx:3]().

## Daemon Lifecycle and Socket Management

The daemon lifecycle is managed in `cli/src/native/daemon.rs`. When started, it creates a session-specific lock and communication infrastructure in a platform-specific socket directory.

### Startup Sequence
1.  **Socket Directory**: Locates or creates the daemon socket directory via `get_daemon_socket_dir` [cli/src/native/daemon.rs:20-23]().
2.  **Stderr Redirection**: If `AGENT_BROWSER_DEBUG` is set, stderr is redirected to a `.log` file; otherwise, it is redirected to `/dev/null` on Unix to prevent crashes if the parent CLI drops the pipe [cli/src/native/daemon.rs:28-60]().
3.  **PID and Versioning**: Writes a `.pid` file containing the process ID and a `.version` file with the crate version to the socket directory [cli/src/native/daemon.rs:62-66]().
4.  **Cleanup**: Removes stale `.sock` (Unix), `.port` (Windows), and `.stream` files from previous runs to ensure a clean state [cli/src/native/daemon.rs:72-87]().
5.  **Stream Server**: Initializes the `StreamServer` using `StreamServer::start_without_client`, allowing it to bind to a port before the browser is launched [cli/src/native/daemon.rs:102-109]().
6.  **Socket Server**: Starts the main IPC listener (`UnixListener` on Unix, `TcpListener` on Windows) via `run_socket_server` [cli/src/native/daemon.rs:122-129]().

### Idle Shutdown and Resource Cleanup
The daemon supports an auto-shutdown mechanism via `AGENT_BROWSER_IDLE_TIMEOUT_MS` [cli/src/native/daemon.rs:117-120](). If no commands are received within the timeout, the daemon exits [cli/src/native/daemon.rs:211-216](). On Unix, it reaps zombie processes by listening for `SIGCHLD` and calling `reap_children` [cli/src/native/daemon.rs:198-200](). To prevent orphaned Chrome processes, the `close_notify` `Notify` instance is used to signal a graceful exit after a "close" command, allowing destructors to run [cli/src/native/daemon.rs:179-182]().

## Direct CDP Usage and Chrome Management

The `ChromeProcess` struct in `cli/src/native/cdp/chrome.rs` manages the lifecycle of the actual browser binary.

- **Process Groups**: On Unix, it tracks the `pgid` to ensure that when the daemon kills Chrome, all helper processes (GPU, renderer, crashpad) are also terminated [cli/src/native/cdp/chrome.rs:12-29]().
- **Graceful Shutdown**: `wait_or_kill` allows Chrome a timeout to flush cookies and state to the `user-data-dir` before forcing a termination [cli/src/native/cdp/chrome.rs:47-60]().
- **Automatic Cleanup**: The `Drop` implementation for `ChromeProcess` automatically kills the process and attempts to remove the temporary user data directory [cli/src/native/cdp/chrome.rs:63-86]().
- **Launch Options**: Supports extensive configuration via `LaunchOptions`, including proxy settings, headless mode, and viewport dimensions [cli/src/native/cdp/chrome.rs:89-113]().

**Sources:** [cli/src/native/cdp/chrome.rs:8-31](), [cli/src/native/cdp/chrome.rs:63-86](), [cli/src/native/cdp/chrome.rs:89-113]()

## StreamServer and Dashboard Integration

The `StreamServer` provides a real-time view of the browser viewport by tapping into CDP's `Page.screencastFrame` events and serving the dashboard web UI.

### Key Components
- **Multiplexing**: The `StreamServer` uses a `broadcast::Sender` (`frame_tx`) to send screencast frames to all connected WebSocket clients simultaneously [cli/src/native/stream/mod.rs:179]().
- **CDP Client Management**: The `CdpClient` manages the raw WebSocket connection to the browser, handling command IDs via `AtomicU64` and broadcasting events through a `broadcast::Sender<CdpEvent>` [cli/src/native/cdp/client.rs:29-46]().
- **Background Event Loop**: `cdp_event_loop` monitors the browser for navigation events and screencast frames, automatically acknowledging frames via `Page.screencastFrameAck` to keep the stream flowing [cli/src/native/stream/cdp_loop.rs:142-149]().
- **Provider Abstraction**: The daemon can connect to remote browser providers (Browserbase, Browserless, etc.) using `connect_provider`, which returns a `ProviderConnection` containing the remote CDP WebSocket URL [cli/src/native/providers.rs:26-73]().

## Performance and Resource Efficiency

Native mode's primary advantage is its minimal resource footprint, making it ideal for high-density environments or constrained CI/CD runners.

| Metric | Rust Daemon (Native) |
| :--- | :--- |
| **RAM Usage** | ~7MB - 15MB [docs/src/app/native-mode/page.mdx:3-5]() |
| **Binary** | Single static Rust binary |
| **Startup** | Near-instant (no Node.js overhead) |
| **CDP Transport** | Native WebSockets (`tokio-tungstenite`) [cli/src/native/cdp/client.rs:79-82]() |
